# API 

API (Application Programming Interface)는 애플리케이션을 구성하는 여러 시스템들이 서로 통신하기 위해 따라야하는 규칙을 의미합니다.


# 아키텍처에 따른 API 분류

- REST API
- SOAP API

SOAP API는 단순 객체 접근 프로토콜(SOAP)을 사용하여 메시지를 교환합니다. 무거운 구조 때문에 점차 사용되지 않고 있지만 금융권, 대기업 등 보안이 중요한 분야에서는 여전히 많이 쓰이고 있습니다.

REST API는 오늘날 웹에서 가장 많이 볼 수 있는 API로 유연한 구조를 가지고 있으며 많은 분야에서 무거운 SOAP API를 대체했습니다.


# 사용 범위 따른 API 분류

- 공개 API (Public API)
- 프라이빗 API (Private API)

퍼블릭 API는 누구나 사용이 가능하도록 외부에 공개된 API입니다. 퍼블릭 API를 활용하여 자신의 애플리케이션을 구축할 수 있습니다.

예를 들어 여러분이 카카오 지도 API를 활용하면 내 애플리케이션에 지도 기능을 손쉽게 추가할 수 있습니다.

프라이빗 API는 기업이 자신들의 시스템을 구축하는 데 사용되는 API입니다. 프라이빗 API가 공개 API가 되는 경우도 종종 볼 수 있습니다. "좋은 것은 나눠쓰자" 라는 일종의 선순환같은 개념이죠.


# SOAP API

SOAP API에 대해 좀 더 자세히 알아봅시다. 아래는 SOAP API를 이해할 때 중요한 개념들입니다.

- SOAP
- UDDI
- WSDL


SOAP은 단순 객체 접근 프로토콜(Simple Object Access Protocol)의 약자입니다. HTTP, HTTPS, SMTP 등의 프로토콜에 기반해서 네트워크 상에서 메시지(XML 기반)를 교환하는 방법을 정의한 프로토콜입니다.

UDDI는 보편적 설명/발견/통합 (Universal Description/Discovery/Integration)의 약자로 전 세계의 수많은 웹서비스가 자세한 정보(WSDL)와 함께 기재된 웹서비스 보관소입니다.

WSDL은 웹서비스 설명 언어(Web Service Description Language)의 약자로 
웹 서비스가 제공하는 기능, 제약 사항, 사용 방법 등을 담고 있는 웹서비스 설명서입니다. 개발자는 자신의 웹서비스를 전 세계에 공유하기 위해 WSDL을 UDDI에 등록합니다.

위 개념들이 어떻게 작동하고 상호작용 하는지 알아봅시다. 예를 들어 지도서비스가 필요한 사용자가 있습니다. 사용자는 UDDI를 탐험하며 여러 웹서비스의 WSDL을 읽고 자신에게 적합한 웹서비스를 선택합니다. 



# EAI

기업 내 각종 애플리케이션을 상호 연동시키는 솔루션으로 일종의 프라이빗 API입니다.
다음과 같은 구축 유형이 있습니다.

- 점대점 (Point-to-Point)
- 허브와 바퀴살 (Hub & Spoke)
- 메시지 버스 (Message Bus)
- 하이브리드 (Hybrid)


점대점은 가장 기본적인 애플리케이션 통합 방식으로 각각의 애플리케이션들을 1:1로 연결하는 방식입니다. 애플리케이션이 많아지면 구조가 복잡해지고 관리가 어려워집니다.

허브와 바퀴살은 애플리케이션들이 단일 접점인 허브 시스템을 통해 연결되는 방식입니다. 중앙 집중형이므로 확장과 유지보수가 용이하다는 장점이 있지만 허브에 장애가 발생할 경우 시스템 전체에 영향을 미칩니다.

메시지 버스는 애플리케이션 사이에 미들웨어(메시지 버스)를 두어 처리하는 방식입니다. 확장성이 뛰어나 대용량 처리에 적합합니다. 하지만 버스에 장애가 발생하면 전체 시스템에 영향을 미칩니다.

하이브리드는 허브와 바퀴살과 Message Bus의 혼합 방식입니다. 그룹 간에는 메시지 버스 방식을 적용하고 그룹 내에서는 허브와 바퀴살 방식을 적용합니다.
