개발한 소프트웨어를 사용을 위해 배포하는 것.
배포 과정입니다.

1. 빌드 (Build)
2. 테스트
3. 배포

# 빌드

모듈별로 생성한 실행 파일들을 실행 파일로 만드는 과정을 의미합니다.

다음은 빌드 도구입니다. 빌드 과정을 자동화하고 관리하는 도구입니다. 다음은 Java 환경에서 사용되는 대표적인 빌드 도구들입니다.

- Gradle
- Maven

Gradle은 안드로이드 앱 개발 환경에서 사용되는 빌드 도구입니다. 안드로이드 뿐만 아니라 플러그인을 설정하면 자바, C/C++, 파이썬 등의 언어로 작성된 앱도 빌드할 수 있습니다. 간결한 문법과 빠른 처리 속도로 가장 많이 사용되는 빌드 도구입니다.
빌드 설정 파일은 Groovy DSL 기반의 build.gradle입니다.

Maven은 아파치 소프트웨어 재단에서 개발한 빌드 도구입니다. 의존성을 설정하여 라이브러리를 관리합니다. Gradle 대비 상대적으로 복잡한 문법과 느린 속도를 가진 레거시 빌드 도구입니다. 빌드 설정 파일은 XML기반의 pom.xml입니다.


# 배포

CI/CD는 지속적 통합(Continuous Integration) 및 지속적 배포(Continuous Deployment)를 의미합니다. 빌드부터 패키징, 배포까지 모두 자동화된 프로세스를 의미합니다. 지속성을 강조하는 애자일 개발 환경의 구현이라고볼 수 있습니다. 다음은 주요 CI/CD 도구입니다.

- Jenkins
- Github Actions

Jenkins는 가장 많이 사용되는 CI/CD 도구로, 자바 기반의 오픈소스 도구입니다. SVN, Git 등 대부분의 형상 관리 도구와 연동이 가능합니다. Web UI 제공으로 편리한 사용성이 장점입니다.

Github Actions는 깃허브에서 제공하는 CI/CD 도구입니다. 깃허브와의 연동으로 간단한 설정만으로 CI/CD 환경을 구축할 수 있습니다.
