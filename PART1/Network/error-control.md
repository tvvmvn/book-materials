# 오류 제어

데이터 전송 중에 데이터가 변형되거나 손실되면 바로잡는 기능입니다. 

- 오류 검출(Error Detection)
- 오류 복구(Error Correction)


# 오류 검출

오류를 찾는 과정을 의미합니다. 다음은 주요 오류 검출 기법들입니다.

- 패리티 비트 (Parity Bit)
- 체크섬 (Checksum)
- CRC (Cyclic Redundancy Check)

패리티 비트는 추가적인 비트와 1의 개수에 근거해서 오류를 검출하는 기법입니다. 구현하기 간편하지만 2개 비트가 동시에 변하면 에러를 검출 할 수 없습니다.

체크섬은 데이터 전체를 다 더한 값을 헤더에 실어 보내는 기법입니다. 주로 TCP/UDP에서 사용합니다.

CRC는 수학적인 나눗셈(다항식)을 이용하는 기법입니다. 매우 정교해서 이더넷의 프레임(frame)에서 표준으로 사용되는 기법입니다.


# 오류 복구

검출된 오류를 복구하는 과정을 의미합니다. 재전송을 요청하는지 여부에 따라 다음의 두가지 기법이 있습니다.

- 후진 오류 수정 (BEC: Backward Error Correction)
- 전진 오류 수정 (FEC: Forward Error Correction)

BEC는 오류가 발생한 경우 재전송을 요청합니다. ARQ(Automatic Repeat reQuest) 기술로 오류를 제어합니다. 

FEC는 재전송 요청 없이 받는 쪽에서 스스로 에러를 고치는 기법입니다. 대표적으로 해밍 코드(Hamming Code)가 있습니다. FEC는 재전송이 어려운 환경 에서 주로 사용됩니다.


# 패리티 비트 (Parity Bit)

패리티 비트는 추가적인 비트와 1의 개수에 근거해서 오류를 검출하는 기법입니다. 구현하기 간편하지만 2개 비트가 동시에 변하면 에러를 검출 할 수 없습니다. 

1의 개수를 어떻게 정하느냐에 따라 두가지 방법으로 나뉩니다.

- 짝수 패리티 (Even Parity): 1비트를 추가해서 1의 개수를 짝수개로 맞춥니다.
- 홀수 패리티 (Odd Parity): 1비트를 추가해서 1의 개수를 홀수개로 맞춥니다.


다음은 오류 검출과정 예시입니다.

1. 사전에 어떤 패리티로 할 것인지 정합니다. 여기서는 짝수 패리티로 하겠습니다.
(어떤 것을 하든 상관 없습니다)

2. 송신자는 비트 스트림 [1000 1010]를 전송하려고 합니다. 비트스트림에 1을 추가해서 1의 개수가 총 4개인 짝수 패리티를 만들었습니다. (괄호 안이 추가한 비트)

전송 데이터: [1000 1010(1)]

3. 수신자는 받은 비트스트림에서 1의 개수를 세보니 총 5개입니다. 마지막 비트가 신호 간섭 등의 이유로 1로 바뀐 것 같습니다. 짝수 패리티로 사전에 협의했는데 1이 홀수개이므로 전송 실패!

수신 데이터: [1000 1011(1)]
