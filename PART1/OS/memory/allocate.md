# 메모리 할당

운영 체제는 프로세스를 메모리의 빈 공간에 할당합니다.
메모리를 가장 효율적으로 사용하기 위해 고민하며


# 단편화 (Fragmentation)

메모리 할당 과정에서 발생하는 낭비 현상을 의미합니다.

- 내부 단편화 (Internal Fragmentation)
- 외부 단편화 (External Fragmentation)

다음은 단편화를 설명하기 위해 단순화한 예시입니다. 메모리에 4MB, 2MB 두 개의 빈 공간이 있습니다.

운영 체제가 3MB 프로세스를 메모리에 올리려고 합니다. 2MB에는 들어갈 수 없고 4MB에 집어넣습니다. 이 때 4MB 공간 내에서 1MB가 낭비 되는 현상이 내부 단편화입니다.

이번엔 5MB 프로세스를 올리려고 합니다. 빈 공간의 총합은 충분하지만(4MB + 2MB) 5MB 크기의 공간이 없어 프로세스를 올리지 못하고 결국 두 공간 모두 낭비됩니다. 이것이 외부 단편화입니다.


# 배치 전략

메모리 상에서 새로운 프로그램이 들어갈 수 있는 위치가 여러 곳인 경우 어느 위치에 배치시킬 것인지를 결정하는 전략입니다. 

- 최초 적합(First Fit)
- 최적 적합(Best Fit)
- 최악 적합(Worst Fit)

최초 적합은 프로그램이 들어갈 수 있는 빈 공간 중에서 첫번째 영역에 배치시키는 방법입니다. 가장 빨리 배치를 끝낼 수 있습니다.

최적 적합은 프로그램이 들어갈 수 있는 크기의 빈 영역 중에서 단편화를 가장 작게 남기는 영역에 배치시키는 방법입니다. 

최악 적합은 프로그램이 들어갈 수 있는 크기의 빈 영역중에서 내부 단편화를 가장 많이 남기는 영역에 배치시키는 방법입니다. 

예제)
메모리에 다음과 같은 순서로 빈 공간이 있을 때 3MB의 프로그램을 새로 올리려고 합니다.

[4MB, 3MB, 5MB, 4MB]

최초 적합: 첫번째에 배치시킵니다. 
최적 적합: 두번째에 배치시킵니다
최악 적합: 세번째에 배치시킵니다.


# 할당 기법

프로세스에게 연속된 메모리 공간을 배치할지 여부에 따라 다음의 두가지 할당 기법이 있습니다.

- 연속 할당 (Contiguous Allocation)
- 불연속 할당 (Non-Contiguous Allocation)


# 연속 할당

연속 할당은 프로세스를 메모리의 연속된 공간에 올리는 기법입니다. 즉 프로세스 전체를 메모리에 한번에 올리는 방식입니다.

- 고정 분할 (Fixed Partitioning)
- 가변 분할 (Variable Partitioning)

고정 분할은 메모리를 미리 나누고 프로세스를 적재하는 방식입니다.

예를 들어 메모리가 12MB인 경우 사전에 4MB씩 3개로 나눕니다. 세 프로그램이 각각 4MB, 4MB, 3MB인 경우 마지막 프로그램 때문에 1MB의 메모리가 낭비됩니다.(내부 단편화)

가변 분할은 들어오는 프로그램의 크기에 따라 동적으로 메모리를 나누는 방식입니다. 프로그램들이 들어오고 나가기를 반복하다 보면 외부 단편화가 발생하게 됩니다.

예를 들어 12MB의 메모리에 차례대로 4MB, 6MB, 2MB의 세 프로세스가 들어와서 메모리를 각각에 맞게 할당합니다.(내부 단편화가 발생하지 않음) 

그 뒤에 첫번째와 세번째 프로그램이 나가고 5MB의 새로운 프로그램에게 메모리를 할당하려고 합니다. 하지만 빈 공간의 합이 충분함에도 불구하고(4MB + 2MB) 연속된 공간이 없어 5MB 프로세스를 할당할 수 없는 상황이 발생합니다. (외부 단편화 발생)


# 불연속 할당

현대 OS에서 사용하는 기법입니다. 불연속 할당은 프로세스를 여러 부분들로 나누고 현재 필요한 부분들만 메모리에 올리는 기법입니다. 램보다 큰 프로그램을 실행할 수 있는 기반이 됩니다.(가상 메모리 기법)

- 페이징 (Paging)
- 세그멘테이션 (Segmentation)

페이징은 프로그램을 고정된 크기의 페이지(Page)로 나누어서 메모리에 적재하는 방식입니다.

세그멘테이션은 프로그램을 다양한 크기의 논리적인 단위인 세그먼트(Segment)로 나누어 메모리에 적재시키는 방법입니다.
