# 페이징

페이징은 프로세스를 여러 개의 페이지로 나누고 메모리에 적재하는 불연속 할당 기법입니다. 외부 단편화가 발생하지 않고 내부 단편화 문제도 크지 않기 때문에 현대 OS가 주로 사용하는 방식입니다.

다음은 페이징 기법에서 사용되는 주요 개념들입니다.

- 페이지 (Page)
- 프레임 (Frame)
- 논리 주소 
- 페이지 테이블
- MMU (Memory Management Unit)

페이지는 프로그램을 일정한 크기(보통 4KB)로 나눈 단위입니다.

프레임은 물리적인 램에 만들어진 페이지와 같은 크기의 공간입니다. 페이지가 이곳에 순서에 상관없이 채워집니다.

논리 주소는 CPU가 참고하는 각 프로세스의 주소 정보입니다. 물리적으로는 여러 프로세스가 섞여있지만 논리 주소 상에서는 프로세스들이 독립적으로 존재하기 때문에 CPU가 작업하기 좋습니다. 

예를 들어 프로세스 A, B, C의 페이지들이 램에서 실제로는 순서도 없이 엉켜있지만 각 프로세스는 자신의 페이지 주소만 있는 논리 주소를 가지고 있습니다. CPU가 이 논리 주소를 참고하여 편리하게 작업할 수 있습니다.

페이지 테이블은 논리 주소와 물리 주소를 연결하는 정보입니다. 

MMU는 페이지 테이블을 참고해서 CPU에게 실제 데이터가 위치한 물리 주소를 알려주는 역할을 합니다.


# 페이징 작동 과정

1. 프로세스를 일정한 크기의 페이지로 나눕니다.

2. 물리적 메모리를 페이지와 똑같은 크기로 나눕니다. 이때 메모리에서 나누어진 공간을 프레임(frame)이라고 부릅니다.

3. 페이지를 메모리의 남는 프레임에 넣습니다. 이때 모든 페이지와 프레임의 크기가 같으므로 외부 단편화가 발생하지 않습니다.

4. 실제로 페이지는 물리 메모리 상에서 순서도 없이 흩어져 적재됩니다.

5. 이때 필요한 것이 논리 주소입니다. CPU는 [논리주소, 데이터] 쌍을 보고 필요한 데이터가 있는 논리 주소를 MMU에게 말합니다.

6. MMU가 논리 주소와 물리주소를 연결하는 <페이지 테이블>을 참조해서 CPU에게 물리 주소를 알려줍니다. CPU는 물리 주소에서 데이터를 가져옵니다.


# 워킹 셋 

워킹 셋(Working Set)은 프로세스가 자주 참조하는 페이지들의 집합입니다. 워킹 셋에 대해 자세히 알아보기 전에 국부성(Locality)에 대해 먼저 알아봅시다. 국부성은 프로세스가 주기억장치를 참조할 때 일부 영역을 집중적으로 참조하는 성질을 의미합니다. 

- 시간 국부성 (Temporal Locality)
- 공간 국부성 (Spatial Locality)

시간 국부성은 일정 시간 동안 특정 데이터가 집중적으로 참조되는 성질입니다.
예) 반복문에서 반복 변수 i가 조만간 또 참조될 가능성이 높습니다.

공간 국부성은 참조된 데이터의 주변이 집중적으로 참조되는 성질입니다.
예) 배열에서 첫번째 요소가 사용되면 다음으로 두번째, 세번째 요소가 사용될 확률이 높습니다.

따라서 워킹 셋을 주기억장치에 상주시키면 페이지 부재와 그에 따르는 교체 현상이 줄어들기 때문에 작업의 효율이 증가합니다. 

특히 잦은 페이지의 부재로 인해 프로세스의 처리 시간보다 페이지 교체에 소요되는 시간이 더 많아지는 스레싱 현상(Thrashing)을 방지할 수 있습니다.
