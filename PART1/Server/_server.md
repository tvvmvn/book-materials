# 서버 (Server)

서버는 클라이언트에게 서비스를 제공하는 컴퓨터를 의미합니다. 
역할에 따라 서버의 종류를 다음과 같이 나눌 수 있습니다.

- 웹 서버
- WAS
- 파일 서버
- 메일 서버
- Batch 서버

여러분(클라이언트)이 인터넷 검색을 할 수 있는 것도, 음악을 들을 수 있는 것도, 친구와 메일을 주고받을 수 있는 것도 모두 보이지 않는 곳에서 열일하고 있는 서버가 있기에 가능하답니다.


# 웹 서버(Web Server)와 WAS

웹서버는 정적 컨텐츠를 제공하는 서버입니다. 정적 컨텐츠는 모든 사용자에게 똑같이 보여지는 컨텐츠로 애플리케이션의 고정 이미지(로고 등), CSS(스타일 담당), JS(동작 담당)이 있습니다.

WAS(웹 애플리케이션 서버)는 동적 콘텐츠를 처리하기 위한 서버입니다. 동적 컨텐츠는 한마디로 말하면 사용자 맞춤 컨텐츠로 현대 대부분의 애플리케이션은 동적 컨텐츠를 제공합니다. 예를 들어 나의 장바구니, 내게 맞는 상품 추천 페이지, 내가 구독중인 유튜브 채널 목록 등이 동적 컨텐츠입니다.

보통 웹서버와 WAS는 두개의 대립적인 개념이 아니라 같이 작동하며 애플리케이션을 완성합니다. 예를 들어 여러분이 구글에서 검색 서비스를 이용하는 경우를 생각해봅시다. 
웹서버는 구글 로고, 검색 창의 모양 등 모든 사용자에게 똑같이 보여지는 정적 콘텐츠를 제공합니다. WAS는 사용자마다 다른 검색 결과 페이지 등을 담당하겠죠?


# WAS 구조

- 컨트롤러 (Controller): 사용자의 요청에 적합한 서비스를 호출하고 결과를 반환하는 객체입니다.

- 서비스 (Service): 서버의 핵심 로직을 담당하는 부분입니다. DAO, 또는 다른 서비스들과 통신하며 맡은 작업을 처리합니다.

- DAO(Data Access Object): 데이터베이스 접근과 데이터 처리를 수행하는 객체입니다.

- VO (Value Object): 엔티티

- DTO(Data Transfer Object): 클라이언트와 서버 간 데이터 교환을 위해 사용되는 객체입니다


*그림 - 서버의 구조*


서버의 구조를 실제로 우리가 애플리케이션을 이용하는 과정을 통해 이해해봅시다. 
예를 들어 여러분이 구글에 로그인을 시도합니다.

여러분의 요청은 서버에 도착후 DTO 객체에 저장되어 컨트롤러에 입력됩니다. 컨트롤러는 로그인 DTO를 로그인 처리 담당 서비스에 전달합니다. 

서비스는 이제 로그인을 처리하는 로직을 수행합니다. 예를 들면 DAO에 요청하여 클라이언트가 전송한 정보에 부합하는 사용자가 데이터베이스에 존재하는지 확인합니다. 기타 로그인에 필요한 작업을 수행후 처리 결과(로그인 실패/성공)를 컨트롤러에 전달합니다. 

컨트롤러는 클라이언트에게 처리 결과를 돌려줍니다. 이제 클라이언트는 로그인 처리되어 애플리케이션을 이용할 수 있게 됩니다.
