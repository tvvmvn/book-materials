## API 개념

Application Programmig Interface  
서로 다른 모듈 간의 통신 규칙

개발 공부를 하다보면 '인터페이스(Interface)'라는 용어를 자주 접하게 됩니다.
사전적 용어는 접점을 의미합니다 (우주는 과학과 수학의 접점에 있다)
거꾸로 생각하면 접점은 공유하는 사물들이 따라야 하는 규칙이기도 합니다.

예를 들어, 스타벅스의 가맹점들은 '스타벅스 매장'이라는 공통점을 공유합니다.
동시에 '스타벅스 매장'은 가맹점들이 따라야 하는 규칙을 정의합니다.
예를 들어 메뉴의 종류, 레시피, 인테리어 등등  
그러한 규칙이 있을 때 가맹점들을 잘 관리할 수 있을 것입니다

이것을 API에 적용시켜봅시다. API는 애플리케이션을 구성하는 다수의 컴포넌트들이
따라야하는 규칙을 의미합니다. 규칙이 있어야 혼란스럽지 않고 안정된 시스템을 구성할 수 있을 것입니다.

### REST API

Respresentational State Transfer  
오늘날 웹에서 볼 수 있는 가장 많이 사용되고 유연한 API.  
일반적으로 API라고 하면 REST API라고 간주할 수 있다.

#### 특징

- 계층 구조 (Layered)
- 획일화된 인터페이스 (Uniform interface)
- 무상태 (Stateless)
- 캐시 가능 (Cacheable)
- 즉각적인 반응(Code on demand)

```
개발 과정에서 API가 활용되는 사례를 봅시다.
여러분들이 만약 배달앱을 개발하고 있습니다.
배달앱에는 지도가 필요합니다.
하지만 지도를 처음부터 개발하는 것은 쉽지 않습니다.
이때 REST API를 따르는 지도 모듈(줄여서 지도 API)을 사용한다면
어렵지 않게 지도를 내 앱에 적용시킬 수 있을 것입니다.
```


### SOAP API

단순 객체 접근 프로토콜(SOAP)을 사용하는 API.  
클라이언트와 서버는 XML을 사용하여 메시지를 교환합니다.  
과거에 더 많이 사용되었으며 유연성이 떨어지는 API입니다.

*구성*

1. SOAP
1. UDDI
1. WSDL

**SOAP** SOAP API의 토대가 된다.  
Simple Object Access Protocol.  
네트워크 상에서 HTTP(S), SMTP등을 통하여 XML을 교환하기 위한
통신 규약.
최근에는 무거운 구조의 SOAP대신 RESTful 프로토콜을 이용하기도 한다.

**UDDI** WSDL을 등록하여 서비스와 서비스 제공자를 검색하고 접근하는데 
사용됨

**WSDL** Web Service Description Language. 
웹서비스와 관련된 서식이나 프로토콜 등을 기술 및 게시하기 위한 언어.
XML로 작성되며 UDDI의 기초가 된다.
클라이언트는 WSDL 파일을 읽고 서버에서 어떠한 조작이 가능한지 파악할 수 있다.


### RPC API

원격 프로시저 호출(RPC) API. 
클라이언트는 특정 함수(프로시저)를 직접 호출합니다.  
RPC가 작동하려면 클라이언트 측 개발자가 미리 함수 이름과 파라미터를 알고 있어야 합니다.  
1980년대 초에 개발된 API. 여전히 자주 쓰인다  


### Web Socket API

WebSocket API는 클라이언트와 서버 간의 양방향 통신을 지원합니다. 
요청-응답으로 구성되는 일반적인 웹서비스와는 달리, 양방향 통신에서 사용자가 요청하지 않아도 서버가 연결된 사용자에게 메시지를
보낼 수 있습니다.

양방향 통신이란 무엇일까요? 가장 쉽게 찾아볼 수 있는 예시는 바로 '채팅'입니다


## 접근성 기준

1. Private API
1. Public API (Open API)
1. Partner API


### Private API

프라이빗 API는 기업 내부에 있으며 비즈니스 내에서 시스템과 데이터를 연결하는 데만 사용됩니다.


### Public API

퍼블릭 API는 일반에 공개되며 누구나 사용할 수 있습니다. 이러한 유형의 API와 관련된 권한 부여와 비용이 있을 수도 있고 없을 수도 있습니다.
또는 Open API라고도 부른다


## API 통신 유형

1. 단방향
1. 동기
1. 비동기


**단방향** 클라이언트가 서버에 요청만 하고 응답이 없는 방식

**동기** 클라이언트가 서버에 요청하고 응답이 올 때까지 대기하는 방식

**비동기** 클라이언트가 서버에 요청하고 다른 작업을 수행하다 응답이 오면
처리하는 방식

비동기 통신방식에서 대표적으로 AJAX가 있습니다.
Asynchronous JavaScript And XML.  
자바스크립트를 사용하여 클라이언트와 서버 간 XML데이터를 
비동기적으로 주고받는 통신 기술입니다.  
전체 페이지를 새로 고치지 않고 페이지의 일부만 업데이트 할 수 있다.
