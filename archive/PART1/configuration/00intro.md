## 형상 관리 (Configuration Management)
  
소프트웨어의 `변경 사항`을 관리하기 위한 일련의 활동입니다. 
소프트웨어 개발의 전 단계에 적용됩니다.
소프트웨어 개발의 전체 비용을 줄이고, 개발 과정의 발생하는 여러 방해 요인을 최소화하는 것을 목적으로 합니다.

형상 관리라는 말은 어렵습니다. 우리에게 친숙한 버전 관리와 비슷한 개념입니다.
물론 이 둘은 완전히 같지는 않습니다. 형상 관리가 버전 관리를 포함하기 때문입니다.
다이어트 과정에 비유를 해볼까요?

여러분이 만약 지금보다 10kg 감량을 목표로 한다고 해봅시다.
매일 몸무게를 체크하여 기록하는 행위를 '버전 관리'라고 할 수 있습니다.
어제의 나와 오늘의 나는 다른 몸무게를 가진 다른 버전입니다.

'다이어트'는 형상 관리에 해당합니다. '다이어트'는 몸무게를 기록하는 행위 외에도 
체중 감량을 위해 어떤 식단을 구성할 것인지, 운동량이나 수면 시간은 어떻게 할지 등 더 다양한 행위들을 포함합니다.


## 형상관리 절차

1. 형상 식별 (Identification)
2. 형상 통제 (Control)
3. 형상 보고 및 감사
4. 형상 기록

**형상 식별** 형상관리 대상에 이름과 관리 번호를 부여하고 계층 구조로 구분하여 수정 및 추적이 용이하도록 하는 작업을 말합니다.

**형상 통제** 식별된 형상 항목에 대한 변경 요구를 검토하여 현재의 `기준선(Baseline)`이 잘 반영될 수 있도록 조정하는 작업입니다

**형상 감사** 기준의 무결성을 평가하기 위해 확인, 검증, 검열 과정을 통해 공식적으로 승인하는 작업입니다.

**형상 기록** 형상의 식별, 통제, 감사 작업의 결과를 기록 및 관리하고 보고서를 작성하는 작업입니다.


## 버전관리 

버전을 관리합니다

*기본 용어*

- 저장소 (Repository)
- 가져오기 (Import)
- 체크아웃 (Check-Out)
- 체크인 (Check-In)
- 커밋 (Commit)
- 동기화 (Update)

**저장소** 최신 버전의 파일들과 변경 내역에 대한 정보들이 저장되어 있는 곳입니다.

**가져오기** 버전 관리가 되고있지 않은 아무것도 없는 저장소에 처음으로 파일을 복사하는 것

**체크아웃** 프로그램을 수정하기 위해 저장소에서 파일을 받아오는 것

**체크인** 체크아웃 한 파일의 수정을 완료학고 저장소의 파일을 새로운 버전으로 갱신하는 것

**커밋** 체크인을 수행할 때 이전에 갱신된 내용이 있는 경우 충돌(Conflict)을 알리고 diff도구를 이용해 수정한 후 갱신을 완료합니다.

**동기화** 저장소에 있는 최신 버전으로 자신의 작업 공간을 바꾸는 것


## 소프트웨어 버전관리 방식

- 공유 폴더 방식
- 클라이언트 / 서버 방식
- 분산 저장소 방식


## 공유 폴더 방식

버전 관리 자료가 지역 컴퓨터의 공유 폴더에 저장되고 관리됩니다.
파일을 잘못 복사하거나 다른 위치로 복사하는 것에 대비하기 위해 
파일의 변경 사항을 `데이터베이스`에 기록하고 관리합니다.

*종류*

- SCCS
- RCS
- PVCS
- QVCS


## 클라이언트 / 서버 방식

버전관리 자료가 서버에 저장되고 관리됩니다.
서버에 문제가 생기면 서버가 복구되기 전까지 협업 및 버전관리 작업은 중단됩니다.

*종류*

- CVS
- SVN (Subversion)
- CVSNT
- Clear Case
- CMVC
- Perforce


## 분산 저장소 방식

버전 관리 자료가 하나의 `원격 저장소`와 분산된 개발자 PC의 `지역 저장소`에 함께 저장되고 관리됩니다. 지역 저장소에서 버전 관리가 가능하므로 원격 저장소에 문제가 생겨도 지역 저장소의 자료를 이용하여 작업할 수 있습니다.

*종류*

- Git
- GNU arch
- DCVS
- Bazaar
- Mercurial
- TeamWare
- Bitkeeper
- Plastic SCM


## 버전관리 도구

### Subversion

CVN을 개선한 버전관리 도구입니다.
아파치 소프트웨어 재단에서 2000년에 발표했습닏다.
서버(저장소)에는 최신 버전의 파일들과 변경 사항이 관리됩니다.
오픈 소스입니다.
CVS의 단점이었던 제한된 파일/디렉터리의 이름 변경 및 이동이 가능합니다.

*주요 명령어*

**add** 새로운 파일이나 디렉터리를 버전 관리 대상으로 등록합니다.

**commit** 버전 관리 대상으로 등록된 클라이언트의 소스 파일을 서버의 소스파일에 적용합니다.

**update** 서버의 최신 commit 이력을 클라이언트의 소스 파일에 적용합니다.

**checkout** 버전 관리 정보와 소스파일을 서버에서 클라이언트로 받아옵니다.

**lock/unlock** 서버의 소스 파일이나 디렉터리를 잠그거나 해제합니다

**import** 아무것도 없는 서버의 저장소에 맨 처음 소스 파일을 저장하는 명령입니다. 한번 사용하면 다시 사용하지 않습니다.

**export** 버전 관리에 대한 정보를 제외한 순수한 소스 파일만을 서버에서 받아옵니다.

**info** 지정한 파일에 대한 위치나 마지막 수정일자 등에 대한 정보를 표시합니다.

**diff** 지정된 파일이나 경로에 대해 이전 리비전(Revision)과의 차이를 표시합니다

**merge** 다른 디렉터리에서 작업된 버전관리 내역을 기본 개발 작업과 병합합니다.


### Git

리누스 토르발즈가 2005년 리눅스 커널 개발에 사용할 관리도구로 개발한 이후 주니오 하마노에 의해 유지보수되고 있습니다. 


*주요 명령어*

**add** 작업 내역을 지역 저장소에 저장하기 위해 스테이징 영역(Staging Area)에 추가합니다.

**commit** 작업 내역을 지역 저장소에 저장합니다.

**branch** 새로운 브랜치를 생성합니다. 최초로 commit을 하면 master 브랜치가 생성됩니다.

**checkout** 지정한 브랜치로 이동합니다

**merge** 지정한 브랜치의 변경 내역을 현재 HEAD 포인터가 가르키는 브랜치에 반영함으로써 두 브랜치를 병합합니다.

**init** 지역 저장소를 생성합니다.

**remote add** 원격 저장소에 연결합니다

**push** 로컬 저장소의 변경 내역을 원격 저장소에 반영합니다.

**fetch** 원격 저장소의 변경 이력만을 지역 저장소로 가져오고 반영합니다.

**clone** 원격 저장소의 전체 내용을 지역 저장소로 복제합니다.
