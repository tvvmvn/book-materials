## 데이터베이스란?

여러 사람에 의해 공동으로 사용되는 데이터 보관소  
저장장치에 저장되어 언제든지 사용될 수 있는 운영 데이터

```
데이터베이스는 눈에 보이지 않기 때문에
어렵게 느껴집니다.
하지만 어려워할 필요 없습니다. 엑셀에 비유할 수 있습니다.
예를 들어 학교의 학생의 정보를 저장한 엑셀 문서를 생각해보세요
실제로 엑셀과 비슷한 형식을 가지고 있답니다.
차츰 배워가죠!
```

## 스키마 (Schema)

사전적 의미는 도식, 도표, 계획  
데이터베이스의 `전체적인 구조와 제약조건`을 작성한 명세  
하나의 데이터베이스 

예) <학교> 스키마는 <학생>, <교수>, <과목> 등의 테이블을 갖는다.

```
DB - Schema - Table
```

### 스키마의 종류

**외부 스키마** 사용자가 각 개인의 입장에서 필요로 하는 

**개념 스키마** 데이터베이스의 전체적인 논리적 구조. 
모든 사용자들이 필요로 하는 데이터를 종합한 데이터베이스.
하나만 존재

**물리 스키마** 물리적 저장장치에서 본 데이터 구조.
레코드 형식 및 물리적 순서, 데이터 항목의 표현 방법 등을 나타냄

![schema](./schema.jpg)

스키마의 종류, 어렵죠? 엑셀에 비유해봅시다
하나의 엑셀 파일은 하드디스크에 저장되어 있습니다.
물리적으로 저장된 상태의 엑셀 파일을 우리는 물리 스키마라고 부릅니다.

엑셀 파일은 여러 개의 시트로 구성되어 있습니다.
전체 시트를 묶어 개념 스키마라고 부릅니다.
모든 데이터가 다 있죠.

사용자마다 보고있는 시트가 다른 것처럼
외부스키마는 사용자마다 다릅니다.
예를 들어 A가 <학교> 스키마에서 <학생>시트를 보고 있고
B가 <과목>시트를 보고있다면
A의 외부스키마는 <학생>이고 B의 외부스키마는 <과목>입니다


## 데이터베이스 설계 순서

1. 요구사항
1. 개념적 설계
1. 논리적 설계
1. 물리적 설계
1. 구현


### 요구사항

개발에 참여하는 이해관계자들의 요구사항.  
설계의 바탕이 되는 회의 문서

예) 기능 요구사항, DBMS, 성능, 비용, 보안 요구사항 등


### 개념적 설계

현실 세계를 추상적인 개념으로 표현한다  
`E-R Diagram`을 작성합니다


### 논리적 설계

개념적 설계를 구체화한다.  
특정 DBMS에 종속적인 스키마 설계  
ER 모델을 발전시켜 `관계형 모델`을 작성합니다.
Transaction Interface (CRUD Matrix) 설계


### 물리적 설계

접근 경로(저장 매체)를 설정한다.  
분산 데이터베이스 결정 등(Partioning, Indexing)


### 구현

스키마 생성 및 DDL를 통해 테이블을 구현한다


설계 어렵죠?
데이터베이스를 물류 창고라고 생각해봅시다.
(이 경우에는 데이터대신 물건을 보관하겠네요)
우리는 이제 물류 창고를 설계할 겁니다.
먼저 물류 창고를 어떤 구조로 지을 것인지,
예를 들면 어느정도 크기와 몇 개의 층을 가질 것인지 등을 대강
그려봅니다.

다음으로 설계도를 구체화해봅니다.
어느 상품군을 어디에 배치할지 지정하기 위해 구역을 설정합니다.

마지막으로 물류 창고를 어느 곳에 위치시킬지 정합니다.
이왕이면 보안이 안전하고 접근이 편리한 곳이 좋겠네요!


## DBMS

DataBase Management System  
데이터베이스 관리용 소프트웨어

예) Oracle DB, MySQL, MongoDB, SQLite

```
데이터베이스가 추상적인 개념이라면
DBMS는 데이터베이스의 실체라고 생각할 수 있습니다.
```

### 필수 기능 (DMC)

1. 데이터 정의 (Definition)
2. 데이터 조작 (Manupulation)
3. 데이터 제어 (Control)

**데이터 정의** 데이터의 타입, 구조, 제약 조건 등을 정의한다

**데이터 조작** 데이터 검색, 갱신, 삽입, 삭제 등 조작 기능

**데이터 제어** 데이터의 무결성, 보안, 병행 제어 등


### 시스템 카탈로그

메타 데이터를 저장하는 장소  
일반 테이블과 같이 테이블 형태를 갖는다.  
삽입, 삭제, 갱신이 불가, 읽기 전용 데이터  
DBMS가 스스로 생성하고 유지한다.  
데이터 사전(Data Dictionary)라고도 한다.  

**메타 데이터**  데이터베이스에 대한 데이터, 즉 데이터베이스 구조, 스키마, 사용자, 권한 등에 관한 정보

```
데이터베이스를 멋진 차고에 비유해봅시다.
차고에 저장되는 차는 데이터가 될 것입니다.
그렇다면 차고의 건축 정보, 차고 비밀번호 등은?
메타 데이터가 되겠지요.
```
