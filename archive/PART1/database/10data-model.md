## 데이터 모델이란?

현실 세계의 정보를 컴퓨터에서 표현하기 위한 모형.  
단순화/추상화된


## 데이터 모델의 구성 요소

1. 구조 (Structure)
2. 연산 (Operation)
3. 제약조건 (Constraint)


**구조**
개체 간의 관계. 데이터 구조 및 정적 성질 표현

**연산**
데이터를 처리하는 작업. 

**제약조건**
데이터의 제약 조건


```
데이터 모델의 구성요소 어렵죠?
예를 들어 <학교>의 정보를 컴퓨터에서 표현한다고 생각해봅시다.
<학교>의 정보를 <학생>, <성적>, <교사>, <과목> 등으로 분류할 수 있습니다
이렇게 분류된 정보들을 한데모아 <학교>정보의 구조라고 할 수 있습니다

연산은 가지고 있는 정보를 필요에 따라 활용 및 가공하는 행위입니다
"학생 정보에서 1학년만 추출하기", "성적순으로 학생 배열하기" 등이 연산의 예입니다.

제약 조건은 컴퓨터에 저장될 자료의 형식을 제약하는 조건입니다.
예를 들어, 성별 자료는 '남/녀' 둘 중 하나의 값을 가져야 하고,
학년은 '1 - 4' 사이의 숫자여야 합니다.
```

## E-R 모델

개체 관계 (Entity - Relationship) 모델  
현실 세계를 개체와 개체 간의 관계를 중심으로 표현한다.  
1976년 Peter Chan에 의해 제안

### 구성 요소

1. 개체 (Entity)
2. 관계 (Relationship)

**개체**

컴퓨터에서 표현하고자 하는 현실 세계의 대상. 사물

**관계**

개체와 개체 사이의 연결


### 모델링 과정

개체 및 속성 식별 > 관계 정의

## 관계형 모델

키-값의 관계, 표(table)의 형식으로 데이터를 표현한다.  
관계형 데이터베이스의 기반이 된다.

대표적으로 엑셀이 있습니다.

### 구조

- 릴레이션 스키마
- 릴레이션 인스턴스
- 튜플 (Tuple)
- 속성 (Attribute)
- 도메인 (Domain)

![relational-model](./relational-model.jpg)


**튜플** 릴레이션을 구성하는 각각의 행.  
속성의 모임으로 구성된다.  
파일 구조에서 레코드와 같은 의미  
튜플의 수를 기수 (Cardinality)라고 한다.

```
Cardinality는 집합에서 원소의 갯수를 의미하는 단어입니다.
릴레이션을 튜플의 집합으로 본다면 납득이 됩니다
```

**속성** 데이터베이스를 구성하는 가장 작은 논리적 단위.  
개체의 특성을 기술하는 것.  
속성의 수를 차수(Degree)라고 한다

```
퀴즈

위의 <학생> 릴레이션에의 차수는 무엇일까요?
정답: 4개
```

**도메인** 하나의 속성이 취할 수 있는 값들의 집합.

예) '성별' 속성의 도메인은 {남, 여} 이다.

```
퀴즈
4년제 대학교의 '학년' 속성의 도메인은 무엇일까요?
답: {1, 2, 3, 4}
```


### 키 분류 - 유일성과 최소성 기준

유일성과 최소성

**유일성(Unique)** 키 값으로 하나의 튜플만을 식별할 수 있어야한다

**최소성(Minimality)** 키를 구성하는 속성 중 하나를 제거하면 유일성을
만족하지 못하는 것


- 수퍼키
- 후보키
- 기본키
- 대체키

**수퍼키** 한 릴레이션에 존재하는 속성들의 집합으로 구성된 키  
유일성은 만족하지만 최소성은 만족하지 못한다.

**후보키** 튜플을 유일하게 식별하기 위해 사용되는 속성들의 부분집합.

**기본키** 후보키 중에서 특별히 선정된 키

**대체키** 후보키가 둘 이상일 때 기본키를 제외한 나머지 후보키.
보조키라고도 한다.

![keys](./keys.jpg)

| 키 | 유일성 | 최소성 |
| --- | --- | --- |
| 수퍼키 | O | X |
| 후보키 | O | O |
| 기본키 | O | O |
| 대체키 | O | O |


후보키의 다양한 사례를 봅시다.
예를 들어, 학교의 학생에 대한 정보를 담은 <학생>릴레이션이 있습니다.
<학생>릴레이션에는 학번, 이름, 학년, 연락처 등의 속성이 있습니다.
이 속성중에서 학생들을 유일하게 구분할 수 있는 속성은 '학번'입니다.
따라서 '학번' 속성은 후보키가 될 수 있습니다.

다음으로 쇼핑몰 웹사이트의 주문 정보를 담은 <주문>릴레이션이 있습니다.
<주문>릴레이션에는 주문ID, 상품ID, 고객ID 등의 속성이 있습니다.
여기서 주문ID가 각각 100, 상품ID가 각각 1,2,3 고객ID가 각각 10인 3개의 튜플이 있습니다.
이 튜플을 해석해보면 고객ID가 10인 고객이 상품ID가 1,2,3인 3종류의 상품에 대한 주문 정보라고 생각할 수 있습니다.

여기서 [주문ID + 상품ID]가 후보키가 될 수 있겠죠? 튜플 하나를 유일하게
식별할 수 있으니까요. 이 경우 키를 구성하는 속성 중 하나를 제거하면
유일성이 사라질 것입니다. 따라서 최소성도 만족합니다.


### 키 분류 - 조인(Join) 작업에서의 역할 기준

조인(Join)이란 두개 이상의 릴레이션이 기본키/외래키를 기준으로 연결되는 것을 의미한다. 조회 결과를 풍부하게 만들 수 있다.


- 기본키 
- 외래키

**기본키** 다른 릴레이션의 키에 의해 참조되는 키. 유일성과 최소성을 만족
**외래키** 다른 릴레이션의 기본키를 참조하는 속성 또는 속성들의 집합

![fk-pk](./pk-fk.jpg)

조인 작업의 진가는 여러분이 실제 데이터베이스를 조작하며
SQL 쿼리 작업을 해보면 알 수 있습니다 😎

### 무결성 (Integrity)

= 완전성  
현실 세계 실제값과 데이터베이스의 데이터가 완전히 일치하는지 여부  
개체 무결성과 참조 무결성이 있다

- 개체 무결성
- 참조 무결성

**개체 무결성** 기본키는 Null이거나 중복되어서는 안된다.

**참조 무결성** 외래키는 참조 릴레이션의 기본키와 같거나 Null이어야 한다.
