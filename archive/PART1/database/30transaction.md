## 트랜잭션 개념

데이터베이스의 상태를 변환시키는 하나의 논리적 기능을 수행하기 위한 작업의 단위 
또는 한꺼번에 모두 수행되어야 할 일련의 연산들

'은행 송금' 트랜잭션 과정을 봅시다. 여러분은 친구에게 1만원을 송금했습니다.
이 과정을 살펴봅시다.
<계좌 데이터>에서 내 계좌에 만원이 차감되고(Update) 상대방 계좌에
만원이 추가됩니다(Update)
이 경우 <계좌 데이터>에서만 두 건의 갱신 연산이 발생했습니다.


## 트랜잭션 절차

![transaction-process](./transaction-process.png)

**Commit** 트랜잭션이 성공한 경우 실행되는 작업.
데이터베이스의 상태를 변경시킨다.

**Rollback** 트랜잭션이 실패한 경우 실행되는 작업.


```
'송금' 트랜잭션을 통해 트랜잭션의 절차를 알아보자.
'송금' 트랜잭션은 다음 두개의 연산으로 구성되어 있습니다.
첫번째, 송금자의 계좌에서 만원 차감
두번재, 수금자의 계좌에 만원 입금

먼저 트랜잭션에 성공하는 절차를 보겠습니다.
송금자의 계좌에서 만원이 차감되고 수금자의 계좌에 만원이 입금됩니다.
두 연산이 모두 성공했으므로 Commit 작업이 진행되고 데이터베이스의 <계좌>정보에 
저장된 두 사람의 금액 정보가 변경됩니다

트랜잭션에 실패하는 경우를 봅시다.
우선 송금자의 계좌에서 만원이 차감됩니다. 
그런데 수금자의 계좌에 만원이 입금되는 과정에서 알수없는 오류가 발생했습니다.
이 경우, 방치한다면 만원은 그냥 공중으로 사라집니다.
따라서 데이터베이스는 Rollback 작업을 수행하여 이 트랜잭션을
무효화 시킵니다.
```

## 트랜잭션의 특성 (ACID)

1. Atomicity (원자성) 
2. Consistency (일관성) 
3. Isolation (독립성) 
4. Durability (영속성) 


**원자성** 트랜잭션은 분해될 수 없다. 트랜잭션의 연산은 모두 반영되거나 전혀 반영되지 않는다.

**일관성** 트랜잭션이 끝난 후 데이터베이스는 일관성있는 상태가 된다

**독립성** 둘 이상의 트랜잭션이 동시에 실행 중인 경우 한 트랜잭션이 다른 트랜잭션에 끼어들지 않는다

**영속성** 트랜잭션의 결과는 영구적으로 반영된다

```
원자성을 지키기 위한 데이터베이스의 작업은 무엇일까요?
Rollback
```

## 병행 제어

동시에 여러개의 트랜잭션이 실행되는 경우 충돌하지 않도록 병행 제어가 필요하다. 

*방법*

1. Locking
2. Timestamp


### Locking

하나의 트랙잭션이 로킹단위에서 실행중인 경우 잠금을 통해 다른 트랙잭션이 접근하지 못하게 한다.

**로킹 단위** 테이블, 속성, 튜플 등

예) 트랜잭션A가 <학생>테이블에서 실행중인 경우 다른 트랜잭션이 접근할 수 없도록 <학생> 테이블을 잠근다. 이 경우 로킹 단위는 테이블이다
