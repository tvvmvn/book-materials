### 일반 집합 연산

수학적 개념  
연산하는 두 테이블의 컬럼 갯수와 자료형이 같아야 한다(교차곱 제외)  
각 튜플이 집합의 원소에 해당한다.  
<!-- 파티션을 합칠 때 등 사용가능. -->

1. 합집합 (Union)
2. 교집합 (Intersection)
3. 차집합 (Difference)
4. 교차곱 (Cartesian Product)

![set](./set.jpg)

**[예제 보기]** 회원 a, b, c의 정보가 있는 <A동아리 회원>, 회원 c, d, e의 정보가 있는 <B동아리 회원> 등 두개의 릴레이션이 있다.

*1 합집합 결과*  
<A동아리 회원>과 <B동아리 회원> 모두의 정보, 즉 a, b, c, d, e의 정보를 가진 릴레이션

*2 교집합 결과*  
A동아리와 B동아리 모두 가입한 c회원 하나를 가진 릴레이션

*3 차집합 결과*  
<A동아리 회원> - <B동아리 회원>의 경우,
A동아리에 가입하고 B동아리에는 가입하지 않은 a, b 두 회원의 정보를 가진 릴레이션.  

```
두개의 릴레이션이 같은 컬럼 갯수와 같은 자료형을 가질 확률이 얼마나 있을까요? 사실 이건 같은 릴레이션이 관리의 목적이나 용량의 문제 등으로 사전에 분해되었다고 보는 것이 맞습니다.
나중에 배울 데이터베이스 Partioning과도 관련있으니 기억해두세요! 
```

### 순수 관계 연산

관계형 DB를 위해 개발된 연산

1. Select
2. Project
3. Join
4. Division


### Select

조건을 만족하는 Tuple을 구하는 연산.  
수평 연산 

**연산자** σ (시그마)

예) <학생> 테이블에서 점수가 80점 이상인 튜플을 추출하시오
```
σ점수 ≥ 80 (학생)  
```


### Project

제시된 속성값(컬럼)을 추출한다.  
수직 연산

**연산자** 兀 (파이)

예) 
학생 테이블에서 학번, 이름 컬럼 추출하는 연산

```
兀 학번, 이름 (학생)
```

### Join

'공통 속성'을 중심으로 두 개의 릴레이션을 합치는 연산.  
결과 릴레이션은 열이 증가한다

**연산자** ⋈ (bow-tie)

예) <고객>, <주문> 두개의 릴레이션을 조인하는 경우

|고객ID|이름|
|---|---|
|1|a|
|2|b|
<고객>

|주문ID|상품ID|고객ID|
|---|---|---|
|100|1|1|
|100|2|1|
|200|3|2|
<주문>

|주문ID|상품ID|고객ID|이름|
|---|---|---|---|
|100|1|1|a|
|100|2|1|a|
|200|3|2|b|
<고객> ⋈ <주문>


### Division

릴레이션 A, B가 있을 때, B의 조건에 맞는 것들만 A에서 분리하여 프로젝션을 하는 연산

**연산자** ÷ (오벨루스)

예) 다음 연산을 통해 특정 상품을 주문한 주문 정보만을 추출할 수 있다.

|주문ID|상품ID|
|---|---|
|100|1|
|100|1|
|200|2|
|300|3| 
<주문>

|상품ID|
|---|
1
3
<상품>

|주문ID|
|---|
100
300
<주문> ÷ <상품>
