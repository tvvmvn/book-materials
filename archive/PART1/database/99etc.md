## Index

데이터 레코드를 빠르게 접근하기 위해 <키, 포인터> 쌍으로 구성되는 데이터 구조.  
키는 임의값, 포인터는 레코드의 주소를 저장한다.

```
색인은 현실 세계에서 널리 쓰이고 있습니다.
예를 들어 여러분이 수학책에서 <최대공약수> 부분을 찾고싶습니다. 
목차를 보며 처음부터 순서대로 찾는 것보다 '글자순'으로 주제를 정렬해 놓은 색인 (Index)를 보고 <최대공약수, 150페이지> 를 찾아 해당 주제로 빠르게 이동할 수 있습니다.
```


## View

가상 테이블.     
연산 작업 등 테이블과 비슷하게 활용할 수 있다 (약간의 제약사항)  

예) <고객> 테이블에서 도시가 '서울'인 고객만 추출하여 <서울고객> 뷰를 만들 수 있다


## ORM, ODM

서버 측에서 객체와 데이터베이스의 테이블을 연결하는(Mapping) 기술  
서버 개발 언어와 객체 지향 방식으로 데이터베이스를 조작할 수 있다.

1. ORM
2. ODM

**ORM(Object Relational Model)** 객체와 관계형 데이터베이스를 연결하는 기술. 예) JPA (Springboot) 등

**ODM(Object Document Model)** 객체와 NoSQL 데이터베이스를 연결하는 기술. 예) SpringData MongoDB (Springboot) 

```
데이터베이스 조작을 위해서는 SQL가 필요합니다.
하지만 ORM/ODM 을 이용한다면 SQL을 배울 필요가 없어지겠네요! 
```


## Partioning

테이블이 대용량일 경우 작업 시 성능이 저하된다.  
테이블이나 인덱스를 작은 파티션으로 나누는 것을 의미한다.  

*파티셔닝 방법*

1. 범위 분할 (Range Partioning)
2. 해시 분할 (Hash Partioning)
3. 조합 분할 (Composition Partioning)


**범위 분할** 특정 열(일, 월, 분기 등)을 기준으로 분할 한다. 
 
예) 매출 테이블을 월별로 나눈다.


**해시 분할** 해시 함수를 적용한 결과에 따라 테이블을 분할한다.  
특정 파티션에 데이터가 집중되는 범위분할의 단점을 보완한 방법으로 데이터를 고르게 분산할 수 있다. 하지만 특정 데이터가 어디에 있는지 알 수 없다. 
따라서 관리 목적보다는 Disk I/O 및 성능 개선용

```
한 마디로 랜덤분할입니다 😅
억지로 테이블의 크기를 모두 똑같이 맞출 순 있겠네요.
실제 운영되는 테이블에는 사용하지 않습니다. 
보관용으로 추천!
```

**조합 분할** 범위 분할된 파티션을 다시 해시분할한다.  
범위 분할된 파티션이 너무 큰 경우 유용하다.


## 분산 데이터베이스

1. 위치 투명성 (Location Transparency)
2. 중복 투명성 (Replication Transparency)
3. 병행 투명성 (Concurrency Transparency)
4. 장애 투명성 (Failure Transparency)


**위치 투명성** 접근하려는 데이터베이스의 실제 위치를 알 필요없이 단지 데이터베이스의 논리적인 명칭만으로 액세스 할 수 있습니다.

**중복 투명성** 동일 데이터가 여러 곳에 중복되어 존재하더라도 사용자는 마치 하나의 데이터만 존재하는 것처럼 사용합니다. 시스템은 자동으로 여러 자료에 대한 작업을 수행합니다.

**병행 투명성** 다수의 트랜잭션들이 동시에 실현되더라도 트랜잭션 간 서로 결과에 영향을 미치지 않습니다

**장애 투명성** 트랜잭션, DBMS, 네트워크, 컴퓨터의 장애에도 불구하고 트랜잭션을 정확하게 처리합니다.
