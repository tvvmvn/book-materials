## OOP 개념

Object Oriented Programming(객체 지향 프로그래밍)  
객체 중심의 프로그래밍  
반대는 절차지향 프로그래밍. 


## OOP의 구성요소

1. 클래스
2. 객체
3. 메시지


## 클래스

객체 생성을 위한 설명서. 문서  
가구 조립 설명서, 자동차 설계도


### 클래스 구조

속성과 연산으로 이루어져있다

- 속성 (Attribute)  
- 연산 (Operation)  

**속성 (Attribute)** 객체를 이루는 데이터

**연산 (Operation)** 객체가 할 수 있는 동작

![class](./class-inside.png)


## 객체

설명서로부터 생성된 것.  
객체지향 프로그래밍에서 프로그램을 구성하는 단위.  
객체를 조립하여 프로그램을 만든다.  

```
객체는 완성품을 이루는 부품에 비유할 수 있습니다. 엔진, 바퀴 등 여러 개의 부품이 모여 자동차가 되는 것처럼요!
```


## 메시지

외부의 요구사항.  
메시지를 받은 객체는 대응하는 연산을 수행하고 결과를 반환한다

```
객체 지향의 구성요소인 클래스, 객체, 메시지 이 3가지를 
비유를 통해 이해해봅시다.
완성품이 자동차인 경우 '바퀴'는 자동차를 이루는 하나의 객체입니다.
이 바퀴는 '바퀴 설계도'에 해당하는 바퀴 클래스에 의해 제조되었습니다.
다음은 '메시지'의 이해를 위해 주행중인 상황을 가정해봅시다.
'메시지'에 해당하는 운전자의 제어에 따라 바퀴는 굴러가기도 하고 왼쪽으로 또는 오른쪽으로 회전하며 멈추기도 합니다.
```


## OOP의 4가지 특징 

- 상속 (Inheritance)
- 추상화 (Abstraction)
- 다형성 (Polymorphism)
- 캡슐화 (Encapsulation)


## 상속 

자식 클래스가 부모 클래스의 특성을 물려받는 것.  
반복되는 코드를 상속하여 효율성 증가한다

```
'겨울 타이어 설계도'를 개발하는 경우 기존의 '타이어 설계도'에서
대부분을 가져오는 경우와 비슷합니다.
```

## 추상화

추상화를 통해 복잡한 현실 세계를 효과적으로 컴퓨터에 표현할 수 있다.

```
큰 그림을 먼저 그리고 세부적인 그림은 미루는 것과 같습니다.
```

## 다형성

하나의 모습으로 여러가지 역할을 소화할 수 있다.  
코드의 가독성, 코드 작성의 효율성이 증가한다.

```
필요한 도구들을 하나씩 가져다니는 것보다
맥가이버를 가지고 다니는 것처럼
```

## 캡슐화

객체를 은폐하여 내부의 데이터를 보호한다.  
정해진 인터페이스로만 외부세계와 소통할 수 있다.  

```
돈을 금고에 보관 후 문을 통해서만 접근이 가능한 것처럼요
```


## 클래스 관계 (Relationships)

- 연관성 (Association)
- 집합 (Aggregation)
- 일반화 (Generalisation)
- 특수화 (Specialisation)
- 분류화 (Classification)


## 연관 관계

2개 이상의 클래스가 상호 관련되어있다  

**표현 방법** 포함되는 클래스 is member of 포함하는 클래스

```
Guitar is member of Band.
기타는 밴드의 한 구성원이다.
```


## 집합

관련있는 클래스를 묶어 상위 클래스를 만든다  

**표현 방법** 포함되는 클래스 is part of 포함하는 클래스

```
Keyboard is part of Computer
키보드는 컴퓨터의 한 부분이다.
(이게 UML의 포함같은데)
```

## 일반화

추상화된 상위 클래스를 만든다  

**표현 방법** 자식 클래스 is a 부모 클래스

```
Student is a Person
학생은 인간이다
```


## 특수화

상위 클래스를 구체화한 하위 클래스를 만든다  

**표현 방법** 하위 클래스 is a 상위 클래스

```
Student is a Person
학생은 인간이다
```


## 분류화

동일한 형의 객체들을 모아 클래스를 구성한다  

**표현 방법** 객체 is instance of 클래스

```
John is an instance of Student
존은 학생의 한 예시이다.
```


## SOLID

객체지향 설계 원칙

- SRP
- OCP
- LSP
- ISP
- DIP


### SRP

Single Responsibility Principle  
객체는 단 한개의 책임만 가져야 한다

```
식당을 생각해봅시다. 만약 사장 혼자서 음식 조리, 계산, 서빙까지 한다면 식당이 효율적으로 돌아가지 않습니다. 요리사, 캐셔, 웨이터가 각자 맡은 역할을 할때 효율적으로 일 할 수 있습니다
```


### OCP

Open Closed Principle  
객체는 확장에는 열려있고 수정에는 닫혀있어야 한다.

```
결제 시스템을 생각해봅시다. 만약 새로운 결제 수단이 추가되는 경우 기존의 결제 시스템을 그대로 두고 새로운 수단을 추가한 확장된 결제시스템으로 교체하는 것이 좋습니다.

반면 교체가 아닌 기존 시스템을 고쳐서 사용한다면, 기존 시스템으로 다시는 돌아갈 수 없을 것입니다.
```


### LSP

Liskov Substitute Principle
자식은 최소 부모 클래스의 역할을 할 수 있어야 한다.

```
위의 예시와 연결해봅시다. 기존의 결제 시스템이 부모라면 확장된 결제시스템은 자식입니다. 당연히 확장된 결제시스템은 기존 결제시스템의 역할을 다 할수 있어야겠지요?
```


### ISP

Interface Segregation Principle  
클라이언트(구현체)는 사용하지 않는 인터페이스의 영향을 받아서는 안된다

```
예를 들어, 채식주의자가 육식/채식이 모두 있는 메뉴판을 보게된다면 좋지 않을 것입니다. 채식주의자에게는 채식 전용 메뉴판을 주는 것이 좋겠죠?
```


### DIP

Dependency Inversion Principle  
구체적인 것보다는 변하기 어려운 것 즉 추상성이 높은 것에 의존한다

```
어린아이에게 장난감을 선물로 주는 경우, 특정 장난감을 사주는 것보다
용돈으로 주는 것이 낫다 (효율성의 측면에서만 본다면)
```


## OOA

객체 지향 분석 (Object-Oriented Analysis).  
`요구사항`에 적합한 객체, 객체의 속성과 연산, 객체 간 관계 등을 모델링한다. 클래스를 식별하는 것이 주요 목적

*OOA 방법론*

- OMT
- Booch
- Jacobson
- Coad and Yourdon
- Wirfs-Block


```
쉽게 말하면 OOA = 설계도를 만드는 과정이라고 볼 수 있습니다.
설계도는 여러가지 부품(객체)들과 그들의 복잡한 상호작용을 나타냅니다.
OOA는 객체지향 프로그래밍(OOP)를 통한 S/W 구현 단계 전에 필요한 과정이 되겠죠.
```


## OMT 

Object Modeling Tool.  
럼바우 방법론은 객체지향 분석 및 설계를 위한 방법론으로, 소프트웨어의 모든 구성 요소를 `그래픽`으로 모델링하는 기법입니다. 복잡한 시스템을 객체 중심으로 분석하고 설계하는 틀을 제공합니다. UML 탄생에 지대한 영향을 미친 고전적인 객체지향 분석 기법으로 알려져 있습니다. 

다음의 3단계로 구분된다

1. 객체 모델링
2. 동적 모델링
3. 기능 모델링


### 객체 모델링

정보 모델링 (Information Modeling)이라고도 한다.  
객체의 속성과 연산, 객체들 간의 관계 정의 등  

**표현 방법** UML 클래스 다이어그램

### 동적 모델링

객체 간의 상호작용, 제어 흐름, 동작 순서 등 동적인 행위를 표현한다.  

**표현 방법** UML 상태 다이어그램

### 기능 모델링

프로세스 간의 상호작용 등을 표현한다.  

**표현 방법** 자료흐름도(DFD)

```
OMT의 각 단계를 자동차를 설계하는 과정에 비유해봅시다.

첫번째, 객체 모델링은 자동차의 핵심 부품을 설계하는 것입니다.
엔진, 제동장치, 바퀴 등등

두번째, 동적 모델링은 이러한 핵심 부품들의 내부 상호작용 및 움직임 설계하는 것입니다.

세번째, 기능 모델링은 이러한 핵심 부품들 간의 상호작용을 통해 자동차의 작동을 확인하는 것입니다.
```
