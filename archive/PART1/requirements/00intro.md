## 요구사항 개념

소프트웨어가 
1 어떤 문제를 해결하기 위해 제공하는 서비스에 대한 설명과 
2 정상적으로 운영되는데 필요한 제약조건.  

말이 조금 어렵죠? 개발에 참여하는 이해관계자들은 각자의 요구사항을 가지고 있습니다. 각자의 요구사항을 조율하여 하나의 완성된 요구사항이
나오게 됩니다.


## 요구사항의 종류

1. 기능 요구사항
2. 비기능 요구사항

### 기능 요구사항

소프트웨어의 기능에 대한 요구사항.

예) 배달앱에서 지도 기능을 사용할 수 있어야 한다

### 비기능 요구사항

기능을 제외한 요구사항.  
품질이나 제약사항과 관련된 요구사항.  

예) 
- 장비 구성(H/W, S/W)
- 성능
- 인터페이스
- 데이터
- 테스트
- 보안

> 모두가 따라야 할 회의록(문서)이 나오는 과정


### 요구사항 도출

소프트웨어가 무엇을 해야하는지 이해하는 단계  
`이해관계자(사용자, 개발자 등)`를 식별하는 단계 


#### 요구사항 도출 기법

1. 인터뷰, 설문  
2. Brainstorming (회의)
3. Usecase Diagram


#### Usecase Diagram

애플리케이션의 흐름을 설명하기 위한 간단한 그림입니다.
예를 들어, 온라인 쇼핑몰을 구축하는 경우 구매-결제-배송 등의
흐름을 간단한 그림으로 나타낼 수 있습니다. 이 다이어그램은
개발자간 또는 개발자와 사용자간의 소통을 위해 활용됩니다.



### 요구사항 분석

개발 대상에 대한 사용자의 요구사항을 이해하고 문서화하는 활동  
DFD 활용


#### DFD

자료흐름도(Data Flow Diagram)  
요구사항을 분석하는 대표적 기법입니다.  
자료 흐름 그래프, 버블 차트라고도 한다.  


#### 자료흐름도의 구성요소

![dfd-symbol](./dfd-symbol.jpg)

1. 프로세스  
자료를 변환시키는 시스템의 한 부분.  
처리, 기능, 변환, 버블이라고도 표현한다

2. 자료 흐름  
자료의 이동, 흐름

3. 자료 저장소  
파일, 데이터베이스등 자료를 보관하는 곳

4. 단말  
시스템과 교신하는 외부 개체  
입력데이터를 만들고 출력데이터를 받는 대상


#### DD

자료 사전(Data Dictionary).  
자료흐름도에 있는 자료를 자세히 설명하는 것.
데이터를 설명하는 데이터로, 메타데이터라고도 한다.

| 기호 | 의미 | - |
|---|---|---|
| = | 자료의 정의 | ~로 구성되어있다(is composed of) |
| + | 자료의 연결 | 그리고(And) |
| ()| 자료의 생략 | 선택적(Optional) |
| []| 자료의 선택 | 또는(or) |
| {}| 자료의 반복 | Iteration of |
| **| 자료의 설명 | 주석 (Comment) |


#### DFD 예시

![dfd](./dfd.png)

회계부서는 직원 <근무 시간표>와 <직원 목록표>를 참고하여
급여를 계산하고 직원에게 급여를 지급합니다.


### 요구사항 명세

분석된 요구사항을 바탕으로 문서화한다.  
소단위 명세서(Mini-Spec) 활용


#### 요구사항 명세 기법

1. 정형 명세기법
2. 비정형 명세기법


#### 정형 명세기법

수학적인 기호들을 사용하여 요구사항을 정확하고 간결하게 표현할 수 있습니다.
또한 작성자의 주관적인 의견이 들어가기 힘들기 때문에 작성자와 상관없이
모든 명세서들은 일관성이 있을 겁니다.
하지만 복잡한 기호들로 인해 사용자가 이해하기 어렵다는 단점이 있습니다

#### 비정형 명세기법

일상에서 사용하는 언어(문서) 또는 그림을 기반으로 명세서를 작성합니다.
그러다보니 작성자에 따라 결과가 다를 수 있습니다.
하지만 일상의 언어 또는 그림으로 표현했기 때문에 이해하기는 쉽겠네요.


#### 요약

|  | 정형 명세 기법 | 비정형 명세 기법 |
|--|-------------|----------------|
| 기법 | 수학적 원리 기반 | 상태/기능/객체 기반 |
| 작성 방법 | 수힉적 기호 | 자연어 기반의 서술, 다이어그램 |
| 특징     | 높은 일관성, 이해하기 어려움 | 낮은일관성, 이해하기 쉽다 |
| 종류     | VDM, Z, Petri-net, CSP 등 | FSM, Decistion Table, ER Model 등 |
