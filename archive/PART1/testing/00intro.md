## 테스트 개념

애플리케이션에 잠재되어 있는 결함을 찾아내는 일련의 행위 또는 절차


## 테스트 관련 용어

- 테스트 케이스
- 테스트 시나리오
- 테스트 오라클


## 테스트 케이스

테스트 항목에 대한 명세서.  
입력값, 실행 조건, 기대 결과 등으로 구성되어 있다.

*example*
```
두개의 숫자를 입력받아 덧셈을 수행하고 결과값을 출력하는 <덧셈함수>를 테스트하려고 합니다.
<덧셈함수> 테스트케이스는 다음의 내용을 포함할 것입니다.

입력값: 1, 2 
기대 결과: 3
```


## 테스트 시나리오

관련된 테스트케이스들을 묶은 것이다.  
테스트케이스를 적용하는 구체적인 절차를 명시한다.  
입력값, 실행 조건, 기대 결과 등으로 구성되어 있다.


*example*
```
여러분이 <계산기 프로그램>을 만드는 과정을 생각해봅시다.
<4칙 연산> 테스트 시나리오는 다음의 4가지 테스트 케이스를 포함할 것입니다.

<덧셈> 테스트케이스
<뺄셈> 테스트케이스
<곱셈> 테스트케이스
<나눗셈> 테스트케이스

<4칙 연산> 테스트케이스는 다음의 내용을 포함합니다

입력값: 1 + 2 - 3 * 4
절차: 곱셉,나눗셈 => 덧셈, 뺄셈 순서
실행조건: 괄호없음
기대 결과: -9
```


## 테스트 오라클

테스트의 결과가 참인지 거짓인지 판단하기 위하여 `사전에 증명된 참값(오라클)`과 테스트 결과를 비교하는 기법. 


```
한마디로 '테스트 결과를 테스트하는 것'입니다. 
예를 들어보죠.
"먹지 마세요. 배탈이 날 수 있습니다" 라는 경고 문구(오라클)가 적힌 제품이 있습니다. 이미 배탈이 난 사례가 있거나 배탈을 일으키는 물질이 첨가된 것이 확인되었을 것입니다.
그리고 이것이 정말로 배탈을 일으키는지 먹어보는 행위가 바로 테스트 오라클입니다.
(따라하지 마세요 😅)
```


### 특징

- 제한된 검증
- 수학적 기법
- 자동화 기능


### 종류

- 참 오라클 (True Oracle)
- 샘플링 오라클 (Sampling Oracle)
- 추정 오라클 (Heuristic Oracle)
- 일관성 검사 오라클 (Consistent Oracle)


**참 오라클** 모든 테스트케이스의 입력값에 대해 기대하는 결과를 제공하는 모형이다. 발생된 모든 오류를 검출할 수 있다.

**샘플링 오라클** 특정한 몇몇 테스트 케이스의 입력값들에 대해서만 기대하는 결과를 제공하는 모형이다. 전수 테스트가 불가능한 경우 사용하는 오라클이다.

**추정 오라클** 특정 테스트케이스의 입력값에 대해 기대하는 결과를 제공하고 나머지 입력값들에 대해서는 추정으로 처리하는 모형이다.

**일관성 검사 오라클** 애플리케이션에 변경이 있을 때, 테스트케이스의 수행 전/후 결과값이 동일한지 확인하는 모형이다.


## 테스트의 기본 원리

- 파레토 법칙 (Pareto Principle)
- 살충제 패러독스 (Pesticide Paradox)
- 오류-부재의 궤변 (Absence of Errors Fallacy)

**파레토 법칙** 애플리케이션의 20%에 해당하는 코드에서 전체 결함의 80%가 발견된다는 법칙이다.

**살충제 패러독스** 동일한 테스트케이스로 동일한 테스트를 반복하면 더 이상 결함이 발견되지 않는 현상이다.

**오류-부재의 궤변** 소프트웨어의 결함을 모두 제거해도 사용자의 요구사항을 만족하지 못하면 해당 소프트웨어는 품질이 높다고 말할 수 없다는 것을 의미한다.
