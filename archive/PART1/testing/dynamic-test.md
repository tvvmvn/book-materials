## 동적 테스트란?

프로그램을 실행하고 테스트 한다.  
소프트웨어 개발의 모든 단계에서 수행하는 테스트이다.  

- White-Box Test
- Black-Box Test


## 화이트박스 테스트

모듈의 `원시 코드(Source Code)`를 오픈시킨 상태에서 원시 코드의 논리적인 모든 경로를 테스트하여 테스트케이스를 설계하는 방법이다.  
모듈 안의 작동을 직접 관찰할 수 있다.  
원시 코드의 모든 문장을 한번 이상 실행함으로써 수행된다.  

*종류*

- 기초 경로 검사 (Base Path Testing)
- 제어 구조 검사 (Control Structure Testing)


## 기초 경로 검사

테스트케이스 설계자가 절차적 설계의 `논리적 복잡성`을 측정할 수 있게 해주는 테스트 기법이다.
대표적인 화이트 테스트 기법이다.

### 순환복잡도  

한 프로그램의 논리적인 복잡도를 측정하기 위한 척도이다.
맥케이브 순환도(McCabe's Cyclomatic)라고도 한다.


*제어흐름도 G에서 순환 복잡도 V(G)의 계산 방법*  

**방법1** 순환 복잡도는 제어 흐름도의 영역 수와 일치하므로 영역의 수를 구한다.

**방법2** V(G) = E - N + 2 (E는 화살표의 수, N은 노드의 수)


*예제 :*

![cyclomatic-complexity](./control-flow.png)

```
방법 1
화살표로 구분되는 영역의 갯수를 구한다.  
A, B, C, D 즉 V(G)는 4이다

방법 2
V(G) = 화살표의 수 - 노드의 수 + 2  
V(G) = 11 - 9 + 2 =  4
```


## 제어 구조 검사

테스트에서 소스코드의 어떤 부분에 중점을 둘 것인지에 따라 다음의 종류를 분류됩니다.

- 데이터 흐름 검사 (Data Flow Testing)
- 조건 검사 (Condition Testing)
- 반복검사 (Loop Testing)

**데이터 흐름 검사** 변수의 정의와 변수의 사용 위치에 초점을 맞춰 실시하는 테스트케이스 설계 기법

**조건 검사** 모듈 내에 있는 논리적 조건을 테스트하는 테스트케이스 설계 기법

**반복 검사** 프로그램의 반복(Loop)구조에 초점을 맞춰 실시하는 테스트케이스 설계 기법


### 테스트 검증 기준 (Test Coverage)

얼마나 자세히 테스트 할 것인가?  
어디까지 테스트할 것인가?

- 문장(구문) 검증 기준 (Statement Coverage)
- 분기 검증 기준 (Branch Coverage)
- 조건 검증 기준 (Condition Coverage)
- 분기 / 조건 검증 기준 (Branch / Condition Coverage)


### 문장 검증 기준 

소스 코드의 `모든 구문`이 한번 이상 수행되도록 테스트케이스를 설계한다.

![coverage](./coverage.png)

*답*
```
1 2 3 4 5 6 7
```


### 분기 검증 기준

소스 코드의 `모든 조건문`에 대해 조건식의 결과가 참인 경우와 거짓인 경우가 각각 한번 이상 수행되도록 테스트케이스를 설계한다.
결정 검증 기준(Decision Coverage)라고도 한다.


![coverage](./coverage.png)

*답*   
```
최소 2번 테스트 해야한다:

YY: 1 2 3 4 5 6 1 
NN: 1 2 4 5 6 7 
또는 
YN: 1 2 3 4 5 6 7
NY: 1 2 4 5 6 1
```


### 조건 검증 기준

소스 코드의 `조건문에 포함된 개별 조건식`의 결과가 참인 경우와 거짓인 경우가 한번 이상 수행되도록 테스트케이스를 설계한다.

예) if (x > 0 && x < 10)

*답*  
```
최소 2번 테스트해야한다:

YY, NN 또는 YN, NY 
```


### 분기 / 조건 기준

분기 검증 기준과 조건 검증 기준을 모두 만족하도록 테스트케이스를 설계한다.


## Blackbox 테스트

소프트웨어의 각 기능이 완전히 작동되는 것을 입증하는 테스트로, `기능 테스트`라고도 한다. 사용자의 요구사항 명세를 보면서 테스트한다. 소프트웨어 인터페이스(UI 등)를 통해 실시된다.

*종류*

- 동치 분할 검사 (Equivalence Partioning Testing)
- 경계값 분석 (Boundary Value Analysis)
- 원인-효과 그래프 (Cause-Effect Graphing)
- 오류 예측 검사 (Error Guessing)
- 비교 검사 (Comparison Testing)


## 동치 분할 검사

입력 데이터에 따른 결과값을 테스트할 때 사용되는 기법이다. 
입력 데이터에 따라 다르게 동작하는 기능을 테스트하는 경우에 사용된다. 

| 점수 | 성적 |
|---|---|
| 90~100 | A |
| 89~89 | B |
| 70~79 | C |
| 0~69 | D |


*동치 분할 검사*

|테스트케이스| 1 | 2 | 3 | 4 |
|---|---|---|---|---|
|입력값|96|82|75|96|
|예상 결과|A|B|C|D|
|실제 결과|A|B|C|D|

## 경계값 분석 

입력 조건의 중간값보다 `경계값`에서 오류가 발생될 확률이 높다는 점을 이용하여 입력 조건의 경계값을 테스트케이스로 선정하여 검사하는 기법이다.

*경계값 분석* (동치분할 검사의 표 참조)

|테스트케이스|1|2|3|
|---|---|---|---|
|입력값|69|80|100|
|예상 결과|D|B|A|
|실제 결과|D|B|A|


## 원인-효과 그래프 

입력 데이터 간의 관계와 출력에 영향을 미치는 상황을 체계적으로 분석한 다음 효용성이 높은 테스트케이스를 선정하여 검사하는 기법이다.

```
입력값과 결과 사이의 관계를 원인-효과 그래프로 나타내고 테스트케이스를 도출하는 방법이다.
```
