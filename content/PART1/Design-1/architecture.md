# S/W 아키텍처 (S/W Architecture)

S/W 아키텍처는 소프트웨어의 '구축 양식', '구축 스타일' 등을 의미합니다.

예를 들어 건축에서 어떤 아키텍처를 선택하느냐에 따라 건물의 모습과 용도가 완전히 달라지는 것처럼, 어떤 S/W 아키텍처를 선택하느냐에 따라 소프트웨어의 모습과 용도는 달라집니다.

개발자들은 시스템 개발에 앞서 요구사항과 사용 목적에 부합하는 적절한 아키텍처를 선택합니다.


# 아키텍처 설계 4대 원칙

소프트웨어 아키텍처 설계의 4가지 기본 원리는 다음과 같습니다.
기본 원리에 충실할수록 더 좋은 아키텍처로 평가됩니다.

- 모듈화 (Modularity)
- 추상화 (Abstraction)
- 단계적 분해 (Stepwise Refinement)
- 정보 은닉 (Information Hiding)

모듈화는 소프트웨어의 성능 향상과 관리의 편의성 등을 위해 시스템을 여러 모듈로 나누는 것을 의미합니다. 모듈 내부의 응집도를 최대화하고 모듈 간 결합도를 최소화하는 것이 모듈화의 목표입니다.

추상화는 복잡한 내부 구현을 숨기고 쉽고 단순한 인터페이스만 노출시키는 것을 의미합니다. 추상화를 통해 모듈은 서로에 대해 자세히 알 필요가 없어지고 이는 모듈 간 결합도를 낮추는 역할을 합니다.

단계적 분해는 아키텍처를 상위 개념에서 하위 개념 방향으로 진행하며 구체화시키는 과정을 의미합니다. 예를 들어 소프트웨어의 포괄적인 기능을 먼저 정의하고 알고리즘과 자료구조 등 상세한 작업은 나중에 진행합니다.

정보 은닉은 모듈의 내부 정보를 숨기고 승인된 인터페이스를 통해서만 모듈 내부에 접근할 수 있도록 하는 과정입니다. 정보 은닉을 통해 모듈 내부의 정보를 보호할 수 있습니다.


# 아키텍처 패턴 (Architecture Pattern)

S/W를 설계할 때 참조할 수 있는 정형화된 아키텍처 패턴을 의미합니다. 다음은 주요 아키텍처 패턴입니다.

- 계층형 패턴 (Layered Pattern)
- 클라이언트-서버 패턴 (Client-Server Pattern)
- 파이프-필터 패턴 (Pipe-Filter Pattern)
- MVC 패턴 (MVC Pattern)

계층형 패턴은 고전적인 패턴으로 시스템이 여러 개의 계층(Layer)으로 구성됩니다. 
서로 마주보는 계층 간에서만 상호작용이 일어나는 구조로 하위 계층은 상위 계층에 대한 서비스 제공자가 되고 상위 계층은 하위 계층의 클라이언트가 됩니다. 

예) OSI 모델, WAS 서버

*그림 - 레이어 패턴*


클라이언트 서버 패턴은 하나의 서버와 다수의 클라이언트로 구성되는 패턴입니다. 클라이언트가 서버에 요청을 전송하면 서버가 클라이언트에게 응답을 제공하는 구조입니다.
대표적 사례로 다수의 사용자들이 하나의 웹사이트 또는 웹앱을 이용하는 경우가 있습니다.

*그림 - 클라이언트 - 서버 패턴*


파이프-필터 패턴은 일련의 순서에 따라 원본 데이터를 최종 결과물로 변환하는 프로세스를 가지는 패턴입니다. 데이터 스트림(Data Stream)이 파이프-필터를 지날 때 각 필터는 자신에게 주어진 방법으로 데이터를 처리하고 파이프는 필터 간의 이동 경로 역할을 합니다. 데이터 변환, 버퍼링, 동기화 작업 등에 주로 사용됩니다. 

*그림 - 파이프-필터 패턴*


MVC 패턴은 UI를 구축할 때 사용되는 패턴으로 모델(Model), 뷰(View), 컨트롤러(Controller)의 3가지 요소로 구성됩니다. 모델은 UI에 출력될 데이터를 담당하고 뷰는 사용자에게 보여질 화면을 담당합니다. 컨트롤러는 모델과 뷰를 제어하고 사용자에게 결과물을 제공하는 역할을 합니다.

'회원정보 페이지'를 예로 들어보겠습니다. 우선 모델은 '회원정보' 데이터를 가지고 있습니다. 뷰는 모델로부터 '회원정보' 데이터를 입력받고 사용자에게 보여질 출력물을 만듭니다. 컨트롤러는 뷰로부터 출력물을 전달받고 최종적으로 사용자에게 보여줍니다.

*그림 - MVC 패턴*


# 기타 아키텍처 패턴

- 마스터-슬레이브 (Master-Slave)
- 브로커 (Broker)
- 피어투피어 (Peer-To-Peer)
- 이벤트-버스 (Event-Bus)
- 블랙보드 (Blackboard)
- 인터프리터 (Interpreter)

마스터-슬레이브 패턴은 마스터가 여러 슬레이브 컴포넌트들에게 작업을 할당하고 결과물을 돌려받는 방식의 패턴입니다.

예) 장애 허용 시스템, 병렬 컴퓨팅 


브로커 패턴은 많은 사용자들의 요청과 여러 서비스 제공자들이 존재하는 환경에서 중개 역할을 하는 브로커를 두는 패턴입니다. 브로커는 사용자의 요청에 적합한 서비스 제공자를 연결함으로써 복잡한 환경에서도 빠르고 안전한 통신을 가능하게 합니다.

예) 분산 시스템


피어-투-피어 패턴은 피어(Peer)라 불리는 하나의 컴포넌트가 클라이언트가 될 수도 있고 서버가 될 수도 있는 패턴입니다. 적용 사례로 파일 공유 네트워크가 있습니다. 

예를 들어 영화 공유 네트워크에서 사용자는 다른 사용자가 가진 영화를 다운받는 클라이언트가 될 수도 있고 내가 가진 영화를 다른 사람들에게 공유하는 서버가 될 수도 있습니다.


이벤트-버스 패턴은 이벤트 기반의 시스템에서 볼 수 있는 패턴으로 이벤트 소스(Event Source), 이벤트 리스너(Event Listener), 그리고 중간에 이벤트 버스(Event Bus)로 구성됩니다. 이벤트 소스가 새로운 이벤트를 이벤트 버스(모든 종류의 이벤트들이 머무는 곳)에 발행하면 해당 이벤트를 구독한 리스너들이 정해진 작업을 수행하는 패턴입니다.

예) 알림 메시지


블랙보드 패턴은 해결책이 명확하지 않거나 여러 분야의 지식이 필요한 복잡한 문제를 해결할 때 적합한 패턴입니다. 공유 데이터 저장소인 블랙보드(Blackboard), 지식 소스(Knowledge Source), 제어 컴포넌트(Control Component)로 구성이 되며 작동 과정을 다음과 같이 비유할 수 있습니다.

칠판(블랙보드) 앞에서 사회자(제어 컴포넌트)의 입회 하에 여러 명의 전문가(지식 소스)가 문제 해결을 위해 자신이 가진 지식을 칠판에 적고 회의하며 해결책을 찾아갑니다.

예) 음성 인식, 차량 식별, 신호 해석 


인터프리터 패턴은 프로그래밍 언어나 명령어 등 새로운 문법을 창조하려고 할 때 문법을 이해하고 해석하는 해석기(Interpreter)를 만드는 데 사용되는 패턴입니다. 

예를 들어 사용자 친화적인 SQL 쿼리어를 C 언어 기반으로 개발된 데이터베이스가 이해할 수 있도록 SQL 파서(인터프리터)가 중간에서 번역시키는 과정을 생각할 수 있습니다.

예) 컴파일러/인터프리터, 정규식, SQL 파서, 번역기
