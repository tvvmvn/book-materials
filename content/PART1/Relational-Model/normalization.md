# 정규화

테이블의 속성들이 상호 종속적인 관계를 갖는 특성을 이용하여 테이블을 무손실 분해하는 과정입니다. 정규화의 목적은 가능한 한 중복을 제거하여 이상의 발생 가능성을 줄이는 것입니다.

논리적 설계 단계에서 수행합니다.


# 이상 (Anomaly)

데이터베이스에서 데이터들이 불필요하게 중복되어 발생하는 곤란한 현상을 의미합니다.

삽입 이상 (Insertion Anomaly): 테이블에 데이터를 삽입할 때 원하지 않는 값들로 인해 데이터를 삽입할 수 없는 현상을 의미합니다. 

삭제 이상 (Deletion Anomaly): 테이블에서 튜플을 삭제할 때 의도와는 상관없는 값들도 함께 삭제되는 현상을 의미합니다. 

갱신 이상 (Update Anomaly): 테이블에서 튜플의 속성값을 갱신 할 때 일부 튜플의 정보만 갱신되어 정보의 불일치성이 생기는 현상을 의미합니다.


# 함수적 종속

릴레이션에서 속성 A의 값이 속성 B의 값을 하나만 결정할 때, 속성 B는 속성 A에 함수적으로 종속된다고 말합니다. 이때 A를 결정자, B를 종속자라고 합니다.

이를 기호로 표현하면 다음과 같습니다. 
A -> B

예제)
<학생>테이블에서 아래와 같이 학번 -> 이름이 성립합니다.

100 -> 김철수
200 -> 이영희
300 -> 김수진

이런 경우는 어떨까요. 이름 -> 생일
아래와 같이 한 이름에 대해 여러 생일이 있을 수 있으므로 이는 함수적 종속이 아닙니다.

이영희 -> 1월 2일
이영희 -> 3월 5일


# 함수적 종속의 유형

함수적 종속은 종속의 성격에 따라 다음의 3가지 종류로 구분됩니다

- 완전 함수적 종속
- 부분 함수적 종속
- 이행적 함수적 종속

완전 함수적 종속은 위에서 배운 함수적 종속의 정의와 기본적으로 같습니다.
예) 학번 -> 이름 

반면 기본키가 복합키일 때, 기본키를 이루는 속성 K만으로도 속성 A의 값이 결정될 때 A는 기본키에 부분 함수적으로 종속된다고 말합니다.

예를 들어 <수강> 테이블에서 (학번, 과목)이 기본키 일 때 '학년'은 '학번'만 알아도 구할 수 있기 때문에 '학년'은 기본키에 대해 부분 함수적 종속입니다.
기호로 표현하면 다음과 같습니다. 

(학번, 과목) -> 학년

이행적 함수적 종속은 릴레이션을 구성하는 속성 A, B, C가 있고 A->B, B->C가 성립될 때 자연스럽게 A->C가 발생하는데, 이때 A->C 종속 관계를 의미합니다.

예를 들어 <학생> 테이블이 (학번, 학과ID, 학과 전화번호)로 구성될 때 학번->학과ID, 학과ID->학과 전화번호가 성립되어 이행적 종속 관계인 학번->학과 전화번호가 발생합니다.


# 정규형 

릴레이션을 종속 관계나 속성의 형태에 따라 여러가지 형태로 구분할 수 있습니다. 숫자가 더 높은 정규형은 그보다 더 낮은 정규형들을 모두 만족합니다. 

- 제 1정규형(1NF)
- 제 2정규형(2NF)
- 제 3정규형(3NF)
- BCNF (Boyce-Codd Normal Form)
- 제 4정규형(4NF)
- 제 5정규형(5NF)


# 제 1정규형

제 1정규형은 모든 속성의 값이 원자값(더 이상 분해할 수 없는 값)인 정규형입니다. 

다음은 제 1정규형을 만드는 과정입니다. 모든 튜플이 원자값을 가지도록 합니다.

# 제 2정규형

제 2 정규형은 모든 속성이 기본키에 대해 완전 함수적 종속을 만족하는 정규형입니다. 

다음은 제 2정규형을 만드는 과정입니다. 부분 함수적 종속을 제거해서 제 2정규형으로 만듭니다.

# 제 3정규형

제 3정규형은 기본키가 아닌 모든 속성이 기본키에 대해 이행적 함수적 종속을 만족하지 않는 정규형입니다.

다음은 제 3정규형을 만드는 과정입니다. 이행적 함수정 종속을 제거해서 만들 수 있습니다.

<학생> 테이블이 (학번, 학과ID, 학과 전화번호)로 구성될 때 학번->학과ID, 학과ID->학과 전화번호가 성립되어 이행적 종속 관계인 학번->학과 전화번호가 발생합니다.

두개의 테이블 <학생>(학번, 학과ID), <학과>(학과ID, 학과 전화번호) 두개의 테이블로 분할합니다.

# 반정규화

시스템의 성능을 향상시키고 개발과 운영의 편의성을 높이기 위해 정규화된 데이터 모델을 의도적으로 통합, 중복, 분리하여 정규화 원칙을 위배하는 행위입니다. 

반정규화를 수행하면 시스템의 성능이 향상되고 관리 효율성을 증가하지만 데이터의 일관성과 정합성이 저하될 수 있습니다. 또한 과도한 정규화는 오히려 성능을 저하시킬 수 있으므로 주의해서 사용해야 합니다.
