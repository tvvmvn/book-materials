# 관계 연산 

관계 모델에서 수행하는 연산을 의미합니다.
데이터베이스를 조작하는 SQL의 기초가 됩니다.

- 관계 대수 (Relational Algebra)
- 관계 해석 (Relational Calculus)


# 관계 대수 

릴레이션으로부터 원하는 정보를 구하기 위해 사용되는 절차적 언어입니다. 관계 대수 연산에서 피연산자, 연산 결과는 모두 릴레이션입니다.

일반 집합 연산 (Set Operation): 수학에서 사용하는 집합 연산
순수 관계 연산 (Relation-Specific Operation): 관계 모델에 적용하기 위해 특별히 개발된 연산


# 일반 집합 연산

수학의 집합 연산과 같습니다. 교차곱을 제외하고 나머지 연산에 참여하는 두 집합은 구조가 일치해야 합니다. (속성의 수와 각 속성의 도메인이 일치해야 함)

- 합집합 (Union)
- 교집합 (Intersection)
- 차집합 (Difference)
- 교차곱 (Cartesian Product)


# 합집합 

합집합은 두 릴레이션에 존재하는 튜플의 합집합에서 중복되는 튜플은 제거하는 연산입니다. 
합집합의 결과로 생성된 릴레이션의 카디널리티는 두 릴레이션의 카디널리티의 합보다 크지 않습니다.
기호) A⋃B

예를 들어 오픈마켓 앱의 사용자들이 어떤 도시들에 거주하는지 알고 싶습니다.
<판매자> 테이블로부터 '도시'를 추출한 릴레이션 A와
<구매자> 테이블로부터 '도시'를 추출한 릴레이션 B를 합집합 연산합니다.


# 교집합

교집합은 두 릴레이션에 존재하는 튜플의 교집합을 구하는 연산입니다. 
교집합의 결과로 생성된 릴레이션의 카디널리티는 두 릴레이션 중 카디널리티가 적은 릴레이션의 카디널리티보다 크지 않습니다.
기호) A⋂B

예를 들어 오픈마켓 앱에서 판매자와 구매자들 모두가 거주하는 도시들을 알고 싶습니다.
<판매자> 테이블로부터 '도시'를 추출한 릴레이션 A와
<구매자> 테이블로부터 '도시'를 추출한 릴레이션 B를 합집합 연산합니다


# 차집합

차집합은 두 릴레이션에 존재하는 튜플의 차집합을 구하는 연산입니다. 
차집합의 결과로 생성된 릴레이션의 카디널리티는 릴레이션 A의 카디널리티보다 크지 않습니다
기호) A˗B

예를 들어 오픈마켓 앱에서 판매자들만 있는 도시들을 알고 싶습니다.
<판매자> 테이블로부터 '도시'를 추출한 릴레이션 A에서
<구매자> 테이블로부터 '도시'를 추출한 릴레이션 B를 뺍니다


# 교차곱

교차곱은 두 릴레이션에 있는 튜플들의 순서쌍을 구하는 연산입니다. 
교차곱의 디그리는 두 릴레이션의 디그리를 더한 것과 같고 카디널리티는 두 릴레이션의 카디널리티를 곱한 것과 같습니다.
기호) A×B

예제)
디그리 2, 카디널리티 3인 릴레이션 A와 디그리 3, 카디널리티 4인 릴레이션 B를 교차곱 연산하는 경우, 결과 릴레이션 R의 디그리는 5, 카디널리티는 12입니다.


# 순수 관계 연산

관계 모델에 적용하기 위해 특별히 개발된 순수 관계 연산입니다. 다음의 4가지 연산이 있습니다.

- Select 
- Project
- Join 
- Division


# Select

Select는 릴레이션에 존재하는 튜플 중에서 선택 조건을 만족하는 튜플들을 추출하는 연산입니다. 릴레이션의 행(튜플)을 추출하므로 수평 연산이라고도 합니다. 
연산자) σ(시그마)

예를 들어 <직원> 테이블에서 직급이 대리인 튜플만 추출하고 싶습니다.
σ직급 = '대리'(직원)


# Project

Project는 릴레이션에서 주어진 속성들만 추출하는 연산입니다. 릴레이션의 열(속성)을 추출하는 것이므로 수직 연산이라고 합니다.
연산자) ㅠ(파이)

<직원> 테이블에서 이름과 직급 데이터만 추출하고 싶습니다.
예) ㅠ이름,직급(직원)


# Join

Join은 공통 속성을 중심으로 두개의 릴레이션을 하나로 합쳐서 새로운 릴레이션을 만드는 연산입니다. Join의 결과는 릴레이션에 교차곱을 수행한 다음 Select를 수행한 것과 같습니다. 
연산자) ⋈(보우타이)

학생들이 어떤 동아리에 가입했는지 한 번에 볼 수 있는 테이블이 필요합니다.
=> 학생 ⋈ 동아리

예제)
<학생>(학번, 이름, 동아리ID), <동아리>(동아리ID, 동아리명) 테이블을 조인하면 (학번, 이름, 동아리ID, 동아리명)으로 구성된 릴레이션을 구할 수 있습니다.


# Division

Division은 X ⊃ Y인 두 개의 릴레이션 R(X)와 R(Y)가 있을 때 R의 속성이 S의 속성값을 모두 가진 튜플에서 S가 가진 속성을 제외한 속성만을 구하는 연산입니다.
연산자) ÷ (나누기)


# 관계 해석 

관계 데이터 모델의 제안자인 코드(E.F.Codd)가 수학의 술어 해석(Predicate Calculus)에 기반을 두고 관계 데이터베이스를 위해 제안했습니다. 

관계 해석은 원하는 정보가 무엇이라는 것만 정의하는 비절차적 특성을 지닙니다. 
원하는 정보를 정의할 때에는 계산 수식을 사용합니다.
