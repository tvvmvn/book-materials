# Database


## DBMS

데이터베이스 관리 시스템(Database Management System)의 약자로 사용자의 요구에 따라 정보를 생성해주고 데이터베이스를 관리해주는 소프트웨어입니다.

DBMS의 필수 기능

- 정의 기능 (Definition)
- 조작 기능 (Manipulation)
- 제어 기능 (Control)

정의 기능은 데이터의 형과 구조에 대한 정의, 이용 방식, 제약 조건 등을 명시하는 기능입니다. 조작 기능은 데이터 검색, 갱신, 삽입, 삭제 등을 위해 인터페이스 수단을 제공하는 기능입니다. 제어 기능은 데이터의 무결성, 보안, 권한 검사, 병행 제어를 제공하는 기능입니다.


## 스키마

데이터베이스의 구조와 제약 조건에 관한 전반적인 명세를 의미합니다. 스키마는 다음의 3가지로 분류됩니다

- 외부 스키마
- 개념 스키마
- 내부 스키마

외부 스키마는 사용자나 응용 프로그래머가 각 개인의 입장에서 필요로 하는 데이터베이스의 논리적 구조를 정의한 스키마입니다. 개념 스키마는 데이터베이스의 전체적인 논리적 구조를 나타냅니다. 모든 응용 프로그램이나 사용자들이 필요로 하는 데이터를 종합한 조직 전체의 데이터베이스로서 하나만 존재합니다. 내부 스키마는 물리적 저장장치의 입장에서 본 데이터베이스의 구조입니다. 실제로 저장될 레코드의 형식, 저장 데이터 항목의 표현 방법, 내부 레코드의 물리적 순서 등을 나타냅니다.


## 데이터베이스 설계

데이터베이스를 설계하는 과정은 5단계가 있습니다

1. 요구 조건 분석
2. 개념적 설계
3. 논리적 설계
4. 물리적 설계
5. 구현

요구조건 분석은 데이터베이스를 사용할 사람들로부터 필요한 용도를 파악하는 것입니다. 데이터베이스 사용자에 따른 수행 업무와 필요한 데이터의 종류, 용도, 처리 형태, 흐름, 제약 조건 등을 수집합니다. 수집된 정보를 바탕으로 요구조건 명세를 작성합니다

개념적 설계는 정보의 구조를 얻기 위해 현실 세계의 무한성과 계속성을 이해하고 다른 사람과 통신하기 위해 현실 세계에 대한 인식을 추상적 개념으로 표현하는 과정입니다. 개념적 설계에서는 개념 스키마 모델링과 트랜잭션 모델링을 수행하고 요구조건 명세를 바탕으로 DBMS에 독립적인 E-R 다이어그램을 작성합니다. 

논리적 설계는 현실 세계에서 발생하는 자료를 컴퓨터가 이해하고 처리할 수 있는 물리적 저장 장치에 저장할 수 있도록 변환하기 위해 특정 DBMS가 지원하는 논리적 자료 구조로 변환시키는 과정입니다. 개념 세계의 데이터를 필드로 기술된 데이터 타입과 데이터 타입 간의 관계로 표현되는 논리적 구조의 데이터로 모델링합니다.
개념적 설계가 개념 스키마를 설계하는 단계라면 논리적 설계에서는 개념 스키마를 평가 및 정제하고 DBMS에 따라 서로 다른 논리적 스키마를 설계하는 단계입니다. 또 트랜잭션의 인터페이스를 설계하는 단계입니다

물리적 설계는 논리적 설계에서 논리적 구조로 표현한 데이터를 디스크 등의 물리적 저장장치에 저장할 수 있는 물리적 구조의 데이터로 변환하는 과정입니다. 다양한 데이터베이스 응용에 대해 처리 성능을 얻기 위해 데이터베이스 파일의 저장 구조와 액세스 경로를 결정합니다. 저장 레코드의 형식, 순서, 접근 경로 조회 집중이 발생하는 레코드 등의 정보를 사용하여 데이터가 컴퓨터에 저장되는 방법을 묘사합니다.

마지막으로 데이터베이스 구현은 논리적 설계와 물리적 설계에서 도출된 데이터베이스 스키마를 파일로 생성하는 과정입니다. 사용하려는 특정 DBMS의 데이터 정의어(DDL)를 사용하여 데이터베이스 스키마를 기술한 후 컴파일하여 빈 데이터베이스 파일을 생성합니다. 응용 프로그램을 위한 트랜잭션을 작성하고 데이터베이스 접근을 위한 응용 프로그램을 작성합니다.
