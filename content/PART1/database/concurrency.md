# 병행 제어 (Concurrency Control)

동시에 여러 개의 트랜잭션이 병행 수행될 때, 트랜잭션들이 데이터베이스의 일관성을 파괴하지 않도록 트랜잭션 간의 상호작용을 제어하는 활동입니다.

병행 제어의 종류입니다.

- 로킹 (Locking)
- 타임 스탬프 순서 (Timestamp Ordering)
- 최적 병행 수행
- 다중 버전 기법


# 로킹

로킹은 한 트랜잭션이 작업 중인 객체를 잠가서(Lock) 다른 트랜잭션이 접근할 수 없도록 만드는 기법입니다. 

예를 들어 트랜잭션 A가 테이블 T에서 작업을 수행중이라면 다른 트랜잭션들이 T에 접근할 수 없도록 T를 잠가 버립니다.

로킹 기법에서 한 번에 잠그는 객체의 크기를 로킹 단위라고 합니다. 데이터베이스, 테이블, 레코드, 필드 등이 로킹 단위가 될 수 있습니다. 

로킹 단위가 크면 관리하지 쉽지만 병행성 수준은 낮아집니다. 반대로 로킹 단위가 작으면 관리가 복잡해지고 오버헤드가 증가하지만 병행성 수준은 높아집니다.


# 타임스탬프 순서

트랜잭션이 시스템에 들어온 시간(타임스탬프)을 기준으로 실행 순서를 미리 정해주는 기법입니다. 더 먼저 들어온 트랜잭션이 우선 순위를 가집니다.
