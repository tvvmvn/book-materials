# 인덱스

인덱스(Index)는 데이터 레코드에 빠르게 접근하기 위해 사용되는 데이터입니다.


# 파티셔닝 (Partioning)

대용량의 테이블이나 인덱스를 작은 논리적 단위인 파티션으로 나누는 활동을 의미합니다.
파티셔닝을 통해 데이터 관리가 간편해지고 성능 저하를 방지할 수 있습니다.

어떻게 나누느냐에 따라 다음과 같이 파티셔닝을 분류할 수 있습니다.

- 범위 분할 (Range Partitioning)
- 해시 분할 (Hash Partitioning)
- 조합 분합 (Composite Partitioning)


범위 분할은 지정한 열의 값을 기준으로 테이블을 분할합니다. 예를 들어 일별, 월별, 분기별 분할이 있습니다. 

해시 분할은 해시함수를 적용한 결과 값에 따라 테이블을 분할합니다. 특정 파티션에 데이터가 집중되는 범위 분할의 단점을 보완한 것으로서 데이터를 고르게 분산할 때 유용합니다. 고객번호, 주민번호 등과 같이 데이터가 고른 열에 효과적입니다.
하지만 특정 데이터가 어디에 있는지 알 수 없다는 단점이 있습니다.

범위 분할한 파티션이 너무 커서 관리가 어려울 때 유용한 방법입니다. 범위 분할로 우선 분할할 다음 해시 함수를 적용해 다시 분할하는 방식입니다.


# 뷰

사용자에게 접근이 허용된 자료만을 제한적으로 보여주기 위해 하나 이상의 기본 테이블로부터 유도된 가상 테이블입니다. 


# 분산 데이터베이스

분산 데이터베이스는 논리적으로 하나의 시스템에 속하지만 물리적으로는 네트워크를 통해 연결된 여러 사이트에 분산된 데이터베이스를 의미합니다.


- 위치 투명성
- 중복 투명성
- 병행 투명성
- 장애 투명성


위치 투명성: 액세스하려는 데이터베이스의 실제 위치를 알 필요가 없습니다. 단지 데이터베이스의 논리적인 명칭만으로 액세스 할 수 있습니다.

중복 투명성: 동일 데이터가 여러 곳에 중복되어도 있더라도 사용자는 마치 하나의 데이터만 존재하는 것처럼 사용합니다. 시스템은 자동으로 여러 자료에 대한 작업을 수행합니다.

병행 투명성: 분산 데이터베이스와 관련된 다수의 트랜잭션들이 동시에 실행되더라도 그 트랜잭션의 결과는 영향을 받지 않습니다.

장애 투명성: 트랜잭션, DBMS, 네트워크, 컴퓨터 장애에도 불구하고 트랜잭션을 정확하게 처리합니다.
