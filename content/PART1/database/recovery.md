# 회복 (Recovery)

트랜잭션들을 수행하는 도중 장애가 발생하여 데이터베이스가 손상되었을 때 손상되기 이전의 정상 상태로 복구하는 작업입니다

회복 기법의 종류

- 연기 갱신 (Deferred Update)
- 즉각 갱신 (Immediate Update)
- 그림자 페이징 (Shadow Paging)
- 검사적 기법 (Check Point)


# 회복 연산

데이터베이스가 회복 과정에서 내부적으로 사용하는 연산입니다.

- REDO
- UNDO

REDO: 데이터베이스가 비정상적으로 종료되었을 때, 저장된 로그를 분석하여 트랜잭션의 시작(start)과 완료(commit)에 대한 기록이 있는 트랜잭션들의 작업을 재작업합니다. 즉 로그를 이용하여 이전 값을 이후 값으로 변경하는 연산입니다.

UNDO: 데이터베이스가 비정상적으로 종료되었을 때, 저장된 로그를 분석하여 트랜잭션의 시작(start)에 대한 기록은 있지만 완료(commit)에 대한 기록은 없는 트랜잭션들이 작업한 변경 내용들을 모두 취소합니다. 즉 로그를 이용하여 이후 값을 이전 값으로 변경하는 연산입니다.


# 연기 갱신의 회복 절차

연기 갱신은 트랜잭션의 모든 연산들이 성공적으로 완료되면 DB에 반영하는 기법입니다.
다음은 연기 갱신의 경우 회복 과정입니다.

REDO를 수행하지 않는 경우

1. 트랜잭션이 완료(Commit)되기 전에 장애가 발생했습니다.
2. DB에는 아무런 변화가 없습니다.
3. 사용자는 다시 트랜잭션을 시도해야 합니다.

REDO를 수행하는 경우

1. 트랜잭션이 완료(Commit)된 상태에서 시스템 장애가 발생했습니다.
2. 하지만 DB에는 아무런 변화가 없습니다.
3. 시스템이 복구되면 사용자가 시도했던 트랜잭션을 다시 처리(REDO)합니다.


# 즉각 갱신의 회복 절차

즉각 갱신은 트랜잭션의 개별 연산들이 성공하는 데로 DB에 반영하는 갱신하는 기법입니다. 다음은 즉각 갱신인 경우의 회복 과정입니다. UNDO 또는 REDO를 수행합니다.

UNDO를 수행하는 경우

1. 트랜잭션의 개별 연산들이 성공하는 데로 DB에 반영됬습니다. 
2. 트랜잭션이 완료(Commit)되기 전에 시스템 장애가 발생했습니다.
3. 트랜잭션의 일부만 DB에 반영된 상태가 됬습니다.
4. 시스템이 복구되면 DB에서 일부 수정된 내용을 취소(UNDO)합니다. 
사용자가 다시 시도해야 합니다.

REDO를 수행하는 경우

1. 트랜잭션의 개별 연산들이 성공하는 데로 DB에 반영됬습니다. 
2. 트랜잭션이 완료(Commit)된 상태에서 시스템 장애가 발생했습니다.
3. 트랜잭션의 일부만 DB에 반영된 상태가 됬습니다.
4. 시스템이 복구되면 사용자가 시도했던 트랜잭션을 마저 처리(REDO)합니다.
