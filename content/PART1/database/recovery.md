# 회복

트랜잭션들을 수행하는 도중 장애가 발생하여 데이터베이스가 손상되었을 때 손상되기 이전의 정상 상태로 북구하는 작업입니다

회복 기법의 종류

- 연기 갱신
- 즉각 갱신
- 그림자 페이지 대체
- 검사적 기법


## REDO/UNDO

데이터베이스가 비정상적으로 종료되었을 때, 저장된 로그를 분석하여

REDO: 트랜잭션의 시작(start)과 완료(commit)에 대한 기록이 있는 트랜잭션들의 작업을 재작업합니다. 즉 로그를 이용하여 해당 데이터 항목에 대해서 이전 값을 이후 값으로 변경하는 연산입니다.

UNDO: 트랜잭션의 시작(start)에 대한 기록은 있지만 완료(commit)에 대한 기록은 없는 트랜잭션들이 작업한 변경 내용들을 모두 취소합니다. 즉 로그를 이용하여 해당 데이터 항목에 대해서 이후 값을 이전 값으로 변경하는 연삽입니다.


## 

연기 갱신:

트랜잭션이 완료될 때까지 데이터베이스에 대한 실질적인 갱신을 연기하는 방법입니다. 트랜잭션이 수행되는 동안 갱신된 내용은 일단 로그에 보관합니다. 트랜잭션의 부분 완료 시점에 로그에 보관한 갱신 내용을 실제 데이터베이스에 기록합니다. REDO 작업만 가능합니다.

즉각 갱신:

트랜잭션이 데이터를 갱신하면 부분완료 이전에 즉시 실제 데이터베이스에 반영하는 방법입니다. 장애가 발생하여 회복 작업을 할 경우를 대비하여 갱신된 내용들은 로그에 보관합니다. REDO, UNDO 작업 모두 가능합니다.
