# 관계형 데이터 모델

관계형 데이터 모델(Relational Data Model)은 1970년 E.F. Codd 박사에 의해 제안된 모델로, 데이터를 2차원 표(Table) 형태로 표현하고 관리하는 방식입니다. 현재 전 세계적으로 가장 널리 사용되는 데이터베이스 모델의 표준입니다.


# 관계형 모델의 구조

<그림 - 릴레이션의 구조>

- 릴레이션 스키마 (Relation Schema)
- 릴레이션 인스턴스 (Relation Instance)
- 튜플 (Tuple)
- 카디널리티 (Cardinality) / 기수
- 속성 (Attribute)
- 디그리 (Degree) / 차수
- 도메인 (Domain)


릴레이션 스키마는 릴레이션의 구조를 나타내고 릴레이션 인스턴스는 릴레이션의 값들을 나타냅니다.

튜플은 릴레이션을 구성하는 각각의 행을 의미합니다. 튜플은 속성의 모임으로 구성됩니다. 파일 구조에서 레코드와 같은 의미입니다.

카디널리티 또는 기수는 한 릴레이션에서 튜플의 수를 의미합니다.

속성은 데이터베이스를 구성하는 가장 작은 논리적 단위로 객체가 가진 각각의 특성을 나타냅니다.

디그리 또는 차수는 한 릴레이션을 이루는 속성의 수는 의미합니다.

도메인은 하나의 속성이 취할 수 있는 같은 타입의 원자값의 집합입니다. 예를 들면 '성별' 속성의 도메인은 {남, 여} 입니다.


# 키 (Key)

키는 릴레이션에서 튜플을 고유하게 식별하기 위한 속성의 부분 집합입니다. 예를 들어 <학생> 테이블에서 주민번호(키)로 특정 학생(튜플)을 찾을 수 있습니다.

유일성과 최소성 원칙에 기반해 다음과 같이 구분됩니다. 유일성과 최소성을 모두 만족하면 기본키로 사용가능합니다.

유일성: 튜플을 고유하게 식별할 수 있어야 한다.
최소성: 최소의 속성으로 구성되야 한다.(키를 구성하는 속성들 중에서 하나를 제거하면 튜플을 유일하게 식별할 수 없음)

- 슈퍼키 (Super Key)
- 후보키 (Candidate Key)
- 기본키 (Primary Key)
- 대체키 (Altenate Key)


슈퍼키는 유일성은 만족하지만 최소성을 만족하지 못하므로 기본키로 사용할 수 없습니다. 

예) <학생> 테이블에서 (이름, 주민번호, 나이), (이름, 핸드폰 번호)


후보키는 유일성과 최소성을 모두 만족하므로 기본키로 사용할 수 있는 키입니다.

예) <학생> 테이블에서 (주민번호), (핸드폰 번호)


후보키가 두 개 이상일 때 후보키 중에서 특별히 선정된 키를 기본키라고 하고 기본키를 제외한 나머지 키들을 대체키(보조키)라고 합니다.

예) <학생> 테이블에서 기본키가 (주민번호)로 선정됬다면 (핸드폰 번호)가 대체키입니다.

# 무결성 (Integrity)

무결성은 데이터베이스에 저장된 데이터와 그것이 표현하는 현실 세계의 실제값이 일치하는 정확성을 의미합니다. 

주요 무결성 종류는 다음과 같습니다.

- 개체 무결성
- 참조 무결성
- 도메인 무결성
- 사용자 정의 무결성


개체 무결성: 기본키 값은 NULL(없음)이거나 중복될 수 없습니다.
예) <학생> 테이블에서 '학번'이 기본키인 경우 학번이 NULL이거나 중복되면 안됩니다.

참조 무결성: 외래키 값은 참조하는 릴레이션 튜플의 기본키 값과 일치해야 합니다. 만약 참조하는 튜플이 없다면 외래키 값은 NULL이어야 합니다. (존재하지 않는 튜플의 기본키 값을 가질 수 없습니다)

도메인 무결성: 속성의 도메인을 정의한 경우 속성 값은 정의된 도메인에 속해야 합니다.
