# 스키마 (Schema)

스키마는 우리 말로 개요(Schema)를 의미하는 단어로 데이터베이스를 다루는 과정에서 광범위하게 사용되는 용어입니다.

여러가지 기준에 따라 분류할 수 있습니다.
<!-- '구조'처럼 다양하게 활용됨 -->

- 일반적인 분류 (시험용)
- 개발 과정에서 분류 (실무용)


#  일반적인 분류

- 외부 스키마 (External Schema)
- 개념 스키마 (Conceptual Schema)
- 내부 스키마 (Internam Schema)

외부 스키마는 사용자나 응용 프로그래머가 각 개인의 입장에서 필요로 하는 데이터베이스의 논리적 구조를 정의한 스키마입니다. 

개념 스키마는 데이터베이스의 전체적인 논리적 구조를 나타냅니다. 모든 응용 프로그램이나 사용자들이 필요로 하는 데이터를 종합한 조직 전체의 데이터베이스로서 하나만 존재합니다. 

내부 스키마는 물리적 저장장치의 입장에서 본 데이터베이스의 구조입니다. 실제로 저장될 레코드의 형식, 저장 데이터 항목의 표현 방법, 내부 레코드의 물리적 순서 등을 나타냅니다.


# 실무적 분류

데이터베이스 각 설계 단계에서 다루는 실무적인 스키마라고 할 수 있습니다.

- 개념 스키마 (Conceptual Schema)
- 논리 스키마 (Logical Schema)
- 물리 스키마 (Physical Schema)

개념 스키마는 데이터베이스의 추상적이고 개념적인 구조를 의미하며 보통 ER 다이어그램으로 표현합니다.


논리 스키마는 테이블에 대한 자세한 정보와 테이블 간의 관계를 표현합니다.

물리 스키마는 데이터베이스의 물리적 구조를 의미합니다. 물리적 설계 단계에서 물리 스키마를 다루고 관리합니다.

물리 스키마가 다루는 항목들

- 인덱스: 검색 속도와 관련됨
- 파티션 (Partion): 데이터를 나누는 단위입니다.
- 클러스터: 자주 같이 쓰이는 데이터들을 물리적으로 가까운 곳에 모은 것
