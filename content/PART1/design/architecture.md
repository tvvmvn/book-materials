# S/W 아키텍처 (S/W Architecture)

소프트웨어를 구성하는 요소들 간의 관계를 표현하는 시스템의 구조 또는 구조체입니다.
소프트웨어 아키텍처 설계의 4가지 기본 원리는 다음과 같습니다

- 모듈화 (Modularity)
- 추상화 (Abstraction)
- 단계적 분해 (Stepwise Refinement)
- 정보 은닉 (Information Hiding)

모듈화는 소프트웨어의 성능 향상, 시스템의 수정 및 재사용, 유지관리등이 용이하도록 시스템을 기능 단위인 모듈로 나누는 것을 의미합니다. 모듈의 응집도를 최대화하고  모듈 간 결합도를 최소화하는 것이 모듈화의 목표입니다.

추상화는 문제의 전체적이고 포괄적인 개념을 설계하고 차례로 구체화시켜 나가는 것을 의미합니다. 추상화는 크고 복잡한 아키텍처의 설계도 가능하게 만듭니다.

단계적 분해는 Niklaus Wirth에 의해 제안된 하향식(Top-Down) 설계 전략으로 문제를 상위 개념부터 하위 개념으로 구체화시키는 방법입니다. 예를 들어 소프트웨어의 포괄적인 기능부터 시작해서 알고리즘과 자료구조 등 상세한 내역은 가능한 한 뒤로 미루어 진행합니다.

정보 은닉은 모듈의 내부 정보를 숨기고 승인된 인터페이스를 통해서만 모듈 내부에 접근할 수 있도록 합니다. 이 과정을 통해 모듈 내부의 정보를 보호할 수 있습니다.


# 아키텍처 설계 과정

1. 목표 설정: 요구 사항을 분석한 후 시스템의 설계 목표를 설정합니다.

2. 시스템 타입 결정: 시스템과 서브 시스템의 타입을 결정하고 아키텍처 패턴을 선택합니다.

3. 아키텍처 패턴 적용: 선택한 아키텍처 패턴을 적용하고 아키텍처를 설계합니다.

4. 서브 시스템 구체화: 서브 시스템의 기능과 서브 시스템 간의 상호작용을 위한 
인터페이스를 정의합니다.

5. 검토: 설계한 아키텍처가 설계 목표와 설계의 기본 원리를 만족하는지 검토합니다.


# 아키텍처 패턴 (Architecture Pattern)

S/W 아키텍처를 설계할 때 참조할 수 있는 전형적인 해결 방식 또는 예제를 의미합니다.

주요 아키텍처 패턴들

- 계층형 패턴 (Layered Pattern)
- 클라이언트-서버 패턴 (Client-Server Pattern)
- 파이프-필터 패턴 (Pipe-Filter Pattern)
- MVC 패턴 (MVC Pattern)

계층형 패턴은 고전적인 패턴으로 시스템이 여러 개의 계층(Layer)으로 구성됩니다. 
서로 마주보는 계층 간에서만 상호작용이 일어나는 구조로 하위 계층은 상위 계층에 대한 서비스 제공자가 되고 상위 계층은 하위 계층의 클라이언트가 됩니다. 

예) OSI 모델, 서버 프레임워크

*그림 - 레이어 패턴*


클라이언트 서버 패턴은 하나의 서버와 다수의 클라이언트로 구성되는 패턴입니다. 클라이언트가 서버에 요청을 전송하면 서버가 클라이언트에게 응답을 제공하는 구조입니다.

예) Web App, API

*그림 - 클라이언트 - 서버 패턴*


파이프-필터 패턴은 데이터 스트림(Stream)을 처리하기 위한 아키텍처 패턴으로 데이터를 처리하는 필터와 필터 간의 전송을 담당하는 파이프로 이루어져 있습니다. 
원본 데이터는 여러 필터를 거치게 되는데 각 필터는 자신이 맡은 업무를 처리하고 최종 결과물이 산출되는 구조입니다. 데이터 변환, 버퍼링, 동기화 작업 등에 주로 사용됩니다. 

예) UNIX의 쉘(Shell)

*그림 - 파이프-필터 패턴*


MVC 패턴은 UI를 구축할 때 사용되는 패턴으로 모델(Model), 뷰(View), 컨트롤러(Controller)의 3가지 요소로 구성됩니다. 모델은 UI에 나타날 데이터를 담당하고 뷰는 사용자에게 보여질 화면(레이아웃, 디자인 등) 담당합니다. 컨트롤러는 모델과 뷰를 제어하고 사용자에게 결과물을 제공하는 역할을 합니다

예) UI 

*그림 - MVC 패턴*


기타 패턴들

- 마스터-슬레이브 (Master-Slave)
- 브로커 (Broker)
- 피어투피어 (Peer-To-Peer)
- 이벤트-버스 (Event-Bus)
- 블랙보드 (Blackboard)
- 인터프리터 (Interpreter)

마스터-슬레이브 패턴은 마스터가 여러 슬레이브 컴포넌트들에게 작업을 할당하고 결과물을 돌려받는 방식의 패턴입니다.

예) 장애 허용 시스템, 병렬 컴퓨팅 

브로커 패턴은 많은 사용자들의 요청과 여러 서비스 제공자들이 존재하는 환경에서 중개 역할을 하는 브로커를 두는 패턴입니다. 브로커는 사용자의 요청에 적합한 서비스 제공자를 연결함으로써 복잡한 환경에서 안정적인 통신을 가능하게 합니다

예) 분산 시스템

피어-투-피어 패턴은 피어(Peer)라 불리는 하나의 컴포넌트가 클라이언트가 될 수도 있고 서버가 될 수도 있는 패턴입니다. 패턴의 적용 사례로 파일 공유 네트워크가 있습니다. 예를 들어 영화 공유 네트워크에서 사용자는 다른 사용자가 가진 영화를 다운받는 클라이언트가 될 수도 있고 내가 가진 영화를 다른 사람들에게 공유하는 서버가 될 수도 있습니다.


이벤트-버스 패턴은 이벤트 기반의 시스템에서 볼 수 있는 패턴으로 이벤트 소스(Event Source), 이벤트 리스너(Event Listener), 그리고 중간에 이벤트 버스(Event Bus)로 구성됩니다. 이벤트 소스가 새로운 이벤트를 이벤트 버스(이벤트들이 머무는 곳)에 발행하면 해당 이벤트를 구독한 리스너들이 정해진 작업을 수행하는 패턴입니다.

예) 알림 서비스

블랙보드 패턴은 해결책이 명확하지 않거나 여러 분야의 지식이 필요한 복잡한 문제를 해결할 때 적합한 패턴입니다. 이 패턴은 블랙보드(공유 데이터 저장소), 지식 소스(분야별 데이터), 제어 컴포넌트로 구성이 되며 각 컴포넌트의 역할과 상호 작용을 다음과 같이 비유할 수 있습니다 - 블랙보드(칠판) 앞에서 제어 컴포넌트의 입회 하에 여러 명의 전문가(지식 소스)가 문제 해결을 위해 자신이 가진 지식을 칠판에 적고 회의하고 해결책을 찾아가는 과정.

예) 음성 인식, 차량 식별, 신호 해석 

인터프리터 패턴은 프로그램 코드의 각 라인을 수행하는 방법을 지정하고 기호마다 클래스를 갖도록 구성된 패턴입니다. 

인터프리터 패턴은 프로그래밍 언어나 명령어 등 새로운 문법을 창조하려고 할 때 문법을 이해하고 전달하는 해석기(Interpreter)를 만드는 데 사용되는 패턴입니다. 예를 들어 사용자 친화적인 SQL 쿼리어를 C 언어 기반으로 개발된 데이터베이스가 이해할 수 있도록 SQL 파서(인터프리터)가 중간에서 번역시키는 과정을 생각할 수 있습니다.

예) 컴파일러/인터프리터, 정규식, SQL 파서, 번역기


# S/W 아키텍처의 품질 평가 기준

다음은 소프트웨어 아키텍처가 이해 관계자들이 요구하는 수준의 품질로 설계되었는지 확인하기 위한 평가 기준입니다.

- 아키텍처 측면 (Architecture)
- 시스템 측면 (System)
- 비즈니스 측면 (Business)

아키텍처 측면은 아키텍처의 완성도 등 소프트웨어의 아키텍처 그 자체에 대한 평가 기준입니다. 평가 기준으로 개념적 무결성, 정확성, 완결성, 구축 가능성, 변경성, 시험성 등이 있습니다.

시스템 측면은 아키텍처가 실제로 적용된 시스템을 대상으로 평가하는 기준입니다. 평가 기준으로 성능, 보안, 가용성, 기능성, 사용성, 변경 용이성, 확장성 등이 있습니다

비즈니스 측면은 아키텍처가 적용된 소프트웨어가 실제로 매력적인 상품인지 또는 상품성이 있는지 평가하는 기준입니다. 평가 기준으로 시장 적시성, 비용과 혜택, 예상 수명, 목표 시장, 공개 일정 등이 있습니다.
