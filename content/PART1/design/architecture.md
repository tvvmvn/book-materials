# S/W 아키텍처 (S/W Architecture)

소프트웨어를 구성하는 요소들 간의 관계를 표현하는 시스템의 구조 또는 구조체입니다.
소프트웨어 아키텍처 설계의 4가지 기본 원리는 다음과 같습니다

- 모듈화 (Modularity)
- 추상화 (Abstraction)
- 단계적 분해 (Stepwise Refinement)
- 정보 은닉 (Information Hiding)

모듈화는 소프트웨어의 성능 향상, 시스템의 수정 및 재사용, 유지관리등이 용이하도록 시스템의 기능들을 모듈 단위로 나누는 것을 의미합니다. 모듈화는 모듈 간 결합도의 최소화와 모듈 내 요소들의 응집도를 최대화하는 것이 목표입니다.

추상화는 문제의 전체적이고 포괄적인 개념을 설계하고 차례로 구체화시켜 나가는 것을 의미합니다. 

단계적 분해는 문제를 상위의 중요 개념부터 하위의 개념으로 구체화시키는 방법입니다. Niklaus Wirth에 의해 제안된 하향식 설계 전략입니다. 소프트웨어의 포괄적인 기능에서부터 시작해서 점차적으로 구체화하고 알고리즘과 자료구조 등 상세한 내역은 가능한 한 뒤로 미루어 진행합니다.

정보 은닉은 한 모듈 내부에 포함된 자료와 절차들의 정보가 감추어져 다른 모듈이 접근하거나 변경하지 못하도록 하는 기법입니다.


# 아키텍처 설계 과정

1. 설계 목표 설정: 요구사항을 분석하고 전체 시스템의 설계 목표를 설정합니다.

2. 시스템 타입 결정: 시스템과 서브시스템의 타입을 결정하고 아키텍처 패턴을 선택합니다.

3. 아키텍처 패턴 적용: 시스템의 표준 아키텍처를 설계합니다.

4. 서브 시스템 구체화: 서브 시스템의 기능과 서브 시스템 간의 상호작용을 위한 
동작과 인터페이스를 정의합니다.

5. 검토: 설계 목표, 요구 사항, 설계의 기본 원리 등을 만족하는지 아키텍처를 검토합니다.


# 아키텍처 패턴 (Architecture Pattern)

S/W 아키텍처를 설계할 때 참조할 수 있는 전형적인 해결 방식 또는 예제를 의미합니다.

주요 아키텍처 패턴들

- 계층형 패턴 (Layered Pattern)
- 클라이언트-서버 패턴 (Client-Server Pattern)
- 파이프-필터 패턴 (Pipe-Filter Pattern)
- MVC 패턴 (MVC Pattern)

계층형 패턴은 시스템을 계층으로 구분하고 구성하는 고전적인 패턴입니다. 하위 계층은 상위 계층에 대한 서비스 제공자가 되고 상위 계층은 하위 계층의 클라이언트가 됩니다. 서로 마주보는 두 개의 계층 사이에서만 상호작용이 일어납니다. 대표적으로 OSI 모델이 있습니다.

*그림 - 레이어 패턴*


클라이언트 서버 패턴은 하나의 서버와 다수의 클라이언트로 구성되는 패턴입니다. 사용자가 클라이언트를 통해 서버에 요청을 전송하면 클라이언트가 서버로부터 응답을 받아 사용자에게 제공하는 방식입니다.

*그림 - 클라이언트 - 서버 패턴*


파이프-필터 패턴은 데이터 스트림(Stream)의 각 단계를 필터로 캡슐화하고 파이프를 통해 전송하는 패턴입니다. 각 필터가 데이터를 처리한 후 그 결과물을 파이프를 통해 다음 필터로 넘겨주는 과정을 반복합니다. 데이터 변환, 버퍼링, 동기화 작업 등에 주로 사용됩니다. 대표적으로 UNIX의 쉘(Shell)이 있습니다.

*그림 - 파이프-필터 패턴*


MVC 패턴은 서브 시스템을 모델(Model), 뷰(View), 컨트롤러(Controller)로 구조화하는 패턴입니다. 컨트롤러가 사용자의 요청을 받으면 핵심 기능과 데이터를 보관하는 모델을 이용하여 뷰에 정보를 출력하는 구조입니다. 

*그림 - MVC 패턴*


기타 패턴들

- 마스터-슬레이브 (Master-Slave)
- 브로커 (Broker)
- 피어투피어 (Peer-To-Peer)
- 이벤트-버스 (Event-Bus)
- 블랙보드 (Blackboard)
- 인터프리터 (Interpreter)

마스터-슬레이브 패턴은 슬레이브 컴포넌트에서 처리된 결과물을 마스터가 다시 돌려받는 방식으로 작업을 수행하는 패턴입니다. 장애 허용 시스템, 병렬 컴퓨팅 시스템 등이 있습니다.

브로커 패턴은 사용자가 원하는 서비스를 브로커 컴포넌트에게 전달하면 브로커 컴포넌트가 적합한 컴포넌트를 사용자와 연결해주는 패턴입니다. 분산 환경 시스템 등이 있습니다. 

피어-투-피어 패턴은 피어라 불리는 하나의 컴포넌트가 클라이언트가 될 수도 있고 서버가 될 수도 있는 패턴입니다. 파일 공유 네트워크가 있습니다.

이벤트-버스 패턴은 소스가 특정 채널에 이벤트 메시지를 발행하면 해당 채널을 구독한 리스너들이 메시지를 받아 이벤트를 처리하는 패턴입니다. 알림 서비스가 있습니다.

블랙보드 패턴은 모든 컴포넌트들이 공유 데이터 저장소와 블랙보드 컴포넌트에 접근이 가능한 패턴입니다. 음성 인식, 차량 식별, 신호 해석 등이 있습니다.

인터프리터 패턴은 프로그램 코드의 각 라인을 수행하는 방법을 지정하고 기호마다 클래스를 갖도록 구성된 패턴입니다. 번역기, 컴파일러, 인터프리터 등이 있습니다.


# S/W 아키텍처의 품질 속성

소프트웨어 아키텍처가 이해 관계자들이 요구하는 수준의 품질로 설계되었는지 확인하기 위한 평가 기준으로 다음의 3가지 측면으로 구성됩니다

- 아키텍처 측면: 개념적 무결성, 정확성, 완결성, 구축 가능성, 변경성, 시험성 등
- 시스템 측면 : 성능, 보안, 가용성, 기능성, 사용성, 변경 용이성, 확장성 등
- 비즈니스 측면: 시장 적시성, 비용과 혜택, 예상 수명, 목표 시장, 공개 일정 등
