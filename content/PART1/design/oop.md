# 객체지향

소프트웨어의 각 요소들을 객체로 만들고 객체들을 조립해서 소프트웨어를 개발하는 기법입니다.

객체 지향의 3가지 구성요소

- 객체
- 클래스
- 메시지

객체는 데이터와 이 데이터를 처리하기 위한 함수로 구성되어 있습니다. 

클래스는 공통된 속성과 연산을 갖는 객체의 집합입니다. 클래스에 속한 각각의 객체를 인스턴스라고 부릅니다.

메시지는 객체들 간의 상호작용에 사용되는 수단으로 객체의 동작이나 연산을 일으키는 외부의 요구사항입니다. 메시지를 받은 객체는 대응하는 연산을 수행하고 예상된 결과를 반환합니다


## 객체 지향의 특징

- 상속
- 추상화
- 다형성
- 캡슐화

상속은 상위 클래스의 모든 속성과 연산을 하위 클래스가 물려받는 것을 의미합니다. 하위 클래스는 상속받은 속성과 연산 외에도 새로운 속성과 연산을 추가할 수 있습니다.

추상화는 상위 클래스에서는 객체의 큰 틀만 정의하고 하위 클래스에서 구체적으로 구현하는 것을 의미합니다.

다형성은 하나의 메시지에 대해 각각의 객체가 가지고 있는 고유한 방법으로 응답할 수 있는 능력을 말합니다. 예를들어 객체들은 동일한 메소드명을 사용하여 같은 의미의 응답을 할 수 있습니다

캡슐화는 외부에서의 접근을 제한하기 위해 인터페이스를 제외한 세부 내용을 은닉하는 것을 의미합니다. 캡슐화된 객체는 외부 모듈의 변경으로 인한 파급효과가 적습니다.
객체들 간에 메시지를 주고 받을 때 상대 객체의 세부 내용은 알 필요가 없으므로 인터페이스가 단순해지고 객체 간의 결합도가 낮아집니다.


## 연관성

두 개 이상의 객체들이 상호 참조하는 관계를 의미합니다

- 연관화 (Association)
- 분류화 (Classification)
- 집단화 (Aggregation)
- 일반화 (Generalization)
- 특수화/상세화 (Specialization)

연관화는 2개 이상의 객체가 서로 관련되어 있음을 의미합니다. 

분류화는 동일한 형의 특성을 갖는 객체들을 모아서 구성하는 것을 의미합니다

집단화는 관련있는 객체들을 묶어 하나의 상위 객체를 구성하는 것을 의미합니다

일반화는 공통적인 성질들로 추상화한 상위 객체를 구성하는 것을 의미합니다

특수화/상세화는 상위 객체를 구체화하여 하위 객체를 구성하는 것을 의미합니다


## 객체지향 설계 원칙

- SRP
- OCP
- LSP
- ISP
- DIP

- 단일 책임 원칙: 객체는 단 하나의 책임만 가져야 한다

- 개방-폐쇄 원칙: 확장에는 열려있고 수정에는 닫혀있어야 한다

- 리스코프 치환 원칙: 자식 클래스는 최소한 부모 클래스의 기능을 수행해야 한다

- 인터페이스 분리 원칙: 자신이 사용하지 않는 인터페이스에 영향을 받아서는 안된다

- 의존 역전 원칙: 추상성이 높은 클래스와 의존 관계를 맺어야 한다


## 객체 지향 분석

사용자의 요구사항과 관련된 객체, 속성, 연산, 관계 등을 정의하고 모델링하는 작업입니다. 클래스를 식별하는 것이 OOA의 주요 목적입니다

객체 지향 분석의 주요 방법론들

- Rumbaugh
- Booch
- Jacobson
- Coad & Yourdon
- Wirfs-Brock


## Rumbaugh

모든 소프트웨어 구성 요소를 그래픽을 활용하여 모델링하는 기법으로 OMT(객체 모델링 기법)이라고도 합니다. 분석 활동으로 다음의 3단계가 있습니다

- 객체 모델링
- 동적 모델링
- 기능 모델링

객체 모델링은 정보 모델링이라고도 하며 시스템에서 요구되는 객체를 찾아 속성과 연산을 식별하고 객체들 간의 관계를 규정하는 활동입니다. UML 객체 다이어그램을 활용합니다

동적 모델링은 시간의 흐름에 따른 객체들 간의 제어 흐름, 상호작용, 동작 순서 등의 동적인 행위를 표현하는 활동입니다. UML 상태 다이어그램을 활용합니다

기능 모델링은 다수의 프로세스들 간의 자료 흐름을 중심으로 처리 과정을 표현하는 활동입니다. 자료 흐름도(DFD)를 활용합니다
