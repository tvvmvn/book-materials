# Database

데이터베이스는 여러 사람에 의해 공동으로 사용될 데이터를 중복을 배제하여 통합하고, 쉽게 접근하여 처리할 수 있도록 저장장치에 저장하여 항상 사용할 수 있도록 하는 운영 데이터이다.


# DBMS

데이터베이스 관리 시스템(Database Management System)의 약자로 사용자의 요구에 따라 정보를 생성해주고 데이터베이스를 관리해주는 소프트웨어입니다. 많은 문맥에서 데이터베이스 그 자체를 의미하기도 합니다.

예) Postgresql, MySQL, Oracle, MongoDB 

DBMS는 다음의 3가지 필수 기능을 가지고 있습니다.

- 정의 기능 (Definition)
- 조작 기능 (Manipulation)
- 제어 기능 (Control)


정의 기능은 데이터의 형과 구조에 대한 정의, 이용 방식, 제약 조건 등을 명시하는 기능입니다. 

조작 기능은 데이터 검색, 갱신, 삽입, 삭제 등을 위해 인터페이스 수단을 제공하는 기능입니다. 

제어 기능은 데이터의 무결성, 보안, 권한 검사, 병행 제어를 제공하는 기능입니다.


# 시스템 카달로그 (System Catalogue)

시스템 그 자체에 관련이 있는 다양한 객체에 관한 정보를 포함하는 시스템 데이터베이스입니다. 시스템 카탈로그 내의 각 테이블은 사용자를 포함하여 DBMS에서 지원하는 모든 데이터 객체에 대한 정의나 명세에 관한 정보를 유지관리하는 시스템 테이블입니다. 

카탈로그가 생성되면 데이터 사전에 저장되기 때문에 좁은 의미로는 카탈로그를 데이터 사전이라고도 합니다.


# 데이터베이스 설계

데이터베이스를 설계하는 과정은 5단계가 있습니다

1. 요구사항 분석 (Requirements Analysis)
2. 개념적 설계 (Conceptual Design)
3. 논리적 설계 (Logical Design)
4. 물리적 설계 (Physical Design)
5. 구현 (Implementation)


# 요구사항 분석

요구조건 분석은 데이터베이스를 사용할 사람들로부터 필요한 용도를 파악하는 것입니다. 

데이터베이스 사용자에 따른 수행 업무와 필요한 데이터의 종류, 용도, 처리 형태, 흐름, 제약 조건 등을 수집합니다. 수집된 정보를 바탕으로 요구조건 명세를 작성합니다


# 개념적 설계

개념적 설계는 정보의 구조를 얻기 위해 현실 세계의 무한성과 계속성을 이해하고 다른 사람과 통신하기 위해 현실 세계에 대한 인식을 추상적 개념으로 표현하는 과정입니다.

개념적 설계에서는 개념 스키마 모델링과 트랜잭션 모델링을 수행하고 요구 사항 명세를 바탕으로 DBMS에 독립적인 E-R 다이어그램을 작성합니다. 


# 논리적 설계

ER 다이어그램을 바탕으로 DBMS(Postresql 등)에 종속적인 논리 스키마를 설계하는 단계입니다.


# 물리적 설계

물리적 설계는 성능을 위해 데이터베이스의 물리적 구조를 최적화하는 단계입니다.
다음은 물리적 설계 단계에서의 주요 활동들입니다.

- 인덱스 설계: 검색 속도를 높이기 위해 인덱스를 설계합니다.
- 파티셔닝 (Partioning): 대규모의 레코드로 구성된 테이블은 무거워서 연산 성능이 떨어질 수 있으므로 나누어 저장합니다.
- 클러스터링: 자주 같이 쓰이는 데이터들을 물리적으로 가까운 곳에 모읍니다.


# 구현 단계

구현 단계는 DBMS의 데이터 정의어(DDL)를 사용하여 실제 데이터베이스를 생성합니다.
