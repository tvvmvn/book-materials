# 데이터 모델

현실 세계의 정보들을 컴퓨터에 표현하기 위해 정보들을 추상적이고 체계적으로 표현한 모형입니다. 데이터베이스 설계의 기본이 되는 모델입니다.

예) ER 모델, 관계형 데이터 모델, 계층 모델 등


# 데이터 모델의 구성

데이터 모델은 다음의 3가지 요소를 가지고 있습니다.

- 데이터 구조 (Structure)
- 데이터 연산 (Operation)
- 제약 조건 (Constraint)


데이터 구조는 데이터를 이루는 각각의 개체와 개체 간의 관계를 다룹니다.
예) 개체와 속성, 관계

데이터 연산은 사용자가 원하는 결과를 얻기 위해 데이터를 처리하는 방법을 다룹니다.
예) 조회, 삽입/삭제 등

제약 조건은 데이터의 무결성을 유지하기 위한 규칙을 다룹니다.
예) 개체 무결성, 도메인 무결성 등


데이터 모델의 개념을 자판기에 비유해봅시다. 여러분은 이제 자판기 관리자입니다.

데이터 구조: 자판기에 들어가는 다양한 종류의 음료(개체)들을 다룹니다. 각 음료는 다양한 속성을 가지고 있습니다. 가격, 맛, 인기도 등 말이죠.

데이터 연산: 자판기를 사용하는 방법을 다룹니다. 지폐나 동전을 넣어야 합니다. 100원 이상의 동전만 넣어야 하죠. 원하는 음료가 전시된 버튼을 눌러야 합니다. 음료가 나오면 아래에 있는 출구를 통해 꺼내야 합니다.

제약 조건: 음료가 비어서는 안됩니다. 음료의 유통기한도 지켜져야 합니다. 또 외국 지폐를 받아서도 안됩니다. 이 밖에도 많은 제약 조건이 있을 것입니다.


# 개체 간 관계

개체 간의 관계에서는 다음의 3가지 형태가 나타날 수 있습니다.

- 일대일(1:1)
- 일대다(1:N)
- 다대다(N:M)

<그림 - 집합을 통해 표현한 개체 관계>


개체 집합 A와 B가 있을 때

일대일: A의 각 원소가 B의 원소 한 개와 대응합니다.

일대다: A의 각 원소가 B의 여러 원소와 대응합니다. 이미 대응된 B의 원소는 다른 A의 원소에 대응될 수 없습니다.

다대다: A의 각 원소와 B의 각 원소가 서로 아무렇게나 대응합니다.
