# 스키마 (Schema)

스키마는 데이터베이스에서 매우 광범위하게 사용되는 용어입니다.
여러가지 기준에 따라 분류할 수 있습니다.


#  일반적인 분류

- 외부 스키마 (External Schema)
- 개념 스키마 (Conceptual Schema)
- 내부 스키마 (Internam Schema)


외부 스키마는 사용자나 응용 프로그래머가 각 개인의 입장에서 필요로 하는 데이터베이스의 논리적 구조를 정의한 스키마입니다. 

개념 스키마는 데이터베이스의 전체적인 논리적 구조를 나타냅니다. 모든 응용 프로그램이나 사용자들이 필요로 하는 데이터를 종합한 조직 전체의 데이터베이스로서 하나만 존재합니다. 

내부 스키마는 물리적 저장장치의 입장에서 본 데이터베이스의 구조입니다. 실제로 저장될 레코드의 형식, 저장 데이터 항목의 표현 방법, 내부 레코드의 물리적 순서 등을 나타냅니다.


# 실무적 분류

데이터베이스 각 설계 단계에서 다루는 실무적인 스키마라고 할 수 있습니다.

- 개념 스키마
- 논리 스키마
- 물리 스키마


개념 스키마는 데이터베이스의 추상적이고 개념적인 구조를 의미하며 보통 ER모델로 표현합니다.


논리 스키마는 테이블에 대한 자세한 정보와 테이블 간의 관계를 표현합니다.

물리 스키마는 데이터베이스의 물리적 구조를 의미합니다. 물리적 설계 단계에서 물리 스키마를 다루고 관리합니다.

물리 스키마가 다루는 항목들

- 인덱스: 검색 속도와 관련됨
- 파티션 (Partion): 데이터를 나누는 단위입니다.
- 클러스터: 자주 같이 쓰이는 데이터들을 물리적으로 가까운 곳에 모은 것


# 인덱스

인덱스(Index)는 데이터 레코드에 빠르게 접근하기 위해 사용되는 데이터입니다.


# 파티셔닝 (Partioning)

대용량의 테이블이나 인덱스를 작은 논리적 단위인 파티션으로 나누는 활동을 의미합니다.
파티셔닝을 통해 데이터 관리가 간편해지고 성능 저하를 방지할 수 있습니다.

어떻게 나누느냐에 따라 다음과 같이 파티셔닝을 분류할 수 있습니다.

- 범위 분할 (Range Partitioning)
- 해시 분할 (Hash Partitioning)
- 조합 분합 (Composite Partitioning)


범위 분할은 지정한 열의 값을 기준으로 테이블을 분할합니다. 예를 들어 일별, 월별, 분기별 분할이 있습니다. 

해시 분할은 해시함수를 적용한 결과 값에 따라 테이블을 분할합니다. 특정 파티션에 데이터가 집중되는 범위 분할의 단점을 보완한 것으로서 데이터를 고르게 분산할 때 유용합니다. 고객번호, 주민번호 등과 같이 데이터가 고른 열에 효과적입니다.
하지만 특정 데이터가 어디에 있는지 알 수 없다는 단점이 있습니다.

범위 분할한 파티션이 너무 커서 관리가 어려울 때 유용한 방법입니다. 범위 분할로 우선 분할할 다음 해시 함수를 적용해 다시 분할하는 방식입니다.
