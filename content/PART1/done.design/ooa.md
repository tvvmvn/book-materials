# 객체 지향 분석 (OOA. Object Oriented Analysis)

객체 지향 분석은 객체 지향적 관점으로 시스템을 분석하고 설계하는 과정입니다. 
다음은 주요 객체 지향 분석의 방법입니다

- Rumbaugh 방법
- Booch 방법
- Jacobson 방법
- Coad & Yourdon 방법
- Wirfs-Brock 방법

특히 세명의 아미고스(The Three Amigos)라 불리는 James Rumbaugh, Grady Booch, Ivar Jacobson의 분석 방법이 통합되고 발전되어 현대의 UML이 탄생하게 됩니다.


# Rumbaugh 방법

가장 대표적인 분석 방법으로 여러가지 그래픽을 활용하는 분석 기법입니다. 객체 모델링 기법(OMT. Object Modeling Technique)이라고도 합니다. 

분석 활동은 다음의 3단계 (객/동/기)로 이루어집니다.

1. 객체 모델링 (Object Modeling)
2. 동적 모델링 (Dynamic Modeling)
3. 기능 모델링 (Functional Modeling)

객체 모델링은 객체 다이어그램(Object Diagram)을 활용하여 시스템에서 요구되는 객체를 정의하고 객체들 간의 관계를 규정하는 활동입니다. 정보 모델링(Information Modeling)이라고도 합니다.

동적 모델링은 이전 과정에서 정의한 객체를 대상으로 상태 다이어그램(State Diagram)을 활용해 상황에 따른 객체의 동작, 객체 간의 상호작용 등의 동적인 행위를 시간의 흐름에 따라 자연스럽게 표현하는 활동입니다.

마지막으로 기능 모델링은 자료 흐름도(DFD)를 활용하여 시스템에 흐르는 자료들과 프로그램을 구성하는 프로세스를 중심으로 모델링하는 활동입니다.


위의 과정을 키오스크 개발 과정에 비유해봅시다. 
첫번째, 키오스크를 구성하는 부품(객체)들을 식별합니다.

- 스크린: 사용자 인터페이스(UI)
- 본체: 로직 처리
- 결제 단말기: 결제 처리

두번째, 객체의 동작과 객체 간 상호작용을 정의합니다.

- 스크린: 사용자의 주문 정보를 입력받고 본체에 전달합니다. 
- 본체: 주문 정보를 바탕으로 결제 단말기에게 결제 명령을 내립니다. 
- 결제 단말기: 네트워크를 통해 외부 카드사와 통신하여 결제를 처리합니다.

세번째, 시스템을 구성하는 단위인 프로세스들과 시스템을 흐르는 자료들로 전체 시스템을 표현합니다.

- 프로세스: '사용자 입력처리', '결제 및 외부통신', '주문정보 저장, '영수증 출력' 등

- 자료: 사용자에서 시스템 방향으로 흐르는 '사용자의 입력(주문) 정보', 시스템에서 사용자 방향으로 흐르는 '주문 처리 결과' 등


# Booch 방법

Grady Booch는 설계를 두가지 수준으로 나누어 관리해야 한다고 주장했습니다.

- 거시적 프로세스(Macro): 계획, 개념 등 프로젝트 전체의 흐름과 관련된 프로세스
- 미시적 프로세스(Micro): 클래스 설계와 구현 등 실제 개발과 관련된 프로세스


# Jacobson 방법

야콥슨은 사용자를 중심으로 시스템 분석과 개발이 이루어져야 한다고 주장했으며 UML 유스케이스 다이어그램의 기반이 된 유스케이스(Usecase) 다이어그램을 최초로 도입했습니다.


# Coad & Yourdon 방법

코드와 요든은 E-R 모델을 객체 지향에 접목했습니다. 코드와 요든의 분석 과정을 다음의 5단계로 구분했습니다.

1. 객체 식별: 시스템에 필요한 객체와 클래스를 정의합니다.
2. 구조 식별: 객체들 사이의 관계를 정의합니다.
3. 주제 정의: 기능 별로 객체들을 구분합니다.
4. 속성 정의: 객체의 속성을 정의합니다
5. 연산 정의: 객체의 연산(메서드)을 정의합니다.
