# 인증 (Authentication)

다중 사용자 시스템에서 사용자의 로그인 정보를 확인하고 접근이 가능한지 확인하는 절차입니다.

- 지식 기반 (Something You Know) 
- 소유 기반 (Something You Have)
- 생체 기반 (Something You Are)
- 행위 기반 (Something You Do)
- 위치 기반 (Something You Are)


지식-기반 인증은 사용자가 기억하고 있는 정보를 바탕으로 인증을 수행하는 절차입니다.
사용자의 기억을 기반으로 하기 때문에 관리 비용이 저렴하지만 사용자가 인증 정보를 잊으면 인증을 시도할 수 없습니다.

예) 비밀번호, i-PIN(사이버 주민등록번호)


소유-기반 인증은 사용자가 소유하고 있는 것을 바탕으로 인증을 수행하는 절차입니다. 소유물이 도용될 수 있으므로 지식-기반 인증, 생체-기반 인증과 함께 사용됩니다.

예) 신분증, 스마트 카드, OTP(One-Time Password)


생체-기반 인증은 사용자의 고유한 생체 정보를 바탕으로 인증을 수행하는 절차입니다.
사용자가 인증하기 편리하고 도난과 위조의 위험이 적습니다.

예) 지문 인식, 음성 인식, 얼굴 인식, 홍채/망막 인식 


행위-기반 인증은 사용자의 습관이나 행동 패턴 등을 바탕으로 인증을 수행합니다.

예) 서명(Signature), 걸음걸이 분석


위치-기반 인증은 IP 주소, GPS 위치 등을 기반으로 인증을 수행합니다. 

예) 해외 로그인 차단


# 3A (Triple A) 모델 

아래의 3단계로 구성된 보안 절차를 의미합니다. 3A 기능을 전문적으로 제공하는 서버를 3A 서버라고 부릅니다.

- Authentication(인증)
- Authorization(인가)
- Accounting(과금)


인증은 접근하는 사용자의 신원을 검증하는 절차입니다. 예를 들어 로그인 절차가 있습니다.

인가는 신원이 검증된 사용자에게 사전에 주어진 권한만큼 소프트웨어의 사용을 허용하는 절차입니다.

과금은 사용자가 어떤 종류의 서비스와 자원을 얼마만큼 사용했는지 기록하고 관리하는 절차입니다.


# OAuth

OAuth(Open Authorization)는 권한 위임에 바탕을 둔 사용자 인증 API입니다. 사용자가 다른 애플리케이션의 로그인 정보를 활용해 새로운 애플리케이션에 비밀번호를 제공하지 않고 접근 권한을 가질 수 있습니다. 공개 API이므로 누구나 개발에 적용할 수 있습니다.

대표적인 사용 사례로 우리가 일상에서 많이 사용하는 구글 로그인, 네이버 로그인 등이 있습니다.
