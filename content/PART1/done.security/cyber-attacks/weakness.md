# 보안 약점

그 자체로서 큰 문제를 일으키지는 않지만 해커의 손이 닿는 경우 시스템을 고장낼 수 있는 코드 상의 결함을 의미합니다.

- 메모리 버퍼 오버플로
- 하드코드된 암호화 키
- NULL 포인터 역참조


# Memory Buffer Overflow

메모리 상에서 발생하는 보안 약점입니다. 버퍼(데이터를 담는 통)의 내용이 넘쳐서 다른 메모리 공간을 침범하는 상황을 의미합니다. 이로 인해 다른 메모리 공간에 있던 데이터가 덮어써지는 일이 발생하게 됩니다. 처음에 적절한 버퍼의 크기를 설정하여 예방할 수 있습니다.

다음은 메모리 버퍼 오버플로우(스택 버퍼 오버플로우)를 악용한 공격 입니다.

1. 해커가 의도적으로 버퍼에 과도한 데이터를 삽입하여 스택 버퍼 오버플로우를 일으킵니다. 

2. 프로그램이 함수 실행을 끝내고 메인으로 돌아가기 위해 스택에 저장된 복귀 주소를 읽습니다.

3. 이미 해커에 의해 복귀 주소는 오염되었고 프로그램은 악성코드를 실행하게 됩니다.


# 스택 가드 (Stack Guard)

스택 가드는 스택 버퍼 오버플로우를 악용한 공격으로부터 메모리는 지키는 기술입니다. 다음은 그 공격과 그에 따른 스택 가드의 방어 과정입니다.

1. 사전에 복귀 주소 앞에 카나리아(임시 데이터)를 삽입합니다. 이제 복귀 주소에 접근하려면 카나리아를 반드시 거쳐야 합니다.

2. 프로그램이 함수 실행을 끝내고 복귀 주소에 접근하기 전에 카나리아를 읽습니다.

3. 카나리아가 변경된 경우 복귀 주소가 오염된 것으로 판단하고 프로그램이 중단됩니다.

왜 '카나리아(Canary)'라고 부를까요? 옛날 광부들은 탄광에 들어갈 때 유독가스가 발생하는지 확인하기 위해 일산화탄소에 민감한 카나리아 새를 데리고 갔습니다. 가스가 발생하면 새가 먼저 죽게 되고 광부들은 그걸 보고 도망갈 수 있었습니다. 


# 널 포인터 역참조 (NULL Pointer Dereference)

C 언어와 같은 프로그래밍 언어에서 NULL 포인터가 가리키는 위치를 역참조하는 경우를 의미합니다. 이 때 발생하는 에러를 NPE(Null Pointer Exception)라고 부릅니다. 포인터를 이용하기 전에 포인터가 NULL을 나타내는지 검사해서 NPE를 예방할 수 있습니다.


# 하드코딩된 암호화 키 (Hardcoded Encryption Key) 

암호화에 사용되는 키가 프로그램의 소스 코드에 직접 입력되면(Hardcoded) 유출이 발생하는 경우 그 값을 쉽게 추측할 수 있습니다. 따라서 암호화 키처럼 중요한 데이터는 외부에 저장하고 소스코드 내에서 호출하는 방식을 사용해야 합니다.
