# 블랙박스 테스트

'블랙박스'라는 이름처럼 소스코드를 오픈하지 않고 진행하는 테스트입니다. 
사용자의 관점에서 소프트웨어가 정상적으로 작동하는지 확인하는 테스트로 기능 테스트라고도 불립니다. 개발 코드가 아닌 요구사항 명세서를 바탕으로 테스트케이스를 설계합니다.

다음은 주요 블랙박스 테스트의 기법들입니다.

- 동치 분할 (Equivalence Partioning)
- 경계값 분석 (Boundary Value Analysis)
- 원인-효과 그래프 (Cause-Effect Graph)
- 오류 예측 (Error Guessing)
- 비교 (Comparison)


# 동치 분할

프로그램의 입력 조건으로 타당한 입력 자료와 타당하지 않은 입력 자료의 개수를 균등하게 설정하고 테스트합니다. 동치 클래스 분해라고도 불립니다.

예를 들어, 0 - 100점 사이의 값을 입력받아 성적을 계산하는 프로그램이 있다고 가정해봅시다. 입력값으로 0과 100사이의 값을 n개 입력받고 이 범위를 벗어나는 값을 똑같이 n개 입력받아 테스트하는 경우가 동치분할 테스트입니다.


# 경계값 분석

입력 조건의 중간값보다 경계값에서 오류가 발생될 확률이 높다는 점에 착안한 테스트로, 경계값을 활용해서 실시하는 테스트입니다.

예를 들어 입력된 점수 별로 성적을 계산하는 프로그램이 있다고 가정해봅시다. A는 90점 이상, B는 80이상 90미만, C는 70점 이상 80점 미만 일때, 입력값으로 85점, 65점 처럼 각 범위에 안전하게 속하는 값이 아니라 79점, 60점 등 각 범위의 경계선에 위치한 값을 입력하고 테스트합니다.


# 원인-효과 그래프

입력 데이터 간의 관계와 출력에 영향을 미치는 상황을 체계적으로 분석하고 효용성이 높은 테스트케이스를 선정 및 검사하는 기법입니다.
