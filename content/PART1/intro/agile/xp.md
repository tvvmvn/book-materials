# XP (eXtreme Programming)

"좋은 건 극단적으로(Extreme) 많이 하자"라는 정신을 구현한 개발 방법입니다.
XP를 잘 이해하기 위해 XP의 5대 핵심 가치를 알아봅시다.

- 의사소통 (Communication)
- 단순성 (Simplicity)
- 용기 (Courage)
- 존중 (Respect)
- 피드백 (Feedback)


# XP 실천 사항 (Practice)

실천 사항은 다음과 같이 4가지 카테고리로 분류되며 총 12개의 항목이 있습니다.

- 피드백 (Fine-scale Feedback)
- 지속적 프로세스 (Continuous Process)
- 이해 공유 (Shared Understanding)
- 개발자 복지 (Programmer Welfare)

1. 피드백 

짝 프로그래밍(Pair Programming): 두 사람이 짝을 지어 프로그래밍합니다. 한명은 코드를 쓰고 다른 한명은 실시간으로 검토합니다.

계획 게임(Planning Game): 고객이 제시하는 비즈니스 가치와 개발자가 제시하는 기술적 비용을 저울질합니다.

TDD(Test-Driven Development): 개발자가 실제 코드를 작성하기 전에 테스트케이스를 먼저 작성합니다.

전체 팀(Whole Team): 고객도 프로젝트팀의 일원으로 생각합니다.

2. 지속적 프로세스 

계속적인 통합(Continuous Integration): 각각의 모듈들을 지속적으로 통합하여 완벽에 가까운 통합을 구현합니다.

리팩토링(Refactoring): 기능은 유지하면서 내부를 끈임없이 개선합니다.

소규모 릴리즈(Small Releases): 고객의 새로운 요구나 개선할 점을 빠르게 반영합니다.

3. 이해 공유 

공동 코드 소유(Collective Ownership): 모든 팀원들이 소스코드를 공유하고 책임집니다.

시스템 은유(System Metaphor): 시스템을 팀원들이 쉽게 이해할 수 있도록 비유를 활용합니다.

단순한 설계(Simple Design): 현재의 요구사항에만 집중합니다. 불필요한 미래 예측은 복잡도를 높일 뿐입니다.

코딩 표준(Coding Standards): 코딩의 표준에 따라 프로그래밍합니다. 누가 작성했든 일관된 결과를 얻을 수 있습니다.

4. 개발자 복지 

지속 가능한 속도 (Sustainable Pace): 초과 근무(야근)를 지양합니다.


# XP 개발 프로세스

XP 개발 프로세스는 끝을 향해 달려가는 것이 아니라 프로세스가 목적을 달성할 때까지 끈임없이 반복됩니다.

1. 릴리즈 계획 (Release Planning)
2. 이터레이션 (Iteration)
3. 승인 검사 (Acceptance Test)
4. 소규모 릴리즈 (Small Release)

<그림 - XP 프로세스>

릴리즈 계획: 사용자 스토리(User Story)로 부터 이번 릴리즈에 반영할 항목들을 고릅니다. 정형화된 요구사항 정의서 대신 카드에 사용자가 원하는 것을 적습니다. 이것을 사용자 스토리라고 부릅니다. "나는 [사용자]로서 [기능]을 통해 [가치]를 얻고 싶습니다"와 같이 대화하듯이 써내려갑니다.

이터레이션: XP 프로세스의 핵심으로 짝 프로그래밍, TDD 등 XP 실천 사항을 활용하여 실제 개발을 수행하는 단계입니다. 여러 주기로 구성되며 한 주기는 1-3주 정도의 기간동안 진행됩니다. 각 주기에서 스토리를 더 작게 나눈 태스크(Task) 를 수행합니다.

승인 검사: 릴리즈(배포) 전에 이터레이션의 결과물을 사용자가 직접 테스트하는 단계입니다. 통과하지 못한 요구사항은 다음 이터레이션에서 처리합니다.

소규모 릴리즈: 테스트를 통과한 결과물을 실제 배포하는 단계입니다.
