# 프로세스

프로세스는 프로세서에 의해 처리되는 사용자 프로그램, 즉 실행중인 프로그램을 의미합니다.

스레드는 시스템의 자원을 할당받아 실행되는 프로그램의 단위 또는 프로세스 내의 작업 단위를 의미합니다. 
하나의 프로세스에 하나의 스레드가 존재하는 경우를 단일 스레드, 하나 이상의 스레드가 존재하는 경우를 다중 스레드라고 합니다. 
프로세스의 일부 특성을 가지고 있기 때문에 경량 프로세스라고도 불립니다. 


# PCB

프로세스 제어 블록(Process Control Block)의 약자로 운영체제가 프로세스에 대한 중요한 정보를 저장해 놓는 곳입니다. 각 프로세스가 생성될 때마다 고유의 PCB가 생성되고 프로세스가 완료되면 PCB도 제거됩니다. 

PCB에 저장된 주요 정보들은 다음과 같습니다.

- 프로세스의 현재 상태
- 포인터
- 프로세스 식별자
- 스케줄링 및 프로세스 우선순위
- CPU 레지스터 정보
- 주기억장치 관리 정보


# 프로세스 상태 전이

프로세스가 시스템 내에 존재하는 동안 상태가 변하는 것을 의미합니다. 

<그림 - 프로세스 상태 전이도>


제출: 작업을 처리하기 위해 사용자가 작업을 시스템에 제출한 상태
접수: 제출된 작업이 스풀 공간인 디스크의 할당 위치에 저장된 상태
준비: 프로세스가 프로세서를 할당받기 위해 기다리고 있는 상태
실행: 준비상태 큐에 있는 프로세스가 프로세서를 할당받고 실행 중인 상태
대기: 입/출력이 필요한 경우 프로세스의 실행이 중단되고 입/출력이 완료될 때까지 대기 중인 상태
종료: 프로세스의 실행이 끝나고 프로세스 할당이 해제된 상태

디스패치: 준비 상태에서 대기하고 있는 프로세스가 프로세서를 할당받아 실행 상태로 변하는 것
Wake Up: 입/출력 작업이 완료되어 프로세스가 대기 상태에서 준비 상태로 변하는 것
Spooling: 입/출력할 데이터를 직접 입/출력 장치에 보내지 않고 나중에 한꺼번에 입/출력하기위해 디스크에 저장하는 과정.


# 프로세스 스케줄링

프로세스 실행을 위해 필요한 시스템의 자원을 프로세스에게 할당하는 작업입니다. 

- 비선점 스케줄링
- 선점 스케줄링


비선점 스케줄링은 이미 할당된 CPU를 다른 프로세스가 강제로 빼앗아 사용할 수 없는 원칙에 기반한 스케줄링입니다. 프로세스가 CPU를 할당 받으면 해당 프로세스가 완료될 때까지 CPU를 사용합니다. 프로세스의 응답 시간을 예측하기 용이하고 일괄처리 방식에 적합합니다. FCFS, SJF, 우선순위, HRN 등의 알고리즘이 있습니다

선점 스케줄링은 하나의 프로세스가 CPU를 할당받고 실행 중일때 우선 순위가 높은 다른 프로세스가 다른 프로세스의 CPU를 강제로 빼앗을 수 있는 원칙에 기반한 스케줄링입니다. 우선순위가 높은 프로세스를 빠르게 처리할 수 있다는 장점이 있지만 많은 오버헤드를 초래합니다. 빠른 응답 시간을 요구하는 대화식 시분할 시스템에 주로 사용됩니다. Round Robin, SRT, 선점 우선순위, 다단계 큐 등의 알고리즘이 있습니다.


# 프로세스 스케줄링 알고리즘

- FCFS
- SJF
- HRN
- RR
- SRT


# 교착 상태 

상호 배제에 의해 나타나는 문제점으로 둘 이상의 프로세스들이 자원을 점유한 상태에서 서로 다른 프로세스가 점유하고 있는 자원을 요구하며 무한정 기다리는 현상을 의미합니다.

교착 상태의 발생에 필요한 조건들

- 상호 배제 (Mutual Exclusion)
- 점유와 대기 (Hold and Wait)
- 비선점 (Non-Preemption)
- 환형 대기 (Circular Wait)


상호 배제: 자원은 한 번에 한 프로세스만 쓸 수 있습니다.

점유와 대기: 프로세스가 하나의 자원을 점유하고 있으면서 다른 프로세스의 자원을 추가로 점유하기 위해 대기합니다.

비선점: 다른 프로세스의 자원은 사용이 끝날 때까지 강제로 빼앗을 수 없습니다.

환형 대기: 기다리는 프로세스들이 원을 이룹니다(A->B->A). 즉 A는 B의 자원을 기다리고 B는 A의 자원을 기다립니다.


# 교착 상태의 해결 방법

- 예방 (Prevention)
- 회피 (Avoidance)
- 탐지 및 회복 (Detection & Recovery)


예방: 사전에 교착 상태 발생의 4가지 조건 중에서 하나를 제거하는 방법입니다. 간편하지만 자원의 낭비가 심한 기법입니다.

회피: 은행원 알고리즘 등을 활용해서 교착 상태에 빠지지 않도록 합니다.

탐지 및 회복: 자원 할당 그래프 등으로 교착 상태를 탐지합니다. 교착 상태가 발견되면 교착 상태에 빠진 프로세스에게 할당된 자원을 빼앗거나 프로세스를 종료시킵니다. 가장 많이 사용되는 해결 방법입니다.
