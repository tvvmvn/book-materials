# 요구사항

소프트웨어가 제공하는 서비스에 대한 설명과 정상적으로 운영되는데 필요한 제약 조건을 의미합니다. 소프트웨어 개발이나 유지보수 과정에서 필요한 기준과 근거를 제공하고 개발에 참여하는 이해관계자들 간의 의사소통을 원활하게 하는 데 도움을 줍니다. 

요구사항은 크게 기능 요구사항과 비기능 요구사항으로 구분할 수 있습니다.

- 기능 요구사항 (Functional Requirements)
- 비기능 요구사항 (Non-Functional Requirements)


기능 요구사항은 시스템이 무엇(What)을 해야하는지, 즉 시스템이 수행해야 할 기능에 관한 요구사항입니다.

예를 들면 시스템의 

- 입력이나 출력으로 무엇이 포함되어야 하는지
- 시스템이 어떤 데이터를 저장하거나 연산을 수행해야 하는지
- 시스템이 반드시 수행해야 하는 기능
- 사용자가 시스템을 통해 제공받기는 원하는 기능 등입니다.


비기능 요구사항은 시스템이 어떻게(How) 동작해야 하는지에 관한 요구사항으로 기능 요구사항을 제외한 모든 것이라고 생각할 수 있습니다.

예를 들면 

- 품질
- 성능
- 장비 구성
- 보안
- 인터페이스
- 테스트
- 제약 사항
- 프로젝트 관리/자원 요구사항 


# 요구사항 개발 프로세스

개발 대상에 대한 요구사항을 체계적으로 도출하고 분석한 후 명세서에 정리한 다음 확인 및 검증하는 일련의 구조화된 활동입니다. 요구사항 개발 프로세스가 진행되기 전에 타당성 조사가 선행되어야 합니다. 

1. 요구사항 도출 (Elicitation)
2. 요구사항 분석 (Analysis)
3. 요구사항 명세 (Specification)
4. 요구사항 확인 (Validation)

요구사항 도출은 사용자, 개발자 등 이해관계자들로부터 요구사항을 유도하고 수집하는 단계입니다. 도출 기법으로 인터뷰/설문, 브레인스토밍(Brainstorming)/워크샵, 프로토타입 만들기(Prototyping), 유스케이스(Usecase) 다이어그램 작성 등이 있습니다.

요구사항 분석은 추출된 요구사항 중 모호하거나 중복되는 항목들, 실현 불가능한 항목들 등을 걸러내고 구체화하는 단계입니다. 요구사항 분석에 사용되는 대표적인 도구로 자료흐름도(DFD)가 있습니다.

요구사항 명세는 분석된 요구사항을 바탕으로 요구사항 명세서(SRS)를 작성하는 단계입니다. 기능 요구사항은 빠짐없이 기술하고 비기능 요구사항은 필요한 것만 기술합니다. 

요구사항 확인은 개발 자원을 요구사항에 할당하기 전에 명세서의 내용이 완전한지, 명세 표준을 준수했는지 여부 등을 검토하는 활동입니다. 


# 자료흐름도 (DFD)

자료흐름도는 데이터의 흐름(Flow)과 데이터를 처리하는 프로세스(Process)를 표현한 그림으로 요구사항 개발 단계나 객체지향 분석 과정 등에서 활용됩니다.
자료 흐름 그래프, 버블 차트라고도 합니다.

- 자료 사전(DD)
- 소단위 명세서(Mini-Spec)

<그림 - 자료흐름도의 기본 기호>

자료 사전은 자료 흐름도에 있는 자료를 더 자세히 정의하고 기록한 것입니다. 데이터를 설명하는 데이터라는 의미의 메타 데이터(Meta Data)라고도 부릅니다.

<표 - 자료사전에서 사용되는 표기 기호>

소단위 명세서는 자료흐름도의 최하위 프로세스를 작성한 문서로, 프로그래밍 소스 코드의 기반이 되는 문서입니다.

<그림 - DFD, DD, Mini-Spec를 모두 나타낸 예제>


# 요구사항 명세 기법

요구사항 명세 기법으로 정형 명세와 비정형 명세가 있으며 소프트웨어 개발에서는 이 두가지 기법을 적절히 혼용하고 있습니다.

- 정형 명세 (Formal Specification)
- 비정형 명세 (Informal Specification)

정형 명세는 수학적 기호와 정형화된 표기법을 사용하여 요구사항을 작성하는 명세 기법입니다. 요구사항을 정확하고 간결하게 표현할 수 있고 요구사항에 대한 결과가 작성자에 관계없이 일관성이 있으므로 완전성 검증이 가능합니다. 반면 표기법이 어려워 전문가가 아니면 이해하기는 어렵습니다. 

예) VDM, Z, Petri-net, CSP 등 

비정형 명세는 일반 명사, 동사 등의 자연어와 그림(다이어그램)을 기반으로 하는 명세 기법입니다. 누구나 이해하기 쉽고 의사소통에 용이하다는 장점이 있습니다. 반면 자연어의 사용으로 결과가 작성자에 따라 달라지거나 한 결과에 대해 해석이 달라질 수 있습니다. 

예) FSM, Decision Table, ER 모형, SADT 등
