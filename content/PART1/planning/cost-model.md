# 비용 산정 기법 

프로젝트 비용을 산정하는 기법입니다. 

- 상향식 산정 (Bottom-Up)
- 하향식 산정 (Top-Down)


# 하향식 산정

프로젝트의 전체 비용을 산정한 후 각 작업별로 비용을 세분화합니다. 
하향식 산정은 전문 지식이 많은 개발자들이 참여한 회의를 통해 비용을 산정하는 비과학적인 방법입니다. 

- 전문가 감정 
- 델파이 (Delphi) 기법

전문가 감정 기법은 조직 내에 있는 경험이 많은 두 명 이상의 전문가에게 비용 산정을 의뢰하는 기법입니다. 가장 편리하고 신속하게 비용을 산정할 수 있지만 개인적이고 주관적일 수 있습니다

델파이 기법은 전문가 감정 기법의 주관적인 편견을 보완하기 위해 많은 전문가의 의견을 종합하고 산정하는 기법입니다. 전문가들의 편견이나 분위기에 지배되지 않도록 한 명의 조정자가 투입됩니다.


# 상향식 산정

프로젝트의 세부적인 작업별로 비용을 산정하고 이를 바탕으로 전체 비용을 산정하는 방법입니다. 다음은 주요 상향식 비용 산정 기법입니다.

- LOC 기법
- COCOMO
- Putnam
- FP


# LOC 기법

LOC(Line Of Code) 기법은 소프트웨어를 개발하는데 필요한 코드량(LOC)를 예측하고 이를 바탕으로 비용을 산정하는 기법입니다. 직관적이고 간단한 방법으로 가장 많이 사용되는 비용 예측 기법입니다. 

다음은 낙관치(a), 기대치(m), 비관치(b)를 바탕으로 LOC를 구하는 공식입니다.

LOC = (a + 4m + b)/6

이제 LOC를 바탕으로 비용을 예측하는 방법을 알아봅시다. 우선 노력이 가장 기본입니다. 노력은 인월(Man-Month)로 표현합니다.

노력(MM) = LOC/인당 월평균 코드생산량

예를 들어 10MM인 경우, 1명이면 10개월, 2명이면 5개월, 5명이면 2개월을 의미합니다. 다음은 나머지 공식입니다.

개발 기간 = 노력/투입 인원
개발 비용 = 노력 x 인당 인건비(월)
생산성 = LOC/노력


예제) 낙관치가 2,000줄, 기대치가 3,000줄, 비관치가 7,000줄이고 프로그래머가 2명, 각 프로그래머들의 평균 생산성이 500줄/월일 때 개발에 소요되는 기간은 얼마일까요? 

LOC = (2,000 + (4 * 3,000) + 7,000)/6 = 3,500줄
노력 = 3,500줄/500줄 = 7MM
개발 기간 = 7MM/2명 = 3.5개월

따라서 예상되는 개발 기간은 3.5개월 입니다.


# COCOMO 모형

COCOMO(COnstructive COst MOdel)는 LOC를 활용한 비용 산정 기법입니다. 
보헴(Bohem)이 제안했습니다.

LOC를 소프트웨어 유형에 따라 다른 방정식에 대입하여 비용을 산정합니다. 산정 결과는 프로젝트를 완성하는데 필요한 노력(인월)으로 나타납니다.

다음은 COCOMO 모형에 따른 소프트웨어의 유형입니다.

- 조직형 (Organic)
- 반분리형 (Semi-Detached)
- 내장형 (Embedded)

조직형은 중/소규모의 소프트웨어입니다. 5만 라인 이하의 소프트웨어에 해당합니다.
일반 업무용 소프트웨어 개발에 적합합니다.

반분리형은 조직형과 내장형의 중간형 소프트웨어입니다. 30만 라인 이하 소프트웨어에 해당합니다.
운영체제나 DBMS같은 시스템 소프트웨어, 컴파일러 개발에 적합합니다.

내장형은 초대형 규모의 소프트웨어입니다. 30만 라인 이상의 소프트웨어에 해당합니다.
미사일 유도 시스템, 실시간 제어 시스템 등 대규모 시스템 개발에 적합합니다.


# Putnam 모형

Putnam이 제안한 것으로 Rayleigh-Nordan 곡선을 기초로 개발 비용을 산정하는 모델입니다.

Rayleigh-Nordan 곡선은 개발 과정에 필요한 노력의 분포를 나타냅니다.
곡선에 따르면 개발 초기에는 적은 노력이 필요하다가 개발이 진행될수록 점점 노력이 많이 필요합니다. 그 이후로는 서서히 줄어듭니다.

<그림 - Rayleigh Curve>


# FP

FP(Function Point)는 소프트웨어를 구성하는 각 기능에게 타입과 타입별 가중치를 부여하고 이를 바탕으로 개발 비용을 산정하는 기법입니다. IBM에서 근무하던 알랭 알브레히트(Allan Albrecht)가 1979년에 제안했습니다. 

LOC 기법이 단순히 전체 코드의 양을 바탕으로 개발 비용을 일괄적으로 계산한다면 FP는 기능별로 비용을 고려했기 때문에 좀 더 실무적인 접근법이라고 볼 수 있습니다.

다음은 FP가 소프트웨어의 기능 타입입니다.

- 내부 논리 파일(ILF)
- 외부 연계 파일(EIF)
- 외부 입력(EI)
- 외부 출력(EO)
- 외부 질의(EQ)

예를 들어 게시물 업로드 기능은 외부 입력(EI), 게시물 보기 기능은 외부 출력(EI)에 해당합니다.


# 비용 산정 도구

- SLIM (Software Lifecycle Management)
- ESTIMATICS

SLIM은 Putnam 모형을 기초로 하여 개발된 비용 산정용 도구입니다. 예상되는 코드 라인 수(LOC)를 입력하면 총 노력(Man-Month)과 개발 기간을 계산합니다.
