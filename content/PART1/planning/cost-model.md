# 프로젝트 비용/일정 예측 

프로젝트 비용을 산정하는 기법입니다. 

- 상향식 산정 (Bottom-Up)
- 하향식 산정 (Top-Down)


# 하향식 산정

프로젝트의 전체 비용을 산정한 후 각 작업별로 비용을 세분화합니다. 
하향식 산정은 전문 지식이 많은 개발자들이 참여한 회의를 통해 비용을 산정하는 비과학적인 방법입니다. 

- 전문가 감정 
- 델파이 (Delphi) 기법

전문가 감정 기법은 조직 내에 있는 경험이 많은 두 명 이상의 전문가에게 비용 산정을 의뢰하는 기법입니다. 가장 편리하고 신속하게 비용을 산정할 수 있지만 개인적이고 주관적일 수 있습니다

델파이 기법은 전문가 감정 기법의 주관적인 편견을 보완하기 위해 많은 전문가의 의견을 종합하고 산정하는 기법입니다. 전문가들의 편견이나 분위기에 지배되지 않도록 한 명의 조정자가 투입됩니다.


# 상향식 산정

프로젝트의 세부적인 작업별로 비용을 산정하고 이를 바탕으로 전체 비용을 산정하는 방법입니다. 다음은 주요 상향식 비용 산정 기법입니다.

- LOC 기법
- COCOMO
- Putnam
- FP


# LOC 기법

LOC(Line Of Code) 기법은 1960년대 등장한 가장 고전적이고 단순한 기법으로 프로그램을 구성하는 코드의 양(LOC)을 바탕으로 비용을 산정하는 기법입니다. 

다음은 낙관치(a), 기대치(m), 비관치(b)를 바탕으로 LOC를 예상하는 공식입니다.
```
LOC = (a + 4m + b)/6
```

이제 LOC를 바탕으로 비용을 예측하는 방법을 알아봅시다. 우선 노력이 가장 기본입니다. 노력은 인월(Man-Month)로 표현합니다.
```
노력(MM) = LOC/인당 월평균 코드생산량

예를 들어 10MM인 경우, 1명이면 10개월, 2명이면 5개월, 5명이면 2개월을 의미합니다. 
```

다음은 나머지 값을 구하는 공식입니다.
```
개발 기간 = 노력/투입 인원
개발 비용 = 노력 x 인당 인건비(월)
생산성 = LOC/노력
```

예제) 낙관치가 2,000줄, 기대치가 3,000줄, 비관치가 7,000줄이고 프로그래머가 2명, 각 프로그래머들의 평균 생산성이 500줄/월일 때 개발에 소요되는 기간은 얼마일까요? 
```
LOC = (2,000 + (4 * 3,000) + 7,000)/6 = 3,500줄
노력 = 3,500줄/500줄 = 7MM
개발 기간 = 7MM/2명 = 3.5개월

따라서 예상되는 개발 기간은 3.5개월 입니다.
```


# COCOMO 모형

COCOMO(COnstructive COst MOdel)는 1981년 Barry Boehm(배리 보엠)이 제안한 기법으로 LOC를 응용하여 비용을 산정합니다.

LOC를 소프트웨어 유형에 따라 다른 방정식에 대입하여 비용을 산정합니다. 산정 결과는 프로젝트를 완성하는데 필요한 노력(인월)으로 나타납니다.

다음은 COCOMO 모형에 따른 소프트웨어의 유형입니다.

- 조직형 (Organic)
- 반분리형 (Semi-Detached)
- 내장형 (Embedded)

조직형은 중/소규모의 소프트웨어입니다. 5만 라인 이하의 소프트웨어에 해당합니다.
일반 업무용 소프트웨어 개발에 적합합니다.

반분리형은 조직형과 내장형의 중간형 소프트웨어입니다. 30만 라인 이하 소프트웨어에 해당합니다.
운영체제나 DBMS같은 시스템 소프트웨어, 컴파일러 개발에 적합합니다.

내장형은 초대형 규모의 소프트웨어입니다. 30만 라인 이상의 소프트웨어에 해당합니다.
미사일 유도 시스템, 실시간 제어 시스템 등 대규모 시스템 개발에 적합합니다.


# Putnam 기법

Putnam 기법은 1978년 Lawrence Putnam(로렌스 퍼트남)이 제안한 것으로 레일리-노든 곡선(Rayleigh-Norden Curve)을 기초로 비용을 산정하는 기법입니다.

이 기법은 레일리-노든 곡선을 바탕으로 시간에 따라 필요한 투입량(인력)을 예측합니다. 곡선에 따르면 개발 초기에는 적은 인력이 필요하고 개발이 진행됨에 따라 점점 더 많은 인력이 많이 필요합니다. 그리고 어느 시점에 이르면 필요한 인력은 정점을 찍고 그 이후로는 서서히 줄어듭니다.

<그림 - Rayleigh Curve>

퍼트남이 이 기법을 바탕으로 구현한 소프트웨어가 SLIM입니다. SLIM은 사용자가 LOC와 개발 환경을 입력하면 가장 효율적인 인력 투입 곡선을 그립니다.


# FP (기능 점수)

FP는 1979년 IBM에서 근무하던 알랭 알브레히트(Allan Albrecht)가 제안한 기법으로 "나쁜 프로그래머일수록 쓸데없이 코드를 길게 짠다"는 점을 감안하지 못한 LOC의 단점을 보완하기 위해 소프트웨어를 구성하는 기능에 기반해 개발 비용을 산정하는 기법입니다.

FP는 소프트웨어를 구성하는 기능들에게 아래와 같이 고유한 가중치를 가진 기능 타입을 부여합니다. 각 타입에 속한 기능의 개수와 타입별 가중치를 FP 공식에 대입해 개발 비용을 계산합니다.

- 내부 논리 파일(ILF)
- 외부 연계 파일(EIF)
- 외부 입력(EI)
- 외부 출력(EO)
- 외부 질의(EQ)

예를 들어 게시물 업로드 기능은 외부 입력(EI), 게시물 보기 기능은 외부 출력(EI)에 해당합니다.
