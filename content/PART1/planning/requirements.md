# 요구사항 (Requirements)

요구사항은 소프트웨어가 제공하는 서비스와 제약 조건을 의미합니다.
S/W 개발에서 요구사항은 개발 과정에 필요한 기준과 근거를 제공하고 개발에 참여하는 이해관계자들 간의 의사소통에 도움을 줍니다.

요구사항은 크게 기능 요구사항과 비기능 요구사항으로 구분할 수 있습니다.

- 기능 요구사항 (Functional Requirements)
- 비기능 요구사항 (Non-Functional Requirements)


# 기능/비기능 요구사항

기능 요구사항은 시스템이 무엇(What)을 해야하는지, 즉 시스템이 수행해야 할 기능에 관한 요구사항입니다. 비기능 요구사항은 시스템이 어떻게(How) 동작해야 하는지에 관한 요구사항으로 성능, 보안, 인터페이스 등 기능 요구사항을 제외한 모든 요구사항을 의미합니다.

예를 들어 도서관 웹서비스에 비유해봅시다. 다음은 기능 요구사항입니다.

- 도서 검색 기능
- 장르별 조회 기능
- 대여/반납 기능

이번엔 도서관 웹서비스의 비기능 요구사항입니다.

- 도서관에 어울리는 학구적인 UI
- 빠른 도서검색 속도
- 도서 보호를 위한 철통 보안


# 요구사항 개발 프로세스

사용자로부터 요구사항을 도출하고 정리하는 활동입니다. 

1. 요구사항 도출 (Elicitation)
2. 요구사항 분석 (Analysis)
3. 요구사항 명세 (Specification)
4. 요구사항 확인 (Validation)

요구사항 도출: 사용자, 개발자 등 이해관계자들로부터 요구사항을 유도하고 수집하는 단계입니다. 
도출 도구) 인터뷰/설문, 브레인스토밍(Brainstorming)/워크샵, 프로토타입 만들기(Prototyping), 유스케이스(Usecase) 다이어그램

요구사항 분석: 추출된 요구사항 중 모호하거나 중복되는 항목들, 실현 불가능한 항목들 등을 걸러내고 구체화하는 단계입니다. 
분석 도구) 자료흐름도(DFD), 소단위 명세서(Mini-Spec)

요구사항 명세: 분석된 요구사항을 바탕으로 요구사항 명세서 작성하는 단계입니다. 기능 요구사항은 빠짐없이 기술하고 비기능 요구사항은 필요한 것만 기술합니다. 
명세 도구) 요구사항 명세서(SRS. S/W Requirements Specification)

요구사항 확인: 개발 자원을 요구사항에 할당하기 전에 명세서의 내용이 완전한지, 명세 표준을 준수했는지 여부 등을 검토하는 활동입니다. 


# 요구사항 분석/명세 기법

정형 명세와 비정형 명세가 있으며, 많은 경우 이 두가지 기법을 적절히 혼용하고 있습니다.

- 정형 명세 (Formal Specification)
- 비정형 명세 (Informal Specification)

정형 명세는 수학적 기호와 정형화된 표기법을 사용하여 요구사항을 작성하는 명세 기법입니다. 요구사항을 정확하고 간결하게 표현할 수 있고 요구사항에 대한 결과가 작성자에 관계없이 일관성이 있으므로 완전성 검증이 가능합니다. 반면 표기법이 어려워 전문가가 아니면 이해하기는 어렵습니다. 
주로 원자력/항공/의료 등 위험에 대한 파급이 큰 시스템의 요구사항을 명세하는데 사용됩니다.

예) VDM, Z, Petri-net, CSP 등 


비정형 명세는 일반 명사, 동사 등의 자연어와 그림(다이어그램)을 기반으로 하는 명세 기법입니다. 누구나 이해하기 쉽고 의사소통에 용이하다는 장점이 있습니다. 반면 자연어의 사용으로 결과가 작성자에 따라 달라지거나 한 결과에 대해 해석이 달라질 수 있습니다. 
일반적인 시스템의 요구사항을 명세하는데 주로 사용됩니다. 

예) E-R 모델, UML, SADT, Decision Table 등
