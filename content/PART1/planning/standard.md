- ISO/IEC 12207
- CMMI

# ISO/IEC 12207

ISO(국제 표준화 기구)에서 만든 소프트웨어 생명주기 프로세스입니다. ISO/IEC 12207은 다음의 3가지 프로세스로 구분됩니다

- 기본 프로세스 (Primary Process)
- 지원 프로세스 (Supporting Process)
- 조직 프로세스 (Organizational Process)

기본 프로세스는 S/W 개발 과정에 대한 표준을 제시합니다.
예) 획득, 공급, 개발, 운영, 유지보수 표준

지원 프로세스는 기본 프로세스 위에 추가적인 항목들을 다룹니다.
예) 품질 보증, 검증, 확인, 활동 검토, 감사, 문서화, 형상 관리, 문제 해결 표준

조직 프로세스는 개발팀에 대한 표준을 제시합니다.
예) 관리, 기반 구조, 훈련, 개선 표준


# CMMI

CMMI(Capability Maturity Model Integration)는 소프트웨어 개발 조직의 업무 능력 성숙도를 평가하는 모형입니다. 카네기멜론 대학교의 S/W 공학 연구소(SEI)에서 개발했습니다. CMMI의 능력 성숙도는 다음과 같이 5단계로 구성됩니다.

1. 초기 (Initial)
2. 관리 (Managed)
3. 정의 (Defined)
4. 정량적 관리 (Quantitatively Managed)
5. 최적화 (Optimizing)

초기 단계는 어떠한 개발 프로세스도 없이 오직 작업자 개인의 능력에 따라 프로젝트의 성공 여부가 결정되는 단계입니다.

관리 단계는 프로젝트마다 개별적으로 개발 프로세스를 정의하고 업무를 수행하는 단계입니다. 

정의 단계는 조직의 표준화된 개발 프로세스를 바탕으로 업무를 수행하는 단계입니다. 

정량적 관리 단계는 조직이 과거의 경험을 바탕으로 프로젝트를 정량적으로 관리하고 통제할 수 있는 예측가능한(Predictable) 개발 프로세스를 갖춘 단계입니다.

최적화 단계는 더 나은 소프트웨어를 개발하기 위해 지속적으로 개발 프로세스를 개선하고 발전시키는 단계입니다.


# SPICE (ISO/IEC 15504)

SPICE(Software Process Improvement and Capability dEtermination)는 소프트웨어의 품질과 생산성 향상을 위해 소프트웨어 개발 프로세스를 평가하기 위한 국제 표준입니다.

SPICE의 개발 프로세스 평가는 다음의 6단계로 구분됩니다.

1. 불완전 (Incomplete)
2. 수행 (Performed)
3. 관리 (Managed)
4. 확립 (Established)
5. 예측 (Predictable)
6. 최적화 (Optimizing)

불완전 단계는 개발 프로세스가 아직 구현되지 않았거나 목적을 달성하지 못한 단계입니다. 

수행 단계는 개발 프로세스가 수행되고 이를 바탕으로 목적이 달성된 단계입니다. 

관리 단계는 개발 프로세스가 정의된 자원 내에서 결과물을 내는 단계입니다. 

확립 단계는 소프트웨어 공학 원칙에 기반한 안정적인 개발 프로세스가 수행되는 단계입니다. 

예측 단계는 개발 프로세스가 통제와 양적인 측정을 바탕으로 일관되게 수행되는 단계입니다. 

최적화 단계는 개발 프로세스가 최적화되고 지속적인 개선이 이루어지는 단계입니다.

# ISO/IEC 9126

- 기능성 (Functionality)
- 신뢰성 (Reliability)
- 사용성 (Usability)
- 효율성 (Efficiency)
- 유지보수성 (Maintainability)
- 이식성 (Portability)

기능성은 "소프트웨어가 사용자가 요구한 기능을 제대로 제공하는가"를 나타냅니다. 하위 특성으로 적절성/적합성, 정밀성/정확성, 상호 운용성, 보안성, 준수성이 있습니다.

신뢰성은 "주어진 시간동안 주어진 기능을 오류없이 수행할 수 있는가"를 나타냅니다. 하위 특성으로 성숙성, 고장 허용성, 회복성이 있습니다.

사용성은 "사용자가 배우기 쉽고 사용하기 편리한가"를 나타냅니다. 하위 특성으로 이해성, 학습성, 운용성, 친밀성이 있습니다.

효율성은 "사용자가 요구하는 기능을 적은 자원으로 빠르게 처리할 수 있는가"를 나타냅니다. 하위 특성으로 시간 효율성, 자원 효율성이 있습니다.

유지보수성은 "환경의 변화 또는 새로운 요구사항이 발생했을 때 소프트웨어를 유연하게 개선할 수 있는가"를 나타냅니다. 하위 특성으로 분석성, 변경성, 안정성, 시험성이 있습니다.

이식성은 "소프트웨어를 다른 환경에 얼마나 쉽게 적용할 수 있는가"를 나타냅니다. 하위 특성으로 적용성, 설치성, 대체성, 공존성이 있습니다.
