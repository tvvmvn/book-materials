# 모듈

모듈은 모듈화를 통해 분리된 시스템의 각 기능입니다. 서브루틴(Subroutine), 서브시스템, 작업 단위 등이 여기에 해당합니다. 


# 결합도 (Coupling)

모듈 간에 상호 의존하는 정도 또는 두 모듈 사이의 연관 관계를 의미합니다. 소프트웨어의 품질은 결합도가 약할수록 높고 결합도가 강할수록 낮습니다.

다음은 결합도의 6가지 종류를 좋은 것부터 나열한 것입니다.

1. 자료 결합도 (Data Coupling)
2. 스탬프 결합도 (Stamp Coupling)
3. 제어 결합도 (Control Coupling)
4. 외부 결합도 (External Coupling)
5. 공통 결합도 (Common Coupling)
6. 내용 결합도 (Content Coupling)

자료 결합도는 모듈 간의 인터페이스가 자료 요소로만 구성될 때의 결합도입니다. 예를 들어 모듈 간에 간단한 값(숫자나 문자열 등)을 주고받는 경우로 가장 바람직한 결합도입니다.

자료 결합도가 단순한 값을 주고받을 때의 결합도라면 스탬프 결합도는 배열이나 레코드 등의 조금 더 복잡한 자료를 주고받을 때의 결합도입니다. 

제어 결합도는 모듈 간에 제어 신호를 주고 받을 때의 결합도입니다. 이런 경우 제어 신호를 받는 모듈이 제어 신호를 전달하는 모듈에게 종속되므로 결합도가 증가합니다. 

외부 결합도는 어떤 모듈 내부에서 선언한 변수를 다른 모듈에서 참조할 때의 결합도입니다.

공통 결합도는 하나의 데이터를 여러 모듈이 공유할 때의 결합도입니다. 예를 들어 여러 모듈이 모듈 밖에 선언된 하나의 전역 변수를 공통으로 사용하는 경우가 있습니다.

내용 결합도는 한 모듈이 다른 모듈의 내부 자료와 기능을 직접 참조하거나 수정도 가능한 경우로 가장 나쁜 결합도입니다.


# 응집도 (Cohesion)

응집도는 모듈의 내부 요소들이 서로 관련되어 있는 정도를 의미합니다. 소프트웨어의 품질은 응집도가 강할수록 높고 응집도가 낮을수록 낮습니다.

다음은 응집도의 7가지 종류를 좋은 것부터 나열한 것입니다.

1. 기능적 응집도 (Functional Cohesion)
2. 순차적 응집도 (Sequential Cohesion)
3. 교환적 응집도 (Communication Cohesion)
4. 절차적 응집도 (Procedural Cohesion)
5. 시간적 응집도 (Temporal Cohesion)
6. 논리적 응집도 (Logical Cohesion)
7. 우연적 응집도 (Coincidental Cohesion)

기능적 응집도는 모듈의 구성 요소들이 하나의 공통된 기능을 구현하기 위해 모인 경우에 형성되는 응집도로 가장 바람직한 응집도입니다.

모듈의 구성 요소들이 입/출력으로 연결된 경우의 응집도입니다. 즉 앞의 구성 요소의 출력이 뒤의 구성 요소의 입력으로 사용되는 경우가 있습니다.

교환적 응집도는 동일한 입/출력 데이터를 사용하지만 서로 다른 기능을 수행하는 구성 요소들이 모인 경우 형성되는 응집도입니다.

절차적 응집도는 모듈이 다수의 기능을 가질 때 모듈 내의 구성 요소들이 각자 맡은 기능들을 순차적으로 수행하는 경우에 형성되는 응집도입니다.

시간적 응집도는 구성 요소들이 관련은 없지만 동시에 실행되어야하기 때문에 묶인 경우에 형성되는 결합도입니다.

논리적 응집도는 유사한 성격의 구성 요소들이 모인 경우에 형성되는 응집도입니다. 
외부로부터의 메시지에 따라 특정 구성 요소가 선택되고 작업을 수행합니다.

우연적 응집도는 모듈이 서로 관련없는 요소들로만 이루어진 경우에 형성되는 응집도로 가장 나쁜 응집도입니다.


# 팬인/팬아웃 (Fan-In/Fan-Out)

팬인/팬아웃으로 모듈 간의 의존 관계와 소프트웨어의 복잡도 등을 파악할 수 있습니다.

- 팬인: 어떤 모듈을 제어하는 모듈의 수를 의미합니다. 
- 팬아웃: 어떤 모듈에 의해 제어되는 모듈의 수를 의미합니다.

*그림 - 모듈*


# 공통 모듈

공통 모듈은 여러 모듈이 공통으로 사용할 수 있는 모듈입니다. 주로 자주 사용되는 기능들을 공통 모듈로 구현하여 개발의 효율성을 높일 수 있습니다. 공통 모듈을 구현할 때는 다음과 같은 명세 기법을 준수해야 합니다.

- 정확성 (Correctness) : 시스템 구현 시 해당 기능이 필요하다는 것을 알 수 있도록 정확히 작성해야 합니다.
- 명확성 (Clarity): 해당 기능을 이해할 때 중의적으로 해석되지 않도록 명확하게 작성해야 합니다.
- 완전성 (Completeness): 시스템 구현을 위해 필요한 모든 것을 기술합니다.
- 일관성 (Consistency): 공통 기능들 간에 상호 충돌이 발생하지 않도록 작성해야 합니다.
- 추적성 (Traceability): 기능에 대한 요구사항의 출처, 관련 시스템 등의 관계를 파악할 수 있도록 작성해야 합니다.
