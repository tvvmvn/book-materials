# S/W 보안

다음은 소프트웨어 보안의 3가지 핵심 요소(CIA)입니다.

- 기밀성 (Confidentiality)
- 무결성 (Integrity)
- 가용성 (Availability)


기밀성: 시스템 내의 자원은 인가된 사용자만 접근할 수 있으며 만약 정보가 외부에 노출된다면 읽을 수 없도록 해야합니다.

무결성: 시스템 내의 자원은 오염되지 않아야 합니다. 수정이 필요한 경우 인가받은 사용자만 수정할 수 있고 만약 불법적으로 수정되면(위/변조 등) 무결성을 잃었다고 판단합니다.

가용성: 인가받은 사용자는 시스템의 자원을 원할 때 언제든지 사용할 수 있어야 합니다.


# Secure SDLC

SecureSDLC는 안전한 소프트웨어을 개발하기 위해 SDLC(S/W 개발 과정)에 보안 강화 프로세스를 추가한 SDLC입니다. SDLC의 각 단계별로 수행해야하는 보안 활동을 제시합니다.

다음은 SecureSDLC의 대표적인 방법론들 입니다.

- CLASP: SDLC의 초기 단계에서 보안을 강화하기 위해 제안되었습니다.
- Microsoft SDL: 마이크로소프트에서 정립한 방법론입니다.
- Seven Touchpoints: 소프트웨어 보안의 모범사례를 SDLC에 통합한 방법론입니다


# 접근 제어 (Access Control)

중요한 자원을 보호하기 외부의 접근을 제한하고 관리하는 기술을 의미합니다.

- DAC
- MAC
- RBAC


DAC는 임의 접근 통제(Discretionary Access Control)를 의미합니다.
데이터에 접근하는 사용자들에게 개별적으로 접근 권한을 부여하는 방식입니다. 
데이터 소유자(Owner)가 접근 권한을 제어합니다. 

예를 들어 내가 원하는 사람들을 초대해서 클라우드상의 문서를 같이 보는 경우가 있습니다.


MAC는 강제 접근 통제(Mandatory Access Control)를 의미합니다.
각각의 데이터(객체)에 보안 등급을 부여하고 각각의 사용자(주체)에게 인가 등급을 부여합니다. 그리고 주체와 객체의 등급을 비교해 접근 가능 여부를 결정하는 방식입니다. 시스템이 접근 통제 권한을 지정합니다. 

보안이 철통같아야 하는 시스템에서 사용됩니다. 대표적인 적용 사례로 리눅스의 보안 강화 버전인 SELinux가 있습니다.


RBAC는 역할-기반 접근 통제(Roll-Based Access Control)를 의미합니다.
역할기반 접근통제는 DAC와 MAC를 보완한 기법으로 사람이 아닌 역할에 접근 권한을 부여합니다. 관리자(Admin)가 접근 권한을 지정합니다.

예를 들어 회사 시스템이 있습니다. 특정 사람이 아닌 '대리', '과장' 등 역할별로 열람할 수 있는 문서를 지정합니다. 만약 새로온 직원이 오는 경우 역할만 부여하면 접근 제어가 완료되며 추가적인 작업을 할 필요가 없습니다.
