# Testing
 
테스트는 애플리케이션에 잠재된 결함을 찾아내는 일련의 행위 또는 절차입니다

## 테스트 기본원리

- 파레토 법칙
- 살충제 패러독스
- 오류-부재의 궤변

파레토 법칙: 애플리케이션의 20%에 해당하는 코드에서 전체 결함의 80%가 발견된다

살충제 패러독스: 동일한 테스트케이스로 동일한 테스트를 반복하면 더 이상 결함이 발견되지 않는다

오류-부재의 궤변: 소프트웨어의 결함을 모두 제거해도 사용자의 요구사항을 만족시키지 못하면 해당 소프트웨어는 품질이 높다고 말할 수 없다


## 테스트 케이스

- 테스트케이스
- 테스트 시나리오

테스트 케이스: 입력값, 실행 조건, 기대 결과등으로 구성된 테스트 항목에 대한 명세서입니다. 

테스트 시나리오: 순서가 있는 테스트 케이스의 집합입니다


## 테스트 오라클

테스트 결과가 올바른지 판단하기 위해 사전에 정의된 참값을 의미합니다
테스트 오라클의 종류는 다음과 같습니다.

- 참 오라클
- 샘플링 오라클
- 추정 오라클
- 일관성 검사 오라클

참 오라클: 모든 테스트케이스의 입력값에 대해 기대하는 결과는 제공하는 오라클입니다. 발생된 모든 오류를 검출할 수 있습니다.

샘플링 오라클: 특정한 몇명 테스트케이스의 입력값에 대해서만 기대하는 결과는 제공하는 오라클입니다. 전수 테스트가 불가능한 경우에 사용합니다

추정 오라클: 특정 테스트 케이스의 입력값에 대해 기대하는 결과를 제공하고 나머지 입력값들에 대해서는 추정으로 처리합니다

일관성 검사 오라클: 애플리케이션에 변경이 있을 때 테스트 케이스의 수행 전/후 결과값이 동일한지 확인하는 오라클입니다


## 테스트 분류 

다양한 기준에 따라 테스트를 분류할 수 있습니다

- 프로그램 실행 여부 기준
- 목적 기준
- 시각 기준
- 테스트 기반 기준


## 프로그램 실행 여부에 따른 테스트 분류

- 정적 테스트
- 동적 테스트

정적 테스트: 프로그램을 실행하지 않고 명세서와 소스코드를 대상으로 테스트합니다.
소스 코드에 대한 코딩 표준, 코딩 스타일, 코드 복잡도, 결함 등을 테스트합니다.
워크스루, 인스펙션 등이 있습니다

동적 테스트: 프로그램을 실행하고 테스트합니다. 블랙박스 테스트와 화이트박스 테스트가 있습니다.


## 목적에 따른 테스트 분류

주요 테스트들은 다음과 같습니다

- 성능 테스트
- 회귀 테스트
- 강도 테스트
- 안전 테스트
- 회복 테스트
- 구조 테스트
- 병행 테스트

성능 테스트: 소프트웨어의 성능이나 효율성을 진단하는 테스트입니다
성능 측정의 기준으로 다음과 같은 지표가 사용됩니다.

- 처리량 (Throughput)
- 응답 시간 (Response Time)
- 경과 시간 (Turn Around Time)
- 자원 사용률 (Resource Usage)

처리량은 일정 시간 동안 애플리케이션이 처리하는 일의 양입니다.
응답시간은 애플리케이션이 요청을 전달받은 시간부터 응답할 때까지 걸린 시간입니다.
경과 시간은 애플리케이션에 작업을 의뢰한 시간부터 처리가 완료될 때까지 걸린 시간입니다.
자원 사용률은 애플리케이션이 의뢰받은 작업을 처리하는 동안 사용한 CPU, 메모리, 네트워크의 등의 양을 의미합니다.

회귀 테스트: 소프트웨어에 변경이 생겼을 때 새로운 결함이 없는지 테스트하는 기법입니다

강도 테스트: 소프트웨어에 점진적으로 부과하는 양을 늘려가며 잘 견디는지 테스트하는 기법입니다.


## 시각에 따른 테스트 분류

- 검증 (Verification)
- 확인 (Validation)

검증은 개발자의 시각에서 제품의 생산 과정을 테스트하는 활동입니다. 제품이 명세서대로 완성됐는지 확인합니다

확인은 사용자의 시각에서 생산된 제품의 결과를 테스트하는 활동입니다. 사용자가 요구한 대로 제품이 완성됐는지 테스트합니다.
