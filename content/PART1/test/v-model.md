# V-모델

소프트웨어의 개발 과정과 각 개발 과정에 필요한 테스트를 연결한 모델입니다.

*그림 - V모델*

- 단위 테스트
- 통합 테스트
- 시스템 테스트
- 인수 테스트


## 단위 테스트

코딩 직후 소프트웨어의 최소 단위인 모듈/컴포넌트를 테스트하는 활동입니다.


## 통합 테스트

단위 테스트가 완료된 모듈들의 통합 과정을 테스트하는 활동입니다.

- 비점진적 통합 방식
- 점진적 통합 방식

비점진적 통합 방식: 모듈들을 단계적으로 통합하고 테스트하는 과정없이 완성된 프로그램을 대상으로 한번 테스트하는 방식입니다. 대표적으로 빅뱅 테스트가 있습니다

점진적 통합 방식: 모듈들을 단계적으로 통합하고 테스트합니다. 상향식/하향식 통합테스트, 혼합식 통합 테스트가 있습니다.


## 시스템 테스트

개발된 소프트웨어가 적용될 시스템 환경에서 잘 작동하는지 테스트하는 활동입니다. 


## 인수 테스트

개발된 소프트웨어가 사용자의 요구사항을 충족하고 있는지 여부를 테스트하는 활동입니다.

테스터에 따라 다음의 2가지 테스트로 분류됩니다

- 알파 테스트
- 베타 테스트

알파 테스트: 개발자의 장소에서 사용자가 개발자 앞에서 완성된 소프트웨어를 테스트합니다. 오류나 문제점을 사용자와 개발자가 함께 확인합니다.

베타 테스트: 선정된 최종 사용자가 여러 명의 사용자 앞에서 행하는 테스트입니다. 사용자가 실제 업무를 가지고 테스트합니다


## 하향식 통합테스트

상위 모듈에서 하위 모듈 방향으로 통합하고 테스트를 하는 기법입니다. 제어 모듈은 실제 모듈을 사용하고 제어 모듈에 의해 제어되는 종속 모듈은 임시 모듈인 스텁을 사용합니다.
하나의 통합 단위의 테스트가 완료되면 스텁은 실제 모듈로 교체됩니다.


## 상향식 통합 테스트

하위 모듈에서 상위 모듈 방향으로 통합하고 테스트하는 기법입니다. 
클러스터로 결합된 하위 모듈들을 테스트하기 위해 임시 모듈인 테스트 드라이버가 사용됩니다. 테스트 드라이버는 하위 모듈을 호출, 파라미터 전달, 결과 도출 등의 작업을 수행합니다. 하나의 통합 단위가 테스트가 완료되면 드라이버는 실제 모듈로 교체됩니다.
