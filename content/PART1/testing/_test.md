# Testing 
 
테스트는 애플리케이션이 사용자의 요구사항을 만족하는지, 결함은 없는지 등을 확인하기 위한 일련의 활동입니다.


# 테스트 케이스 / 테스트 시나리오

테스트케이스는 입력값, 실행 조건, 기대 결과, 실제 결과 등으로 구성됩니다. 

테스트 시나리오는 이러한 테스트 케이스의 집합을 의미하며 예를 들어 '로그인' 테스트 시나리오는 로그인 과정에서 필요한 여러 테스트케이스들의 집합입니다.

# 테스트 기본원리

- 파레토 법칙(Pareto Principle) : 애플리케이션의 20%에 해당하는 코드에서 전체 결함의 80%가 발견된다

- 살충제 패러독스 (Pesticide Paradox) : 동일한 테스트케이스로 동일한 테스트를 반복하면 더 이상 결함이 발견되지 않는다

- 오류-부재의 궤변 (Absence of Errors Fallacy) : 소프트웨어의 결함을 모두 제거해도 사용자의 요구사항을 만족시키지 못하면 해당 소프트웨어는 품질이 높다고 말할 수 없다


# 테스트 오라클 (Test Oracle)

테스트 결과가 올바른지 판단하기 위해 사전에 정의된 참값과 비교하는 활동을 의미합니다. 테스트 오라클의 종류는 다음과 같습니다.

- 참 오라클 (True Oracle)
- 샘플링 오라클 (Sampling Oracle)
- 추정 오라클 (Heuristic Oracle)
- 일관성 오라클 (Consistent Oracle)

참 오라클은 모든 테스트케이스의 입력값에 대해 올바른 결과를 제공하기 때문에 발생된 모든 오류를 검출할 수 있습니다. 주로 항공, 의료 등 신뢰성이 극도로 중요한 분야의 테스트에서 실시하는 오라클입니다.

샘플링 오라클은 특정한 몇명 테스트케이스의 입력값에 대해서만 올바른 결과를 제공하며 전수 테스트가 불가능한 경우에 사용합니다. 일반적인 테스트에서 많이 볼 수 있는 오라클입니다.

추정 오라클은 샘플링 오라클을 개선한 것으로, 특정 테스트케이스의 입력값에 대해 올바른 결과를 제공하고 나머지 입력값들에 대해서는 추정(Heuristic)으로 처리합니다.

일관성 검사 오라클은 애플리케이션에 변경이 있을 때 테스트케이스의 수행 전/후의 결과가 동일한지 확인하는 오라클입니다.

여러분의 이해를 돕기 위해 테스트 오라클의 사용 사례를 보겠습니다. 예를 들어 "이번 테스트는 참 오라클에 기반해서 수행합니다"라고 한다면 테스트케이스의 모든 예상 결과값에 대해 참값을 제공해야 한다는 것을 의미합니다.
