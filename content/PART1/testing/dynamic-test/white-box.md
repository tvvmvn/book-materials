# 화이트박스 테스트

'화이트 박스'라는 이름처럼 투명하게 모듈의 원시 코드를 오픈시킨 상태에서 진행하는 테스트입니다. 다음은 화이트 박스 테스트의 종류입니다.

- 기초 경로 검사 (Basic Path Testing)
- 조건 검사 (Condition Testing)
- 루프 검사 (Loop Testing)
- 데이터 흐름 검사 (Data Flow Testing)

기초 경로 검사는 프로그램의 논리적인 복잡도을 측정하는 테스트로 실행 가능한 모든 경로를 최소 한번 이상 실시하는 테스트입니다. 대표적인 화이트박스 테스트 기법입니다.
기초 경로 검사는 다음과 같은 순서로 진행됩니다.

첫번째, 소스코드를 바탕으로 제어흐름 그래프(Control Flow Graph)를 작성합니다.
두번째, 제어흐름 그래프를 바탕으로 실행 가능한 모든 경로의 개수(순환복잡도)를 파악합니다.
세번째, 테스트케이스를 작성합니다.

조건 검사는 프로그램에 있는 논리적 조건을 검증하는 테스트이고 루프 검사는 프로그램의 반복 구조를 검증하는 테스트입니다. 데이터 흐름 검사는 변수의 생성과 소멸, 변수가 사용되는 위치 등 변수를 중심으로 실시하는 테스트입니다.


# 테스트 커버리지

테스트 커버리지는 테스트의 깊이를 의미합니다. 다음과 같은 커버리지가 있습니다.

- 문장 검증기준 (Statement Coverage)
- 결정 검증기준 (Decision Coverage)
- 조건 검증기준 (Condition Coverage)
- 조건/결정 검증기준 (Condition/Decision Coverage)
- 변경 조건/결정 검증기준 (Multiple Condition/Decision Coverage)

문장 커버리지는 소스 코드의 모든 구문이 한번 이상 수행되도록 안내하는 커버리지입니다.

결정 커버리지는 소스코드의 모든 조건문에 대해 조건식의 결과가 참/거짓인 경우가 한번 이상 수행되도록 안내하는 커버리지입니다. 분기 커버리지(Branch Coverage)라고도 합니다.

조건 커버리지는 소스 코드의 조건문에 포함된 개별 조건식의 결과가 참/거짓인 경우가 한 번 이상 수행되도록 안내하는 커버리지 입니다.

조건/결정 커버리지: 분기 커버리지와 조건 커버리지를 모두 만족하는 커버리지입니다. 조건문이 참/거짓인 경우에 따라 조건 커버리지의 입력 데이터를 구분하도록 테스트합니다.

변경 조건/결정 커버리지는 조건/결정 검증기준을 향상시킨 커버리지입니다. 개별 조건식이 다른 개별 조건식의 영향을 받지 않고 전체 조건식의 결과에 독립적으로 영향을 주도록 테스트합니다.


# 실제 코드로 이해하는 커버리지

if (조건1) { 
  코드 1 실행 
}
코드 2 실행

위의 코드에서 문장 커버리지로 테스트하는 경우를 생각해봅시다. 조건 1이 참인 경우만 테스트하면 됩니다. 이번엔 결정 커버리지로 테스트하는 경우를 생각해봅시다. 조건 1이 참인 경우와 거짓인 경우 모두 테스트해야 합니다

조건 검증 기준을 이해해봅시다. 

if (a && b) {
  코드
}

위의 코드를 분기 커버리지에 따라 테스트한다면 a && b가 참/거짓인 경우, 즉 최소 두 번의 테스트가 필요합니다. 그런데 조건 검증 기준의 경우는 다릅니다. a와 b가 각각 참, 거짓인 경우를 모두 고려해야 합니다. 따라서 최소 4번의 테스트가 필요합니다.
