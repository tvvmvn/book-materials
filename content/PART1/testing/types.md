# 테스트 분류 

다음과 같이 다양한 기준에 따라 테스트를 분류할 수 있습니다.

- 프로그램의 실행 여부
- 테스트의 목적
- 시각


# 프로그램 실행 여부에 따른 테스트 분류

- 정적 테스트 (Static Test)
- 동적 테스트 (Dynamic Test)

정적 테스트는 프로그램을 실행하지 않고 소스코드를 대상으로 실시하는 테스트입니다. 소스 코드에 대한 코딩 표준, 코딩 스타일, 코드 복잡도, 결함 등을 테스트합니다. 워크스루(Walkthrough), 인스펙션(Inspection) 등이 있습니다

동적 테스트는 프로그램이 실행 중인 상태에서 실시하는 테스트입니다. 블랙박스 테스트와 화이트박스 테스트가 있습니다. 동적 테스트는 뒤에서 자세히 다룹니다.


# 목적에 따른 테스트 분류

- 성능 테스트 (Performance Test)
- 회귀 테스트 (Regression Test)
- 강도 테스트 (Stress Test)
- 안전 테스트 (Security Test)
- 회복 테스트 (Recovergy Test)
- 구조 테스트 (Structure Test)
- 병행 테스트 (Parrallel Test)

성능 테스트는 소프트웨어의 성능과 효율성을 진단하는 테스트입니다. 다음과 같은 성능 측정 지표가 사용됩니다.

- 처리량 (Throughput): 일정 시간 동안 애플리케이션이 처리하는 일의 양입니다.
- 응답시간 (Response Time) : 애플리케이션이 요청을 전달받은 시간부터 응답할 때까지 걸린 시간입니다.
- 경과 시간 (Turn Around Time) : 애플리케이션에 작업을 의뢰한 시간부터 처리가 완료될 때까지 걸린 시간입니다.
- 자원 사용률 (Resource Usage): 애플리케이션이 의뢰받은 작업을 처리하는 동안 사용한 CPU, 메모리, 네트워크의 등의 양을 의미합니다.

회귀 테스트는 소프트웨어에 변경이 생겼을 때 새로운 결함이 없는지 확인하는 테스트입니다.

강도 테스트는 실행 중인 소프트웨어에 업무량을 점진적으로 늘려가며 얼마나 잘 견디는지 확인하는 테스트입니다.


# 시각에 따른 테스트 분류

- 검증 (Verification)
- 확인 (Validation)

검증은 개발자의 시각에서 제품의 생산 과정을 테스트하는 활동입니다. 제품이 명세서대로 완성됐는지 확인합니다.

확인은 사용자의 시각에서 생산된 제품의 결과를 테스트하는 활동입니다. 사용자가 요구한 대로 제품이 완성됐는지 테스트합니다.
