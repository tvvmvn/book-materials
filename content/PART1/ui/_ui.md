# UI/UX

UI는 사용자 인터페이스(User Interface)라는 뜻으로 사용자와 기기 간의 상호작용이 원활하게 이루어지도록 도와주는 장치나 소프트웨어를 의미합니다

UX는 사용자 경험(User Experience)라는 뜻으로 사용자가 소프트웨어를 이용하면서 느끼게되는 총제적인 경험을 의미합니다. 

"좋은 UI는 좋은 UX를 만든다" 이것이 UI와 UX의 관계입니다.


# UI의 구분

UI는 기기와 소통하는 방식에 따라 다음과 같이 분류됩니다. 이 UI들은 많은 경우에 함께 사용됩니다.

- CLI (Command Line Interface)
- GUI (Graphic User Interface)
- NUI (Natural User Interface)

CLI는 명령어(텍스트)로 기기와 소통하는 인터페이스입니다. 처리 속도가 가장 빠르지만 많은 명령어들을 미리 알고있어야 합니다. 일반적인 사용보다는 소프트웨어 개발 등 특별한 경우에 사용됩니다.
예) 맥OS의 터미널, 윈도우의 CMD

GUI는 마우스나 손가락으로 기기와 소통하는 인터페이스입니다. 우리가 일상생활에서 가장 많이 사용하는 방식입니다.
예) 컴퓨터 모니터, 스마트폰 등

NUI는 별도의 장치 없이 사용자의 목소리나 얼굴처럼 사용자의 몸짓으로 기기와 소통하는 인터페이스입니다. 학습이 필요없고 직관적으로 사용할 수 있습니다.
예) Siri, 빅스비 등


# UI 4대 기본 원칙

아래의 UI 기본 원칙들을 더 잘 지킬수록 UI의 품질이 더 높다고 할 수 있습니다.

- 직관성
- 유효성
- 학습성
- 유연성

직관성은 "누구나 쉽게 이해하고 사용할 수 있어야 한다."로 표현됩니다. 복잡한 설명이 없어도 빠르게 적응할 수 있어야 함을 뜻합니다. 예를 들어 '취소' 버튼을 빨간색으로 표현하거나 '제출' 버튼 옆에 종이비행기 등을 표현하는 것들이 직관성을 높이기 위한 개발자들의 노고입니다.

유효성은 "사용자의 목적을 정확하고 완벽하게 달성해야 한다."로 표현됩니다. 예를 들어 UI에 존재하는 모든 컴포넌트들(버튼 등)은 확실한 목적과 연결되어야 합니다. 사용자가 '제출하기'버튼을 누르면 제출 기능을 수행해야 하고 '취소'버튼을 누르면 진행을 즉시 중단시켜야 합니다.

학습성은 "누구나 쉽게 배우고 익힐 수 있어야 한다."로 표현됩니다. 아주 간단한 소프트웨어가 아닌 이상 어느 정도는 사용법을 익혀야 합니다. 예를 들어 UI를 구성하는 각각의 페이지들이 유기적으로 연결되어 흐름을 예측할 수 있다면 높은 학습성을 가졌다고 할 수 있습니다.

유연성은 "사용자의 요청을 최대한 수용하고 실수를 최소화해야 한다."로 표현됩니다. 예를 들어 버튼의 크기가 너무 작으면 사용자가 잘못 누를 확률이 높아집니다. 따라서 버튼의 크기를 여유롭게 만들어서 사용자의 입력을 최대한 수용해야 합니다.


# UI 설계 도구

- 와이어프레임 (Wireframe)
- 목업 (Mock-Up)
- 스토리보드 (Storyboard)
- 프로토타입 (Prototype)
- 유스케이스 (Usecase)

와이어프레임은 개략적인 레이아웃이나 구성 요소 등 UI의 뼈대를 설계하는 도구입니다. 기획 단계의 초기에 제작합니다. 
예) 손그림, 파워포인트, 키노트, 스케치, 일러스트

목업은 와이어프레임에 디자인 등을 추가해서 좀 더 실제 화면과 유사하게 만든 모형입니다. 디자인이나 사용 방법 설명, 평가 등을 위해서 만듭니다. 시각적으로만 보기 위한 정적인 모델로 실제 구현되지는 않습니다. 
예) 파워 목업, 발사믹 목업 등의 도구가 있습니다.

스토리보드는 와이어프레임에 콘텐츠에 대한 설명, 페이지 간 이동 흐름 등 서비스를 사용하는 과정(Story)를 추가한 문서입니다. 디자이너와 개발자가 최종적으로 참고하는 작업 지침서입니다. 
예) 파워포인트, 키노트 스케치, Axure 

프로토타입은 와이어프레임이나 스토리보드에 상호 작용 기능을 추가해서 사용 테스트가 가능한 동적인 형태의 모형입니다. 개발자가 사용자의 요구사항을 제대로 해석했는지 검증하기 위해 만듭니다.
예) 스케치, 그림, 글 등의 페이퍼(아날로그) 프로토타입과 파워포인트, 아크로뱃, 비지오 등의 디지털 프로토타입

유스케이스는 사용자의 요구사항을 기능 단위로 표현한 것입니다. 사용자가 원하는 목표를 달성하기 위해 수행할 내용을 기술합니다.
예) UML 유스케이스 다이어그램
